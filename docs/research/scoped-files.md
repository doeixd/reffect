# Scoped native file ownership

Preparation checked 2026-10-02 against Effect **4.0.0-rc.118**, Node **24.21.0** and Rust's stable filesystem API. This advances the real-resource gate in [PLAN](../../PLAN.md#current-frontier), after [scalar brackets](resource-scope.md) and before general Scope registration/resource Layers.

## Primary sources and prior constraints

- [Pinned Effect Scope](https://github.com/Effect-TS/effect/blob/effect%404.0.0-rc.118/packages/effect/src/Scope.ts): sequential finalizers run in reverse registration order, closure masks interruption, and closed scopes have immediate-registration semantics. Retrieved online; installed `Effect.acquireRelease`/`scoped` signatures remain the oracle.
- [Node 24 FileHandle](https://nodejs.org/docs/latest-v24.x/api/fs.html#filehandleclose): explicit close awaits outstanding operations; bigint stat preserves size. Retrieved online.
- [Rust File](https://doc.rust-lang.org/std/fs/struct.File.html): read-only open, metadata length, unique ownership and borrowed access; Drop closes and ignores close errors. Retrieved online (page reports Rust 1.99.0; validation will record the installed toolchain).
- Existing AsyncContext masks cleanup and callers signal cancellation and await completion. Static Layers are resource-free; scalar brackets do not establish OS ownership. Preserve independent frame/source policies, immutable IR, typed emission and reachable dependencies.

## Bounded decisions

- **FILE-001:** `R.File.scoped(path, use, afterClose?)` owns one read-only file in a lexical lifetime; `file.size` is a u64/Boolean computation. The callback receives a symbolic resource reference carrying an internal IRType witness with `std::fs::File` representation, not an Expr or public descriptor. Handles cannot be function inputs/outputs or domain errors. Active lexical binders are checked for every file operation, including reused graph nodes. Nested scopes borrow outer handles without moving/cloning them.
- **FILE-002:** interpret with official `Effect.scoped` and `Effect.acquireRelease`, backed by an injectable Effect service for filesystem operations. The default Node adapter opens asynchronously, reads exact bigint metadata, and explicitly awaits close. Open/stat failures intentionally project to Boolean `false`; this is a documented portable error contract, not full PlatformError parity. Read-only close errors are ignored on both adapters; writable/durable resources need a separate failure contract.
- **FILE-003:** native acquisition awaits `tokio::task::spawn_blocking` around `std::fs::File::open`, under the existing cancellation mask. It must await acquisition even after cancellation, then close the returned handle without entering use. Metadata is a synchronous handle syscall, with cooperative cancellation at helper boundaries. It can block the executor briefly; no throughput claim is made. Alternative Tokio File adds buffering/background-operation and close-lifetime obligations; a blocking inline open prevents deterministic suspended-acquisition checks. No new Cargo crate/features are required beyond reachable Tokio.
- **FILE-004:** lower to one owned local File, borrowed helper arguments, explicit Drop before an optional non-failing Unit/Never after-close effect, and masked awaited cleanup. Generated lexical control flow specializes this one-slot lifetime; no dynamic finalizer registry, boxed futures, cloned handles or native resource table. Alternative general registration would introduce unrelated lifetime machinery before a handle workload proves the basics. This API establishes one real-resource Scope boundary, not arbitrary `Scope.addFinalizer`, child scopes, manual/repeated close, resource Layers or concurrent resource transfer.
- **FILE-005:** paths are build-time, nonempty Unicode scalar strings without NUL, bounded to 4096 UTF-16 code units. Runtime user-selected paths, filesystem sandboxing, portable Windows/Unix path equivalence and symlink identity are outside this profile. Default IO failures expose only `false`, never native error details. Native task panics/reference adapter defects remain outside the admitted Exit/Cause contract.

## Acceptance and costs

Differential reference/native success and typed failure, failed acquisition without cleanup, recovery after closure, nested reverse close/cleanup, borrowed outer-handle access, pre-entry cancellation and cancellation at acquisition/use/cleanup suspension. Check escape/forged-IR/channel/path refusals, both native profiles and frame policies, source attribution, and plain handles/no handle clone/dynamic finalizer storage. Include native live-handle observations where the host supports them, rather than relying only on log text. Record future/context layout and unpolled construction allocation separately from filesystem/thread-pool polling costs. Exercise scalar RPC compatibility with the real-resource handler; general socket conformance remains provided by the existing transport suite until a file-specific disconnect fixture is added.

Implementation results and exact validation commands will follow. General resource Scope registration remains the next frontier after this adapter's ownership evidence.
