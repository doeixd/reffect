# Unary RPC authentication and request ownership

Prepared 2026-10-01 against Effect/platform-node 4.0.0-rc.118, the current scalar RPC compiler, [middleware](https://unpkg.com/effect@4.0.0-rc.118/src/rpc/RpcMiddleware.ts), [server](https://unpkg.com/effect@4.0.0-rc.118/src/rpc/RpcServer.ts), [headers](https://unpkg.com/effect@4.0.0-rc.118/src/http/Headers.ts), [Axum State](https://docs.rs/axum/0.8.9/axum/extract/struct.State.html), and [subtle ConstantTimeEq](https://docs.rs/subtle/2.6.1/subtle/trait.ConstantTimeEq.html). Downloaded middleware source matches the installed version. Network policy is currently enforced/unrestricted; no configured credentials are used for this demo.

## Oracle and supported boundary

The stock server decodes payloads before middleware, invokes middleware around the handler effect, and includes middleware failures in the RPC error codec. HTTP headers precede envelope headers; Headers.fromInput lowercases names and takes the last value. Preserve this order, including case-insensitive names and envelope override. Schema-invalid requests remain defects even when credentials are absent. Authentication failure is a typed middleware failure and must prevent handler execution. The handler factory itself must remain pure; observable work belongs inside the effect.

Implement one explicit bearer adapter for exactly one middleware service per protected procedure. The middleware must have no additional service requirements and a plain string-literal denial schema. It provides one declared bigint principal service; a checked binding projects that service to the first native u64 argument. This is compile-time service projection, not general Context lookup, arbitrary JS middleware compilation or Layer lowering. Public procedures retain ordinary bindings. Reject missing, extra, multiple and identity-mismatched middleware adapters, protected bindings on public endpoints, wrong principal witnesses and unadapted middleware.

Ordinary RpcGroup/Schema/Context/RpcMiddleware contracts remain shared with stock clients. No general string IR or Schema transforms are needed: credentials, request IDs and tags are transport data; the denial is a statically known literal at the boundary. A client can supply headers through ordinary RPC call options; required client middleware remains an ordinary Effect client concern.

## Runtime credentials and ownership

Load credentials once at startup from a named environment variable containing a bounded JSON array of token/principal pairs. Tokens follow the bounded bearer-token character grammar; scheme matching is case-insensitive under [HTTP authentication](https://www.rfc-editor.org/rfc/rfc9110.html#section-11.1). Principals use bounded decimal u64 strings with the same normalization as the canonical RPC codec. Refuse absent/malformed/empty/duplicate credentials, excessive entry/token sizes and invalid principals, with generic startup errors that never echo values. Generated artifacts contain the environment variable name and schema, never credential values. Keep credentials in immutable server-owned state, shared with HTTP tasks through Axum State/Arc. This demonstration is a configured verifier, not JWT verification, session issuance, revocation or a production identity provider.

Use subtle 2.6.1 byte comparison, selected only for auth profiles. Token length and the configured number of entries are not hidden; do not claim entire endpoint constant-time behavior. Scan the bounded table and do not emit credentials to logs or failures. Follow normalized Effect header precedence rather than inventing a second authentication authority. Deployment must explicitly consider that envelope credentials override HTTP credentials.

Each HTTP task owns the decoded request body; each synchronous dispatch owns a stack RequestContext borrowing its stable request ID/procedure and storing an optional authenticated principal. Rust lifetimes prevent that view escaping its request owner. Decode all native arguments, authenticate, then invoke the handler synchronously. Never accept principal/request context from payload fields. Keep u64/bool/() values unchanged. Bodies and credentials allocate at the transport boundary; no WeakMap, global identity map, Box or metadata field is added to domain scalars.

Compiled logging receives a separate structured request field with ID, tag and principal. A lexical RAII log-context guard restores prior context even on unwinding; current synchronous handlers contain no await. Context JSON is prepared only when reachable logging needs it. Existing static/scoped log annotations keep their precedence and cannot spoof the separate request field. Non-RPC logging has no request field. Frame stashes clear before/after dispatch, including denied and invalid requests. HTTP state/context drop normally on completion and scoped test processes terminate at scope exit.

Thread-local guards are acceptable only within this non-suspending slice. Overlapping socket requests prove isolation for synchronous handlers, not future poll/fork/migration isolation. Async compiled effects need explicit owned context passed through tasks and verified cancellation/finalization before this adapter can widen. W3C propagation, RPC spans/metrics, exporters, general middleware composition, graceful draining and source maps remain following work.

## Alternatives and acceptance

Rejected: executing opaque JS middleware through a native proxy; accepting arbitrary middleware solely by tag name; embedding tokens in generated Rust; carrying context on every scalar; claiming thread-local storage models async Effect. A generic service/context IR would broaden scope before a workload establishes its semantics. The explicit principal projection is deliberately narrow and inspectable in the artifact's RPC profile.

Acceptance: stock JS server and generated debug/release server agree on accepted/rejected credentials, normalized HTTP/envelope headers, typed denial, payload-before-auth defects and public endpoints. Overlapping calls return their own principal; denied calls produce no handler log. Correlate handler logs and verify restoration after typed failure, malformed payload and denial; ensure credentials never appear in artifacts/output. Reject unsupported adapters and validate TypeScript contracts. Test missing/malformed runtime configuration and scoped process cleanup. Preserve the existing portable RPC corpus and logging conformance suite.

## Implemented results

NativeRpc.bearer/bindPrincipal now implement this profile without adding a string domain type or general service IR. Adapter construction checks a plain ASCII denial literal and environment selector; compilation matches middleware identity, refuses changed denial schemas and checks the canonical principal witness. Strict TypeScript also refuses extra required/provided services and public/protected binding mismatches. Artifact runtime metadata names the middleware, projected service and credential source; subtle is selected only for auth.

The shared scenario passes against the stock server and fresh native debug/release crates. It proves typed denial/domain error separation, mixed-case scheme/header handling, envelope override/last-value semantics, payload-before-auth defects, public calls, exact batch correlation without relying on response order, 16 overlapping principal calls and 25 correctly correlated handler logs. A raw HTTP socket client verifies repeated Authorization fields do not authenticate from just the first value. Invalid startup cases cover absent/malformed/empty/duplicate/oversized credentials and invalid principals; errors omit values. Native logs and generated artifacts contain no credential fields/values from those requests/configurations.

Independent native debug/release tests prove nested log-context restoration, unwinding restoration and absence on ordinary calls; existing logging records/annotations/spans and the prelude layout remain compatible. Full workspace validation passes 87 tests in 15 files, formatting/lint, strict TypeScript and build. The runnable example confirms principal=9007199254740993, denial=Unauthorized and typed failure=false through the stock client. Package build is fresh; unrelated workspace builds use cache. Repeated post-commit validation is required before publication.

Review corrected a zero-argument Rust closure shape, preserved existing prelude adjacency, and made test parsing select versioned records rather than parse Cargo warning lines. The oracle logger must wrap handler-layer construction; supplying it as a sibling layer captures the wrong logger. Yielding in the oracle also exposed legitimate out-of-order batch completion, now checked by IDs. None of these corrections skips protocol or logging assertions. Async ownership/cancellation, intermediate frame bounds, independent instrumentation selection and OTel remain following work.
