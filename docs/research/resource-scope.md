# Structured resource lifetime foundation

Checked 2026-10-02 against installed Effect 4.0.0-rc.118 and its [pinned upstream implementation](https://github.com/Effect-TS/effect/blob/effect%404.0.0-rc.118/packages/effect/src/internal/effect.ts#L4427). Retrieved that primary source online before implementation. The current [async RPC foundation](async-rpc.md) already provides cooperative cancellation, concrete futures and non-failing awaited cleanup. General resource Scope remains the milestone frontier.

The pinned `acquireUseRelease` wraps acquisition in `uninterruptibleMask`, restores the previous interruptibility for use, and installs `onExitPrimitive(..., true)` release after successful acquisition. Consequently cancellation during acquisition must finish acquisition and release the acquired value without starting interruptible use. Failed acquisition never installs release. Release receives the use Exit upstream; this subset deliberately omits that callback parameter and admits non-failing cleanup only.

## Decisions

- **SCOPE-001 — accepted-for-subset:** implement structured `R.Effect.acquireUseRelease(acquire, use, release)` with one symbolic scalar acquisition result shared by the use and release callbacks. Alternative: introduce a mutable dynamic Scope/finalizer registry now. Structured lowering keeps registration in generated control flow, values plain, futures concrete and no runtime finalizer collection. Consequence: this is a bracket primitive, not `Effect.acquireRelease`, `Effect.scoped`, child scopes or escaping resource ownership. Revisit when a real resource adapter needs shared lifetime/Layer resources.
- **SCOPE-002 — accepted-for-subset:** acquisition and release are masked; use restores the inherited mask. Release is Unit/Never, independent of use Exit. Alternative: arbitrary fallible/Exit-aware release requires a wider Exit/Cause representation and failure-combination semantics. Consequence: existing Boolean/u64/Unit/Never witnesses suffice; failed acquisition skips use/release, cancellation after successful acquisition still releases once. Revisit before admitting fallible resource APIs or rollback selected by Exit.
- **SCOPE-003 — accepted-for-subset:** scalar values can model resource IDs/tokens but no OS-handle type is admitted. Alternative: opaque handle wrappers and registry would invent an unverified native ownership contract. Consequence: tests exercise ownership/control-flow with token acquisition, use and release logs; they do not establish actual file/socket/SQL handle semantics. Revisit with the first native resource implementation registry entry and an escaping-capture refusal design.
- **SCOPE-004 — accepted-for-subset:** use existing explicit owned AsyncContext and bounded frame/provenance policies. No per-value metadata, boxed helper futures, global mutable finalizer stacks or TLS across await. Alternative: RAII Drop alone cannot await async cleanup; detached cleanup cannot guarantee completion/order. Consequence: caller must signal cancellation and await the generated future; abort/drop remains outside the guarantee. Revisit for server draining or cross-fiber resource transfer.

## Validation gates

Compare official Effect and native success/domain failure, failed acquisition, cancellation during acquisition/use/release, nested reverse release ordering and scalar binder preservation. Native tests cover debug/release and both frame policies, source artifacts and explicit std capability refusal. Check no boxed dynamic futures/runtime registration collection and measure construction/layout within the conformance probe. Results will be recorded after implementation; no full Scope support is claimed.

## Implementation and observed results

The structured scalar bracket is implemented across immutable typed IR/checking, official Effect reference/framed reference, capability derivation, shared native helpers, explicit-context cancellation and source occurrences. Release captures only its lexical scalar binder; failed acquisition skips both callbacks. Checked scalar IDs are ordinary values and can be returned from use; this does not establish an escaping OS-resource ownership contract. An unbound symbolic callback capture outside its lexical bracket is refused by the existing checker.

Focused tests pass **2/2** (78.98 seconds of tests, 82.21 seconds total), including native debug/release under Bounded/None frames, pinned reference agreement, interrupted acquisition/use/release, typed failure preserved during masked release, failed acquisition skips release, nested inner-before-outer release, exact u64 token logging, frame/source preservation, std capability refusal, malformed release IR and escaping-binder refusal. Strict package TypeScript and `git diff --check` pass. The first native run required Cargo's environment to be loaded; a JSON test filter accidentally matched a Cargo warning, then was corrected to require the log schema prefix. Concurrent native builds exceeded the initial 120-second budget; this multi-profile fixture now has a bounded 240-second budget. No semantic assertions were weakened.

On Rust 1.98.1 x86_64 Linux, the release probe measured logging-enabled context/bracket/nested future sizes of **104/448/96 bytes** with Bounded frames and **96/408/72 bytes** with None. Construction of AsyncContext and both unpolled concrete futures adds **zero allocations** after creating the cancellation watch. The test asserts those allocation guarantees. These are corpus/compiler-specific layout observations, not ABI budgets or total allocation claims: timer polling, log formatting, failure frames and HTTP/resource adapters have separate costs. The nested scalar example has synchronous acquisition/release callbacks; its smaller future is not representative of arbitrary nested suspension.

General dynamic Scope, acquireRelease registration, native OS handles, Exit-dependent/fallible release, finalizer defects, parallel release, child fibers and graceful drain remain pending. All SCOPE decisions above are reviewable when those workloads arrive.
