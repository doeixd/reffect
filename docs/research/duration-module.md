# Duration authoring configuration

Checked 2026-10-02 against installed Effect **4.0.0-rc.118** and its [published source](https://unpkg.com/effect@4.0.0-rc.118/src/Duration.ts). This is an authoring-time Duration module for Sleep and Schedule configuration, rather than a runtime Duration IR witness.

## Existing boundaries and pinned behavior

The current Sleep node stores integral milliseconds in 0–60000; Schedule stores integral base milliseconds in the same interval (spaced requires at least 1). Their Rust lowering already uses these plain numbers. The [schedule decisions](schedule.md) require retaining these bounded inputs.

Effect v4 Duration supports millisecond numbers, nanosecond bigint, strings, `[seconds, nanos]` tuples, additive component objects and existing Duration values. It preserves negative values and both infinities. Fractional milliseconds become rounded nanoseconds; nanosecond strings round to the nearest nanosecond using ties away from zero. `toMillis` converts nanoseconds through `Number`, while `toNanosUnsafe` preserves the nanosecond bigint. Infinite-to-nanosecond conversion throws; its safe form returns None. NaN constructors normalize to zero, including `millis(NaN)` and tuples with NaN. These are upstream semantics, not an invented nonnegative duration domain.

## Decisions recorded before implementation

- **DURATION-001 — Specialize configuration:** expose pinned official constructors, conversion, arithmetic and comparison functions on a frozen `DurationIR` namespace, using official Duration objects. These execute during authoring and preserve official pipeability and dual forms. Sleep/Schedule extract a checked numeric literal once; generated native values remain plain integers. A new Duration IRType, tagged native milliseconds/nanoseconds/infinity enum and arithmetic nodes would expand representation, ownership and lowering without a runtime workload. Revisit when handler inputs or results genuinely require Duration values.
- **DURATION-002 — Timing admission differs from construction:** constructors and conversions retain all upstream values. The Sleep `checkedMilliseconds` boundary admits only integral 0–60000 milliseconds (optionally minimum 1), and reports structured `INVALID_DELAY` authoring diagnostics. It rejects negative, infinite, fractional and oversized values without rounding/truncating to the target unit. Numeric NaN is explicitly rejected, preserving the existing Sleep admission; an already constructed `Duration.millis(NaN)` is indistinguishable from upstream zero and is accepted. This is a documented narrow timing policy. Supporting fractional/native nanosecond sleeps or infinity requires a separately verified cancellation/timer contract.
- **DURATION-003 — No hidden per-call representation:** official objects exist only in TypeScript authoring configuration and disappear after normalization into the existing IR. No weak metadata registry, new native context fields, native heap allocations or Cargo dependency is introduced. Construction/arithmetic can allocate official objects in TypeScript; this cost is not claimed to be zero or measured. Native timer/context behavior and allocations are inherited from existing Sleep/Schedule, not remeasured by these tests.

Alternatives: independently reimplementing Duration conversion risks signed, rounding and infinity mismatches; blindly spreading the entire module would imply support for runtime/hash/reducer integrations beyond this profile. The curated namespace deliberately exposes configuration functions whose semantics can reuse the pinned implementation directly.

## Acceptance

Differential official-Duration conversion/arithmetic/pipeability and negative/fractional/infinite cases; explicit conversion refusal and safe Option behavior; checked timing boundaries (including exact nanosecond fractions and component/tuple/string inputs); no author casts; checked helper diagnostics preserve operation paths. Sleep accepts official Duration.Input and uses checked normalization. Schedule retains its existing normalization, bounds, diagnostics and serialized-plan validation; its exponential base accepts raw NaN through upstream zero normalization, while spaced rejects that zero because its minimum is 1. This intentional existing policy differs from Sleep's raw-NaN refusal. Public `R.Duration` / direct `R.Effect.sleep` tests exercise compilation and reference paths; this module cannot admit Duration as runtime inputs or outcomes.
