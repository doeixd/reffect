# Private Queue driver ownership

Prepared 2026-10-07 before planning/code. Extends the [QCB bridge](queue-continuation-bridge.md) with scoped registration retirement, not host cancellation, asynchronous cleanup or public compiler admission.

## Preparation and sources

Reviewed PLAN, PROGRESS, QBF/QIR/QCB and the current two-child borrowed driver. Freshly checked [Effect4.0.0 Queue source](https://unpkg.com/effect@4.0.0/src/Queue.ts): take/offer interruption removes live registrations, Done cleanup leaves mandatory owner callbacks in place, and empty Closing can finalize during offer cleanup. Reviewed the installed Effect fiber interruption implementation: parent interruption visits children sequentially and executes cleanup immediately; it does not generally broadcast cancellation before all cleanup. The [Rust Drop contract](https://doc.rust-lang.org/std/ops/trait.Drop.html) distinguishes destruction of a guard from destruction of values it borrows. Poisoned Mutex acquisition can fail; the current checked cancel uses expect and is unsuitable for a destructor during unwinding.

An official public-API probe forks a taker, offers A then suspends a producer offering B, and returns the Queue before scheduled dispatch. Parent exit leaves an Open Queue with A buffered and no pending registrations; neither canceled child continuation runs. This is the bounded no-finalizer workload for this step. No dependency upgrade or new upstream issue is needed.

## Decisions

- **QOWN-001 — Exclusive two-child lifetime.** The private driver owns routing for both task IDs of its Queue bank. Construction requires an open, uninstalled bridge with idle receipts, no pre-existing owner registrations and an exclusive inline owner installation lease. The owner lease and bridge installation bit reject overlapping drivers even while the registration bank is empty; release the mutex before throwing a constructor refusal so overlap does not poison the valid owner. Lease release is idempotent with close, preventing an old closed guard from retiring a replacement driver. Closed dispatch/start must not touch the owner or consume replacement notifications; this is tested separately from destructor idempotence. A closed bridge cannot be installed into another driver. The guard must be destroyed before its borrowed futures, bank and owner can be destroyed. Caller-owned futures may only be destroyed after closure; this is not an owned Future executor.
- **QOWN-002 — Quiescent close.** Explicit close requires no active continuation or held owner mutation lock, marks both children inactive and invalidates both receipts before removing their owner registrations. It is idempotent, runs no child continuation and preserves buffered messages and stored terminal/lifecycle except that an empty Closing owner becomes Done. Ordinary single-child cancel keeps its synchronous peer routing. Broadcast-first retirement is only proved for the current quiescent no-finalizer subset; do not extend it to arbitrary reentrant interruption/finalizers.
- **QOWN-003 — Separate Drop retirement.** Drop uses the same exclusive retirement state change without active/step/depth assertions, future polling or callback routing. Acquire the owner mutex with poison recovery, invalidate the bridge even if a dynamic bank borrow prevents clearing its slots, and remove all registrations by the exclusively owned task IDs rather than only published tickets. This handles interruption between owner registration and ticket publication. No heap allocation or unsafe pin access is needed. The private ownership profile excludes external owner lock guards during Drop; a lock created later in the same scope unwinds before the guard, as tested. The poison fallback is resource hygiene, not semantic recovery from a defect or proof of arbitrary corrupted owner states.
- **QOWN-004 — Preserve the per-operation protocol.** Do not change Queue.cancel's Done/no-op contract. Exclusive whole-driver retirement is a separate internal operation after all supported children are inactive. It discards undeliverable notices for those canceled children and cannot serve as a per-child cancel/Drop implementation. External callback observers, concurrent owner mutations, unrelated registrations and dropping the guard during a live callback are outside its ownership profile. The known upstream shutdown defect remains separately gated.
- **QOWN-005 — Refuse reuse and keep settlement gated.** Queue request futures reject a closed bank before reading a receipt; handles/new driver construction reject it too. Dropping the driver releases its borrows but does not destroy child captures or produce an Effect Exit. Individual request Drop/select, finalizers, hosted cancellation, failure frames and checked native lowering remain unimplemented. A guard cleanup proof is not full Effect task settlement.

## Alternatives and validation

Keeping explicit per-child cancel alone leaks registrations on ordinary scope exit. Calling it sequentially from Drop can run a peer continuation, assert an active flag after a panic, or double-panic on poison. Catching a cleanup panic prevents abort but leaves registrations behind. The exclusive no-callback retirement path is smaller and has a clear lifetime boundary; per-request Drop needs its own routed cancellation design.

Validate overlapping installation refusal without poisoning, replacement-owner safety, panic inside child poll, normal scope exit against official parent cleanup, pending producer/taker removal while buffered data remains, repeated close, closed request/driver refusal, registration-before-receipt and poisoned-owner unwinding, and a held bank borrow during Drop. Use debug/release and a negative mutation removing scoped retirement. Retain existing ordering/terminal/cancellation fixtures and zero-allocation measurements. Actual layouts must be remeasured. Compiler profiles, default-context receipts, frames and owned/public execution remain subsequent gates.

## Delivered evidence

The eight official debug/release traces include the six QCB workloads plus parent exit with an Open or Closing owner. Scope exit removes both pending registrations, runs no canceled child continuation, preserves A and the existing terminal/lifecycle, and drains to Done without admitting B. Removing destructor retirement makes the scope test fail; the delayed-producer mutation still fails independently.

Local safety fixtures reject overlapping owner/bridge installation without poisoning, preserve a replacement driver's registration when an old closed guard drops, refuse closed request repoll/new driver, and remove registrations after a child-poll panic, poisoned-owner unwind with a missing published ticket, or a held bank borrow. These are adapter resource-hygiene probes, not general Effect defect/finalizer parity.

1000 quiet rounds of complete producer/consumer execution plus pending Open Drop and Closing explicit close allocate zero times. Linux owner/bank/borrowed driver/producer/consumer layouts are120/144/72/168/152 bytes. The owner installation flag fits existing padding; bridge lifecycle guards add8 bytes to the prior136-byte bank. Payload scalars remain plain. Queue IR/protocol/bridge regression passes16 tests across3 suites with native builds serial.

Resume in queue-continuation-runtime.ts (private request/bank/driver/retirement), queue-bounded-runtime.ts (inline owner installation bit) and queue-continuation-runtime.test.ts (official and local safety probes). Individual request Drop/select, awaited Effect cleanup/Exit, default-context operation receipts, source frames, checked generated lowering and owned/public execution remain open.
