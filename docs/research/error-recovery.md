# Typed error recovery

Checked 2026-10-02 against installed Effect **4.0.0-rc.118** and its [published primary source](https://cdn.jsdelivr.net/npm/effect@4.0.0-rc.118/src/internal/effect.ts). The downloaded source matches the installed internal implementation byte for byte. Effect v4 calls the primitive `Effect.catch`; this DSL retains the familiar `catchAll` spelling for domain-error recovery. Upstream `catch_` uses `catchCauseFilter`/`findError`, while `mapError` is implemented through `catch_` and `failSync`. Defects and interruptions do not become domain errors.

This builds on [the async profile](async-rpc.md), the scalar nominal channel rules in `effect-ir.ts`, and the current milestone 3A/3B frontier in [PLAN](../../PLAN.md). Scope and service work remain separate.

## Decisions

1. **ERR-001 — accepted for this bounded profile.** Introduce one semantic node, `CatchAll`, containing source, symbolic error binder and recovery computation. Compose `mapError` as recovery followed by `Fail`, and `orElse` as recovery ignoring its symbolic argument. A separate node per surface operation would retain more authored names but multiply interpreter/checker/lowering branches without different semantics. Revisit when exact transformation ancestry or diagnostics need authored combinator identity.
2. **ERR-002 — accepted for this bounded profile.** Recover only the declared domain-error channel. Reference `CompileError` failures bypass recovery; framed internal failures bypass recovery; native `AsyncError::Interrupted` bypasses recovery and preserves its trail. Scalar domain witnesses cannot represent a CompileError. Fallible cleanup and composite Cause recovery remain outside this profile; reconsider before admitting richer error representations.
3. **ERR-003 — accepted for this bounded profile.** Join success witnesses using the existing equal-witness-or-Never rule; the resulting error witness is solely the handler's witness. No implicit mixed Bool/U64 union is introduced. Revisit when an explicit union representation ships.
4. **ERR-004 — accepted for this bounded profile.** Native source helpers use the source's error representation, while handler helpers use the enclosing error representation. This permits Bool-to-U64 error mapping without type erasure or payload boxing. Successful Never sources are eliminated with an exhaustive uninhabited match. Interruption is reconstructed with the new error type rather than coerced.
5. **ERR-005 — accepted for this bounded profile.** Recovered failure frames are explicitly dropped before the recovery handler begins, including before an awaited handler; they are not retained by the suspended recovery future. A recovery handler's failure begins a new trail and adds `catchAll` while unwinding; successful recovery has no trail. `mapError` therefore reports its generated fail/recovery path rather than retaining the original handled failure. This is a deliberate logical-stack contract, distinct from native stacks and full Effect Cause history. Revisit if user demand justifies retaining handled error ancestry externally.
6. **ERR-006 — accepted for this bounded profile.** Recovery is lazy at execution: handlers are built once symbolically and run only after a domain failure. Acquired cleanup in the source completes before recovery executes. Cancellation during a masked finalizer remains interruption or the established typed-failure outcome according to the existing adapter; recovery does not change the masking model.

## Validation obligations

Check inferred channels without author casts, same-witness success joins, incompatible joins refused, forged binder/channel nodes rejected, and default synchronous target admission. Compare official Effect and native success/error values and bounded/disabled frame trails for synchronous and suspending recovery. Include different source/handler error witnesses, successful source skipping recovery, nested recovery, cleanup ordering, and cooperative interruption bypassing recovery. Generated helpers must remain concrete with no new runtime crate, dynamic future boxing or value metadata.

## Integrated implementation and validation

`R.Effect.catchAll`, `mapError` and `orElse` are integrated through checked IR, official Effect reference and synchronous/Tokio native lowering. Helpers are specialized by node, lexical scope and error witness, avoiding reuse of a Bool-error helper where a U64-error helper is required. Existing diagnostic policy controls frame storage; no runtime crate or dynamic future allocation is introduced by recovery.

Focused validation: `vp test packages/reffect/tests/error-recovery.test.ts` passed **2/2** in **95.02s**, covering both targets, both frame policies and fresh debug/release builds. A subsequent reference-only run passed **1/1** (one native test skipped) in **7.69s**, adding ordinary/framed interpreter CompileError bypass evidence. Package strict TypeScript and focused Oxlint pass. The native shared-error-witness regression repeat exceeded its original 120-second fixture budget while concurrent fresh Rust builds were running; it reported no semantic assertion failure before timeout. The fixture now allows 240 seconds for its four fresh target/policy crates and debug/release probes. Parent whole-suite checks must validate this latest regression and the explicit frame-drop review correction.

The initial focused run exposed a test-fixture mistake: frame observation was attempted with the disabled frame policy, which the runner correctly refuses. The fixture now uses ordinary exit observation for that policy. This did not change admitted runtime semantics.
