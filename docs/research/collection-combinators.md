# Pure collection and predicate combinators

Prepared 2026-10-02 against installed Effect 4.0.0-rc.118 and the matching [published Array source](https://unpkg.com/effect@4.0.0-rc.118/src/Array.ts), [Predicate source](https://unpkg.com/effect@4.0.0-rc.118/src/Predicate.ts), and [Boolean source](https://unpkg.com/effect@4.0.0-rc.118/src/Boolean.ts). Read existing [array decisions](arrays.md), [record ordering decisions](records-js-order.md), roadmap, progress and existing kernel/Array/Record authoring first.

## Decisions recorded before implementation

- **COL-001 — reuse structured IR.** Array `some` and `every` specialize existing `reduce` plus lazy Boolean Match. Predicates receive the symbolic element and u64 index. Empty-array identities match Effect. The loop still traverses remaining elements after the result becomes decisive, but skips the predicate expression; no new native dependency or operation is introduced. Early loop termination needs a future checked loop node and remains a performance improvement, not a semantic promise of this slice.
- **COL-002 — distinguish predicate functions from boolean expressions.** `Boolean.and`/`or` are dual expression combinators. `Predicate.and`/`or` combine symbolic callback functions, while `Predicate.not` needs a callback overload alongside the existing expression spelling. Lazy Match preserves runtime short-circuiting. Callback construction happens during authoring; build-time side effects in callbacks are not runtime semantics. Refinement/type-guard signatures remain unsupported.
- **COL-003 — useful empty checks, avoid duplicate APIs.** Array `isArrayEmpty`/`isArrayNonEmpty` reuse length. Record `isEmptyRecord` reuses size, which returns Number rather than u64. Existing length/keys/values/has stay canonical. Record get waits for an owned checked access primitive, because `values` loses keys and constructing an independent lookup interpreter would bypass existing IR semantics.
- **COL-004 — Option-dependent helpers.** `findFirst` specializes reduce into the separate structural Option witness, preserving first-match/index semantics and skipping subsequent predicates. `filterMap` is deferred: map/filter/map would repeat callback expressions or allocate intermediate collections without a shared per-element binder; a proper flat-map/filter-map loop should establish single evaluation first. Array access also waits for a checked index node.

## Validation and costs

Compare reference results with official Array/Predicate/Boolean/Record on empty and mixed arrays, first/middle/last/no match, index-sensitive predicates, Boolean truth tables and record emptiness. Prove reference runtime short-circuit using a reference-only operation that defects if reached, and test native structured branches against official predicates. Native scalar-input functions build local arrays and expose scalar outputs to the existing runner, including debug/release and disabled diagnostic policy. Pure specialization uses std only; reduce's existing accumulator ownership applies. No per-element metadata or heap box is added. A found non-Copy payload may be cloned on every remaining reduce iteration, even though subsequent predicates are skipped. This gives worst-case suffix-dependent copying (and String allocations); early termination is the revisit trigger for a dedicated search node. Allocation counts are unmeasured. The separate `R.Boolean` namespace preserves the frozen `R.Bool` witness identity.

## Delivered evidence

Implemented `some`, `every`, `findFirst`, both mutable/read-only empty-array spellings, `Record.isEmptyRecord`, `Boolean.and`/`or`, and function-based `Predicate.and`/`or`/`not` (with the prior expression-based `not` retained). `findFirst` returns the separately admitted structural Option projection, rather than an official Option instance. The u64 index and unsupported refinement boundaries follow ARR-002.

Validation: `CARGO_PROFILE_DEV_DEBUG=0 CARGO_INCREMENTAL=0 vp test packages/reffect/tests/collection-combinators.test.ts --maxWorkers=1` passes **4/4** (11.20 s total, 9.41 s tests). Fresh native std crates compile in debug and release under Bounded and None failure policies; crate list stays empty. Cases include first/middle/last/excluded-index/no matches, empty arrays, u64 maximum, owned String payloads, Boolean truth tables, symbolic predicate composition, own `__proto__` record keys, and public namespace/witness identity. Reference-only defect expressions establish that decisive Boolean, Predicate, `some`, `every` and `findFirst` results skip later runtime predicate expressions. Strict package TypeScript and focused formatting/lint checks pass. The first test run used an incorrect remembered upstream empty-array spelling; checking actual pinned source corrected the API before the passing evidence above. A transient parent callable-wrapper descriptor error was also fixed before validation.

Revisit COL-001/COL-004 when searches on long or non-Copy arrays matter: introduce a checked search node with early termination, then compare predicate order and clone/allocation counts before replacing this specialization. Record lookup, filterMap, array indexing, order-sensitive sorting, and refinement signatures remain unsupported here.
