# Bounded Deferred continuation turns

Recorded 2026-10-04 before feature implementation. This develops LCOORD-009/010 and DN-007; it does not claim Deferred admission or completed scheduler equivalence. Reviewed AGENTS, PLAN/PROGRESS, Deferred core/native/conformance records and the actual `structured-runtime.ts`, `async-runtime.ts` and `lower.ts` implementations. [Published Effect 4.0.0 Deferred](https://unpkg.com/effect@4.0.0/src/Deferred.ts) was fetched and compared byte-for-byte with the installed source. The installed [fiber/async implementation](https://unpkg.com/effect@4.0.0/src/internal/effect.ts) explains synchronous callback evaluation; [Scheduler](https://unpkg.com/effect@4.0.0/src/Scheduler.ts) establishes the additional automatic-yield boundary.

## Decisions before implementation

**TURN-001 — One borrowed invocation bank, separate from values and AsyncContext.** Generate `TurnBank<const N: usize>` only when lexical coordination is reached. Declare it before lexical Deferred states in the enclosing invocation future. Pass `TurnHandle<'a,N> { bank: &'a TurnBank<N>, slot: usize }` separately through coordinated helpers. Existing AsyncContext remains lifetime-free and existing non-coordination programs retain their layout. Owners, producer futures and pinned child futures borrow the bank; structured draining proves that those borrows end before invocation close. No global registry, thread-local current task, Arc owner or scalar wrapper is needed.

A proposed safe representation is an inline Mutex containing fixed arrays: live slot/parent records, per-slot semantic-pending flags, and a request stack. Each request is `{ caller_slot, target_slot, acknowledged }`. A bank contains identities and protocol flags only, never sibling Future pointers or references. All locks end before polling, waking, logging or executing authored code. Runtime capacity exhaustion is an invariant fault after compiler admission, never a spill allocation or a user-visible queue capacity.

**TURN-002 — Prioritize a turn, not a Waker.** A registered Deferred waiter stores its turn slot and a removable registration identity in an ordered inline list. Winning completion retains its immutable Result and detaches the registration cohort under the owner lock. Outside that lock it releases one surviving registration and pushes a request for that task. While the request is unacknowledged the selected task is the priority; after acknowledgement the completing caller is the priority. Other runnable tasks cannot advance until the caller consumes that acknowledgement and either selects the next waiter or returns completion.

A child wrapper must consult current priority on _each poll_, including later branches of the same coordinator poll. Permit the priority slot and ancestor coordinator routes; block unrelated subtrees. This is stronger than polling a preferred branch first and then freely polling peers. A nested group must route priority to its selected descendant without acknowledging its own waiting parent as a semantic suspension merely because it is driving the adapter. Bank transitions wake the current root executor Waker so a priority caller earlier in the coordinator's branch order is polled again. Executor Wakers are scheduling notifications, not stored computation identities.

**TURN-003 — Acknowledge only an actual semantic boundary.** Wrap the entire child computation, including its typed recovery and awaited cleanup, rather than wrapping only Deferred.await. Before polling an admitted task, clear that slot's semantic-pending flag. A pending primitive marks the flag only after its inner Future really returns Pending: unresolved Deferred await, literal Sleep and admitted cancellation/resource waits. Readiness does not mark suspension. Completion's protocol Pending is explicitly an adapter boundary and does not mark it. The enclosing wrapper acknowledges its current request only on Ready or on Pending with its own slot's semantic flag set. A child's flag never acknowledges its ancestor.

The initial implementation must enumerate every suspension reachable under this profile and either instrument it or refuse it. Existing `ctx.sleep` uses Tokio select directly; simply marking entry to that function is wrong when the timer/cancellation is immediately ready. Store/stream/host operations remain refused in coordinated children pending their own polling contracts. Cancellation dropping an await is not itself the acknowledgement: cleanup may perform synchronous logs or reentrant completion before its first real suspension.

**TURN-004 — Return completion inside the producer's poll.** The acknowledged request continues to prioritize its caller until `CompletionFuture.poll` consumes it. That poll pops the request, selects the next waiter if any, or returns Ready. Rust's enclosing async computation then executes synchronous maps/flatMaps and producer logs in the _same_ poll before the coordinator can poll another child. Thus an earlier waiter that yielded cannot run its later continuation before `producer:true` merely because it has become runnable.

This atomic poll/continuation relationship is an emission invariant: do not split a helper's completion result and its synchronous continuation into independently scheduled jobs. A separate ResumeProducer frame is unnecessary with current directly awaited helper composition. If later emission breaks that invariant, a producer continuation lease must replace it before admission. In particular, popping the final request from a different child's acknowledgement wrapper would be incorrect.

**TURN-005 — Reentrant depth is bounded by blocked callers, not owners or loop iterations.** When selected waiter W1 completes a second Deferred, it pushes a request selecting W2 while its outer request still targets W1. W1 is adapter-pending, so its outer acknowledgement remains withheld. W2's real suspension/completion acknowledges the inner request; W1 resumes, consumes/pops it, and continues until its own semantic boundary, which acknowledges the outer request.

At every active request, the caller is blocked inside that completion. It cannot register another await or start another completion until it consumes/pops the request. Therefore active requests have distinct caller slots. Their maximum depth is at most N, the checked maximum simultaneously live task contexts; the number of lexical owners, sequential scopes and Repeat iterations does not multiply it. An owner already completed has no remaining pending registrations, so reentrant completion of that owner returns false immediately. A task currently blocked in another completion cannot itself be a newly registered target; this rules out a cyclic priority stack in the admitted sequential task bodies.

Consume/pop an inner request before returning Ready, rather than retaining a ResumeProducer frame: otherwise the same task could start successive completions and stack multiple frames with the same caller. An implementation choosing that alternative must replace a completed producer lease, never blindly push another frame.

**TURN-006 — Reuse slots without unbounded counters.** Use per-request acknowledged flags and per-poll semantic flags, not a monotonically increasing semantic epoch. A target's Ready wrapper acknowledges before its slot may be retired. A canceled pending registration removes only itself; completion skips detached registrations that no longer survive. No live request may refer to a slot newly assigned to a different task. The static initial topology gives each simultaneously live child a distinct checked route; group drain and request retirement must precede route reuse in sequential scopes or repeated groups. Assert this invariant in the state prototype/tests. If dynamic allocation is later introduced, add a proved bounded lease protocol instead of relying on a wrapping generation counter.

With one three-child outer All and one two-child inner Race there are six contexts including the root, and four possible leaf awaiters. Waiter capacity and bank/context capacity are separate bounds. Pure sequential operations remain on their current context slot; lexical Deferred nesting adds owners but not task slots.

**TURN-007 — Broadcast is synchronous with respect to producer interruption.** Save the producer's interruptibility and mask only while a winning completion drives its detached cohort. Do not select its watch cancellation against the CompletionFuture. Keep broadcasting after cancellation becomes pending. Restore the previous flag once completion returns; if the original producer was interruptible, check pending interruption before its next authored continuation. If it was already masked, the Boolean continuation runs, with interruption observed at its later restoration boundary. A late waiter reads the installed result without joining the detached cohort, and losing completion is immediately false.

Each selected waiter retains its own context and interruptibility. Its cancellation processes its existing awaited finalization before acknowledgement unless that cleanup itself truly suspends. Parent group cancellation still drains all children. Forced host Future drop remains the existing trusted-host limitation, not asynchronous-finalization support.

**TURN-008 — Initial admission and automatic yielding are separate proof gates.** Initially allow only the existing checked outer group and optional initial inner Never Race. Conservatively refuse task-group creation in resumed waiter continuations, including error/recovery/cleanup paths, until eager child admission and nested group suspension are proved. This still admits the independent cancellation witness: the inner Race exists before awaiting main, its losing waiter's cleanup completes the signal, and the unrelated waiter remains alive.

Default Effect Scheduler yields when currentOpCount reaches 2048. Both automatic yield and explicit yield terminate callback prefixes. The framed reference interpreter introduces additional primitives, so counting authored IR nodes alone does not prove a prefix stays below that threshold. No custom Scheduler context is admitted by this proposed profile. Before implementation acceptance, derive and probe a conservative primitive-count envelope for plain and framed interpretation. Refuse unbounded or oversized synchronous callback prefixes, including zero-delay Repeat/Retry and ForEach, until that proof exists. Do not assume a fabricated operations-per-node bound. A timer or explicit yield test is supplemental, not evidence that automatic yielding has been solved.

## Proposed API and lifecycle

The protocol can expose these internal methods without retaining peer futures:

```rust
impl<const N: usize> TurnBank<N> {
    fn priority(&self) -> Option<usize>;
    fn permits(&self, slot: usize) -> bool; // priority or its ancestor route
    fn before_poll(&self, slot: usize);
    fn semantic_pending(&self, slot: usize);
    fn after_poll(&self, slot: usize, ready: bool, cx: &Context<'_>);
    fn push_request(&self, caller: usize, target: usize, cx: &Context<'_>);
    fn consume_ack(&self, caller: usize) -> bool; // only caller's top request
}
```

Registration happens before releasing a waiter. Completion copies a bounded detached cohort in registration order, using registration identities rather than physical slot order. Selected await returns its stored Copy Result, then the surrounding helper continuation runs until a real suspension or completion. Nested completion changes priority without acknowledging the outer caller. Each consumed acknowledgement retires its request before that producer selects another target. Invocation close asserts empty bank stack and no live registrations. Pure payloads remain Bool/U64/Unit; failures acquire per-await frames rather than retaining producer frames.

## Prototype evidence and remaining obligations

A safe Rust scheduling prototype in `/tmp/reffect-turn-prototype/main.rs`, owned by the prototype agent, uses inline bank/Deferred state and no sibling Future references. Its test harness boxes heterogeneous test futures; that allocation is not required by the generated fixed-arity pinned coordinator. It demonstrates exact nested-completion, nested-yield, reversed-registration and producer-interruption traces. This is preliminary scheduling evidence, not durable native conformance: it does not yet prove real Tokio cancellation, ancestor routing, framed cleanup, poison/drop invariants or generated Rust borrows.

The durable independent official oracle in `packages/reffect/tests/fixtures/deferred-turn-oracle.ts` asserts all seven LCOORD-009 traces. Each fiber starts immediately, callback registration counts are verified directly, and a separate start gate ensures the producer identity exists before callbacks can interrupt it. Running the fixture with Node and Effect.runPromise passed all seven traces; producer interruption yields Failure under both masks. These observations do not discharge native equivalence.

Acceptance requires independently authored official/plain/framed/native traces, including a producer positioned before the resumed waiter in coordinator polling order, registration order differing from physical slot order, nested callback completion, semantic yield after the first prefix, canceled next waiter, producer cancellation under both masks, and the independent nested-Race isolation workload. Test repeated sequential scopes/groups and first/losing completion with empty cohorts. Probe parent cancellation during masked cleanup, callback cleanup that completes another signal, and cancellation of a detached but not yet selected registration. Preserve causal log order; no sorting.

Measure bank/state/future bytes, peak stack depth, waiter slots, Waker clones, allocation counts, generated source growth and None/Bounded costs. Compare non-coordination emitted artifacts and existing allocation budgets. Deferred remains unadmitted until the automatic-yield admission bound and these runtime obligations pass; this record approves a candidate bounded protocol for implementation, not a completed scheduler port.

## Automatic-yield admission investigation

**TURN-009 — Count evaluator operations from source; node count is insufficient.** Effect 4.0.0 increments `currentOpCount` at every run-loop iteration and also inside `succeedWith`. The latter has a 32-step trampoline that can return a Success primitive for another iteration. The default MixedScheduler asks whether this count is at least 2048. Every new `fiber.evaluate` invocation resets the count, including a synchronously resumed callback. Consequently a total operation upper bound below 2048 for each possible evaluation turn would suffice under the default scheduler; short observed traces alone do not establish that bound. An unproved node has infinite admission weight, rather than an invented constant.

Reviewed the current plain and framed evaluators at `effect-ir.ts` runUnknown/evaluate and runWithFramesUnknown/evaluate, as well as the upstream Suspend/OnSuccess/OnFailure/Iterator/OnExit primitives, `try`, `map`, `flatMap`, `catchCause`, `succeedWith`, `ensuring`, concurrent iteration and finalizer close paths. These source-level accounting atoms give a concrete starting rule:

| Expansion atom               | Conservative operation charge | Source reason                                                                                                                                                                                       |
| ---------------------------- | ----------------------------: | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Suspend                      |                             1 | One run-loop evaluation returns its thunk's effect.                                                                                                                                                 |
| Success or Failure primitive |                             1 | One run-loop evaluation; synchronous continuation invocation itself is not another primitive.                                                                                                       |
| Expression `Effect.try`      |                             2 | Suspend plus the produced Success/Failure. Ordinary pure expression traversal does not itself increment the Effect evaluator count.                                                                 |
| `Effect.flatMap` wrapper     |                             1 | OnSuccess pushes its continuation in one run-loop evaluation; the continuation returns the next effect. Charge that returned effect separately.                                                     |
| `Effect.map` wrapper         |                             3 | OnSuccess evaluation, one succeedWith increment and at most one extra Success trampoline iteration. Three is conservative even though the extra iteration happens only at the inline-step boundary. |
| `mapFramedError` wrapper     |                             2 | OnFailure wrapper plus the FailCause primitive on its failure path; Cause.map and diagnostic construction are synchronous JS.                                                                       |

These are expansion weights, not a universal per-IR-node constant. For the actual leaf/composition definitions, for example, plain Succeed costs at most 5 (outer Suspend + expression 2 + flatMap 1 + returned Success 1); plain Map adds at most 7 over its source (outer Suspend 1 + map 3 + flatMap 1 + expression 2). Framed Map adds at most 8 over its source (outer Suspend 1 + source error decoration 2 + flatMap 1 + expression 2 + expression error decoration 2). Plain FlatMap adds 2 over source plus body; framed FlatMap adds at most 6. Each branch of Match/MatchTags contributes its maximum reachable branch weight, while sequential composition contributes the sum. Shared IR objects must be counted per executed occurrence/edge, not deduplicated by object identity. An overflow-safe capped sum should stop at the admission threshold.

A first implementation may deliberately use a whole-invocation expanded weight rather than a precise prefix analysis: sum every reachable occurrence, all admitted cleanup and recovery paths, group startup/observer/teardown expansions and the reference entry/observer wrapper. That overcounts separate child fibers and asynchronous segments, which is safe. Require the resulting bound to be at most 2047. This avoids needing to infer whether a particular timer or await will actually suspend. Reject loops, Repeat, Retry, ForEach, stream/host operations, custom scheduler contexts and resumed-callback group startup in the first profile. Later prefix analysis can recover programs excluded by whole-invocation overcounting.

**The complete weight table is not proved yet.** The above atoms and simple composition charges do not cover the reference's named Effect.fn/context/span setup, input Schema decode, observer teardown, Scope finalizer iteration, All/Race child observers, cancellation/mask restoration or proposed Deferred operations. In particular, the independent cancellation witness needs Ensuring and nested Race; refusing those unaccounted expansions would defeat its acceptance workload. Do not admit that workload merely by applying the simple-node table. Finish the exact upstream expansion audit, or retain the feature gate. A future change to Effect or the reference wrappers invalidates the associated weight proof and must trigger revalidation.

**TURN-010 — Public scheduler instrumentation validates accounting, not admission by sampling.** A research probe subclasses exported `Scheduler.MixedScheduler` and overrides its public `shouldYield(fiber)` method, reading the public readonly `fiber.currentOpCount` and then delegating to `super.shouldYield(fiber)`. Running with `Effect.runPromise(effect, { scheduler })` changes no yield decision; it records maximum observed counts and automatic-yield decisions. This is distinct from setting an artificially large budget or PreventSchedulerYield, which would change the contract being tested. Explicit Effect.yieldNow is not an automatic shouldYield decision.

The probe `/tmp/deferred-yield-budget.mjs` ran the seven durable independent official Deferred oracles and current built plain/framed R reference programs. It used no custom logger/tracer/context and no timer ordering proof. Observations on 2026-10-04:

| Program                                                | Maximum observed plain count | Maximum observed framed count | Automatic yield    |
| ------------------------------------------------------ | ---------------------------: | ----------------------------: | ------------------ |
| Zero-argument scalar success                           |                           17 |                            18 | None               |
| 64 successive R.Effect.map occurrences                 |                          403 |                           402 | None               |
| 256 successive maps                                    |                         1564 |                          1554 | None               |
| 512 successive maps                                    |                         2048 |                          2048 | One in each policy |
| 64 FlatMap + Unit-success pairs                        |                          465 |                           530 | None               |
| 64 nested Ensuring nodes, successful body/Unit cleanup |                          785 |                           786 | None               |
| 64 nested Ensuring nodes, failing body/Unit cleanup    |                          849 |                           916 | None               |

The seven independent official Deferred scenarios observed maxima between 13 and 17 and no automatic yield. Their explicit-yield traces still yielded explicitly, as expected. Framed and plain counts differ, and success versus failure/finalization differs; a single empirical operations-per-node coefficient would conceal those differences. Probe values are observations, not constants for a compiler proof, and the built reference does not yet contain Deferred IR interpretation.

The fixed default-scheduler assumption is therefore sufficient _only conditionally_: an audited, finite source-expansion bound below 2048 rules out automatic yielding for the admitted turn. It is not sufficient for arbitrary graphs, nor does a short native kernel trace prove the needed reference bound. Durable validation should compare audited symbolic weights with public instrumentation for success, failure, cancellation, nested finalization and framed decoration, including a fixture immediately below and one above the threshold. Compiler refusal must precede lowering for every unaccounted operation. No runtime budget field or extra metadata on scalar values follows from this build-time admission analysis.

**TURN-011 — The cooperative owner profile needs no stored per-waiter Waker.** Every admitted child is a borrowed pinned computation polled through the same owning invocation executor. Deferred completion can occur only within that checked invocation; owner handles cannot escape to an external task/thread or a second independently spawned executor. Registration therefore stores its task/registration identity, not a cloned Waker. Request and acknowledgement transitions call `wake_by_ref` on the current executor Context's Waker after releasing the bank lock. Real Sleep/cancellation primitives register their own executor notifications as usual. Losing/late completion requires no broadcast Waker clones.

This refines DN-003's initial detached-Waker-array candidate into a detached ordered task-ID cohort for the bounded cooperative profile. It reduces retained waiter state and avoids the need to claim executor-independent Waker clone allocation costs. It does not establish interoperability with a generally shared Deferred, external completion, or independently spawned waiters; those need a different ownership and wake-delivery proof. Measure the selected owner/runtime rather than charging a proposed Waker array that the implementation does not emit.

Reviewed the focused `deferred-turn-runtime.ts` candidate: its inline stack, Boolean semantic flags and changed flag match the request/ack protocol. Its request assertions enforce distinct active completing callers and prevent selecting a blocked caller as a parked waiter. Its `after_poll` acknowledges only the top selected slot; ancestor routing receives no implicit acknowledgement. The checked route predicate is supplied by the coordinator outside the bank lock. Per-waiter registration/state and root coordinator polling remain outside this kernel, so this review is not public Deferred ownership admission.

**TURN-012 — Declared Never does not prove an infallible coordination outcome.** The existing fallible-task record already proves that pending cancellation can skip recovery while retaining its source failure after E changes to Never. A future typed Deferred await has the same source-failure question, even without a syntactically fallible TaskGroup. Before integrating it, revisit reachability selection of the erased failure carrier, cancellation-aware catches and the infallible task wrapper that currently treats Combined as impossible. Do not select those paths solely from the final declared child E. Prove retained-outcome bounds through the proposed nested topology and preserve the RPC refusal until richer causes have wire conformance. This is a compiler/runtime integration obligation, not behavior established by the success-only kernel fixture.
