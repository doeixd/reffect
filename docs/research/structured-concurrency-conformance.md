# Bounded task-group conformance

This evidence supports the Unit/Never two/three-child All and two-child Race profile described in [preparation](structured-concurrency.md). It does not establish general Fiber, failure Cause composition, detached tasks, shared mutable services or externally dropped future cleanup.

## Test design decisions

| ID           | Choice                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          | Revisit condition                                                           |
| ------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------- |
| TASKCONF-001 | Independently author official Effect programs rather than deriving the oracle from IR. Compare stock Effect, plain reference, framed reference, native debug/release and both failure-frame policies.                                                                                                                                                                                                                                                                                                                                                                           | A broader outcome type or additional task combinator is admitted.           |
| TASKCONF-002 | Logger events establish interruption barriers: both All children started, or the Race loser's masked cleanup started. Native All stderr JSON records trigger a stdin byte; a Rust host thread sends cooperative watch cancellation. For native Race cleanup cancellation, manually poll the complete parent once to its first Pending (pending loser, immediate winner, then masked loser cleanup), signal cancellation in Rust and await it; this avoids an IPC race against a short cleanup timer. Five-millisecond cleanup sleeps provide suspension, not an ordering proof. | A public synchronization primitive can replace harness-only host signaling. |
| TASKCONF-003 | A pending first Race child and an immediate second winner deterministically establish admission order. A separate immediate first winner must prevent the second child from starting.                                                                                                                                                                                                                                                                                                                                                                                           | Scheduling or admission strategy changes.                                   |
| TASKCONF-004 | Assert each child's causal trace and then compare normalized records. Independent sibling ordering is deliberately unconstrained. Verify LIFO registered finalizers, exactly-once cleanup, parent cleanup after every child, and no continuation after interruption.                                                                                                                                                                                                                                                                                                            | An API promises a stronger ordering contract.                               |
| TASKCONF-005 | Compare annotation values and span labels. Parent snapshots must reach both children; child-local annotation scopes and their finalizer snapshots must not leak into siblings or the parent.                                                                                                                                                                                                                                                                                                                                                                                    | Request identity or distributed tracing has its own host workload.          |
| TASKCONF-006 | Allocation probes count whole completed group setup, including child watch channels. Context and unpolled-future construction are measured separately. One hundred completed groups must retain no net live allocations in the quiet current-thread probe. The established quiet setup budget is exactly two allocations per group; the fixture now rejects additional allocation growth.                                                                                                                                                                                       | Runtime substrate or context layout changes.                                |

## Coverage

[Structured tests](../../packages/reffect/tests/structured-concurrency.test.ts) cover three-child All success, two-child Race, parent cancellation of independently suspended All children, cancellation during Race loser cleanup, immediate winner admission, per-child Scope LIFO finalization, enclosing Ensuring lifetime and local log annotation isolation. Masked acquisition cases prove All children inherit the acquisition mask and complete both bodies, whereas Race children remain interruptible and the loser is interrupted; outer cancellation prevents the use callback and still awaits release exactly once. Full/None provenance fixtures verify group and child occurrence/range retention independently of disabled failure frames. Native cancellation is cooperative: the host awaits the parent future to completion after signaling it.

[Type fixtures](../../packages/reffect/tests/structured-concurrency-types.ts) verify inferred Unit/Never results, tuple arities and the data-last Race form. They reject runtime arrays, collected values, typed failures, unsupported options and Race options. Checker fixtures deliberately bypass authoring witnesses to exercise defensive malformed-IR validation. Ownership/service fixtures reject nested groups, groups inside cleanup, inherited parent Scope registration, captured lexical Ref/file, scripted Random, injected Clock and Launch work; default live Clock and child-local lexical Ref remain admissible.

Numeric values carry no task metadata. The quiet native probe excludes the outer host watch channel and Tokio runtime initialization from context/future construction, but includes every child watch allocation in completed group setup. It does not claim zero allocation during group execution. The retained count is a scoped allocator observation of quiet successful groups, not a process RSS or all-workload leak proof. Context/future sizes describe generated concrete types for the probe and can change with Rust version, policy and reachable logging/Scope features. Baseline and group future sizes represent different workloads, not an isolated scalar-field delta.

## Validation

Focused validation on **2026-10-03**, x86_64 Linux, **rustc 1.98.1**:

```sh
. "$HOME/.cargo/env"
CARGO_PROFILE_DEV_DEBUG=0 CARGO_INCREMENTAL=0 \
REFFECT_TASKGROUP_MEASUREMENTS=/tmp/taskgroup-reviewed-layouts.log \
./node_modules/.bin/vp test packages/reffect/tests/structured-concurrency.test.ts \
  --maxWorkers=1 --reporter=verbose
```

**5/5 tests passed**, 137.85 seconds total, 136.44 seconds in tests (`/tmp/taskgroup-reviewed-complete.log`). Native lifecycle ran seven scenarios under debug/release and None/Bounded policies; the allocation probe ran both policies, both build modes and both workload variants. The first preparation run's malformed Launch fixture was corrected because the authoring guard rejected Never success before the intended host-capability check. Subsequent expanded admission checks passed.

Strict package TypeScript and targeted `vp check` passed. The final follow-up made terminal success explicit alongside interruption in both oracle and native observations. The affected official/reference and native lifecycle selections passed **2/2**, with the other three tests skipped because their source and cost probes were unchanged: 61.81 seconds total, 60.06 seconds in tests (`/tmp/taskgroup-exit-validation.log`). Command: the same native environment and test path above with `-t 'structured children|native task groups'`, without the measurements environment variable. All seven lifecycle cases again passed debug/release with both frame policies.

Debug and release produced the same listed layouts and allocation counts. Context construction and unpolled future construction added zero allocations in all four variants. The outer host cancellation watch and initialized Tokio runtime precede those counters; **every child watch channel created while executing the group is included**. Baseline execution is deliberately unpolled: its zero setup allocations do not establish zero-allocation Sleep execution. Generated library size is emitted UTF-8 Rust source, not native binary size. Logging and resource Scope are absent from the cost workload; the lifecycle workload exercises those features separately.
