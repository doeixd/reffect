# Scope registration: real-file workload and evidence gates

Research-only contribution, checked **2026-10-02**. This proposes acceptance evidence for milestone 3A; it does not establish an implemented API or supersede the parent-owned [registration decisions](resource-scope-registration.md). The parent owns integration into the docs index and PROGRESS.

## Recommendation and boundary

Choose a **bounded read-only file-metadata session**: acquisition helpers register files in the current outer scope, return to the session, and the session uses an earlier file after later conditional/repeated registrations and suspension. Actual files stay open until that scope closes. Releases close the owned file, then await non-failing logging cleanup, sequentially in reverse registration order.

This is the missing discriminating workload. Existing `R.File.scoped(path, use, afterClose)` closes at the end of its own use body. A new test that merely nests that API, or registers logs while keeping files inside old brackets, cannot prove outer-scope resource registration. Generate concrete helpers and scope-owned storage if possible, but retain the delayed lifetime and runtime registration multiplicity. Public spelling and binder/continuation shape need the parent design decision; the descriptions below are behavior, not shipped `R.File.acquire` examples.

Keep FILE-001–005's boundaries: build-time validated paths, read-only owned `std::fs::File`, borrowed metadata access, u64 size, Boolean `false` IO failure, ignored read-only close errors, no handle in function input/output/error or wire values. Scope registration moves ownership into the enclosing scope; it does not make handles ordinary returnable Expr values. Unit/Never cleanup remains Exit-independent. Sequential lexical nesting is sufficient; `Scope.fork`, parallel close, cross-fiber transfer, dynamic paths, resource Layers, fallible/Exit-aware release and abort/drop guarantees are separate work.

## Primary sources, versions and checked semantics

Package dependencies pin `effect` and `@effect/platform-node` to **4.0.0-rc.118**. Native selection pins **Tokio 1.53.1**. Online sources consulted on the date above:

1. [Pinned Scope.ts](https://unpkg.com/effect@4.0.0-rc.118/src/Scope.ts): open registrations run on scope close; sequential order is reverse registration order; close is masked; registering on a closed scope runs immediately. Installed `node_modules/effect/src/internal/effect.ts`, `scopeCloseUnsafe`/`scopeCloseFinalizers` (lines 3969–4024), marks Closed before draining, returns without rerunning on repeated close, and awaits each sequential finalizer.
2. [Pinned Effect implementation](https://github.com/Effect-TS/effect/blob/effect%404.0.0-rc.118/packages/effect/src/internal/effect.ts): installed `acquireRelease` (4165–4181) masks acquisition and registration together by default, registers only successful acquisition, and provides the **registration-time Context** to release. `addFinalizer` (4184–4193) also captures Context. The admitted workload uses default masked acquisition; `{ interruptible: true }` needs separate admission/evidence.
3. [Node FileHandle.close](https://nodejs.org/docs/latest-v24.x/api/fs.html#filehandleclose), retrieved documentation **24.21.0**: awaits pending handle operations; the handle's `close` event marks unusability. Explicit close is required; GC auto-close is unreliable. `stat({ bigint: true })` preserves exact size.
4. [Rust File](https://doc.rust-lang.org/std/fs/struct.File.html), retrieved documentation **1.99.0**: File owns an open file, Drop closes and ignores errors, metadata borrows it, and `try_clone` creates another ownership obligation. No clone is needed for this workload.
5. [Tokio 1.53.1 spawn_blocking](https://docs.rs/tokio/1.53.1/tokio/task/fn.spawn_blocking.html): started blocking work cannot be aborted; queued work may be aborted. Await the JoinHandle under the acquisition mask and do not abort/detach it on cooperative cancellation.
6. [Windows GetHandleInformation](https://learn.microsoft.com/en-us/windows/win32/api/handleapi/nf-handleapi-gethandleinformation): queries a specific file HANDLE, returning zero on failure. It enables identity-specific ownership observations without requiring Linux `/proc` or unreliable unlink/rename behavior.

Environment observations: `node --version` reports **v26.5.0**; `rustc --version --verbose` reports **1.90.0, x86_64-pc-windows-msvc**. These differ from the Node 24/Rust 1.98 Linux measurements in earlier records. The basic File/Drop/metadata and handle-observation APIs suffice on this toolchain; do not transplant earlier layout numbers or claim this research ran on Node 24. The Effect skill was reviewed; installed v4 `Context.Service`/`Effect.catch` APIs take precedence over its v3-oriented examples.

## Workload specification

Create isolated files `base-é` (5 bytes) and `optional` (7 bytes), plus an intentionally missing path. Keep test paths build-time literals in the authored fixture.

1. Enter one outer session scope and acquire/register base lease **A**. Its acquisition helper returns; log `registration:return:A` before any release. Retain a scope-bounded symbolic borrow for subsequent size queries.
2. Under a runtime Boolean, acquire/register optional lease **B**, or skip it. An inverted-order variant registers B then A. This distinguishes close order derived from actual registration from static source order.
3. Execute a shared Unit acquisition-and-registration computation **k** times, opening fresh base leases **C1…Ck**, each with its own captured scalar token. Use finite structured repetition/branching; test `k = 0, 1, 3` and the capacity boundary. `Schedule.recurs(n)` means initial execution plus n recurrences; represent zero with a branch, and budget runs rather than schedule recurrences. Do not put `scoped` inside the repeated acquisition.
4. After those helpers have returned, suspend, then query **A.size** again. Require 5 and a live A observation at this point. In the optional variant query B within its admitted branch/binder region; no Option<File> or runtime collection of user-visible handles is necessary.
5. End use by success, Boolean domain failure, or cancellation at a controlled use suspension. Close the outer scope. With B enabled and k=3, the release identities must be **C3, C2, C1, B, A**. Each release moves/takes its owned File exactly once, closes it, logs `release:start:<id>` with captured token, awaits a suspension, and logs `release:done:<id>`. The next release starts only after the previous `done`.
6. An outside recovery/continuation logs only after A's awaited release finishes; it may return a scalar result but cannot use A or any borrowed file computation.

The repeated entries must capture **different evaluated scalar values**, not all read a reused loop binder's last value at close. For a dedicated capture fixture, use the injectable file adapter/test seam to open a predetermined sequence of real files of sizes 5, 7 and 11 for successive executions of one acquisition site. Query size immediately after each acquisition and register an additional scalar-capturing finalizer with that evaluated size. Require close-time scalar logs 11, 7, 5 and matching actual file identities. Apply the same controlled adapter sequence to the independent official fixture, IR reference and native seam; label this adapter-injected case separately from ordinary path-open conformance. This needs no iteration value, user-side mutable counter or new Ref API. Budget both registrations per iteration. Distinct fixed acquisition sites alone are insufficient evidence for repeated shared-site captures.

Alternative assessment: nested lexical brackets can reproduce some LIFO traces but do not demonstrate retained outer ownership or repeated registrations after helper return. Log-only finalizers validate ordering but cannot catch premature/lost file ownership. A full file/session service with public handle collections would add representation and API work without improving this gate. Prefer the existing file adapter plus bounded sequential scope ownership, and retain scalar token fixtures as complementary evidence.

## Observation and deterministic interruption protocol

**Three-way oracle:** independently author the workflow in pinned official Effect using one outer `Effect.scoped` and `Effect.acquireRelease` per successful file open, ignoring the release Exit argument. Compare it to the new IR's ordinary and framed reference interpretations, then generated native execution. The official fixture may use ordinary JS helpers/arrays for observation; compiled callbacks remain symbolic structured IR. Official Effect has no 16-entry capacity: compare admitted cases only; refusals are reffect boundary tests.

**Reference injection:** supply `ReferenceFiles` with an adapter that opens real Node files, assigns a unique acquisition ID, records open/stat/close attempts and successful closures, and signals Deferred phase barriers. Save each fd; stat it while live, await `file.close()`, then assert invalidity before after-close logging. Count close _attempts_ as well as close events so a swallowed second-close error cannot pass. Avoid descriptor reuse between close and invalidity observation. Keep actual FileHandles strongly reachable until explicit close, preventing GC from supplying evidence.

**Native acquisition:** retain the existing max-one-blocking-worker queue barrier as a cheap pre-open suspension case. Add a test-only injectable acquisition seam that runs the actual `File::open`, signals **opened-but-not-returned**, and waits on a gate **before returning the File** to the masked acquisition helper. Send cooperative cancellation, assert no use or completion while blocked, then release the gate. The file must be installed in scope ownership and released once; later acquisition is skipped. This covers the post-open/pre-registration gap that a queue blocker alone cannot observe. Harness hooks stay test-only and use a single emitted, identifiable adapter seam; avoid brittle text replacement of generated Rust or a new public runtime option. The parent must choose the seam before implementation.

**Native actual closure:** have the test-only seam save non-owning raw identities (`AsRawHandle` on Windows, `AsRawFd` on Unix), without duplicating ownership. On Windows check `GetHandleInformation` while live and immediate failure with `ERROR_INVALID_HANDLE` after close; on Unix use a platform-appropriate descriptor query returning `EBADF`. Gate the next open while checking invalidity to avoid ID reuse. Raw observations must not create another File/OwnedHandle or call close themselves. A per-acquisition release-attempt counter and before/after identity checks, combined with single owned storage/take and no clone, establish exactly-once release under supported control flow; they are not syscall tracing.

Use process-handle count/Linux `/proc/self/fd` only as a **secondary leak/count check** in an isolated warmed native probe. Warm runtime/thread pool/log sink, quiesce outstanding work and keep observer handles/channels stable. At the post-registration checkpoint require the exact expected live-file delta, not merely `> baseline`; after each gated release require a decrement of one; at completion require baseline. File-specific invalidity remains the primary check because Windows process counts include events, threads and other handles. Successful rename/unlink is not portable proof of closure because sharing flags and Unix unlink semantics permit open files.

**Cleanup cancellation:** hold the first awaited cleanup at a known barrier, send cancellation and verify the entire scope future stays Pending. Unblock and require all `done` logs and file closures before caller completion. In reference use an injected logger to signal `release:start` plus an injected awaited barrier; in native use a test-only cleanup barrier, or a first Pending poll only when all preceding acquisition/use suspension has been ruled out. Do not signal based on a fixed 10ms timer or assume the first Pending means release. Capture logging annotations/spans at registration and register under different lexical annotation scopes that have ended before close. Compare the oracle's actual records: registration-time Context capture, lexical restoration, scalar tokens, event order, and no contamination of subsequent invocations.

## Concrete acceptance matrix

All admitted execution rows compare independently authored official Effect, reference (ordinary/framed where applicable), and native **debug/release × FailureFrames.Bounded/None**. Frame None changes diagnostics only; compare values/errors/interruption, counts and lifetime traces identically. Refusal rows need type/checker coverage and defensive native checks where stated.

- **SW-01 — Empty scope, optional false, repeat zero:** no acquisition/registration/release; baseline live handles; successful scalar/Unit exit. This is a separate no-base fixture, not the session that always acquires A.
- **SW-02 — Helper returns, later acquisitions, suspended later A.size:** A remains live and metadata succeeds after registration helper return; no release before use ends. This is the bracket-discrimination gate.
- **SW-03 — Optional B true/false; A/B inverted order:** release exactly reverses the executed registration sequence; skipped branch never opens/registers/closes.
- **SW-04 — Shared registration site repeats 1/3 times:** fresh actual handles and entries per execution, exact counts and reverse IDs; distinct evaluated captures preserved per entry rather than final binder value.
- **SW-05 — Success and typed use failure; recovery outside scope:** each successful open has one close attempt and one successful closure; all releases awaited before result/recovery; original failure preserved.
- **SW-06 — Failure before acquisition, missing acquisition after A, and retry fail→success:** before-acquire failure opens nothing. Missing file registers/closes nothing of its own, skips later acquisition, closes A. Retried failed attempts consume no slots; successful attempt registers once.
- **SW-07 — Pre-entry and between-registration cancellation:** pre-entry opens nothing. Between entries closes exactly the registered prefix in reverse order and never starts the next open.
- **SW-08 — Cancellation at queued open and opened-but-not-returned barrier:** caller waits while mask held; successful late acquisition registers/closes once; no use or later acquisition; all prior entries also released. No lost handle between open and install.
- **SW-09 — Cancellation during use and awaited close:** all files close once; all awaited finalizers finish in LIFO order before caller completion. On success during close expect interruption; with an already settled typed failure compare pinned failure precedence.
- **SW-10 — Nested lexical scopes:** inner registry drains fully before outer resumes; outer A remains usable afterward. Inner finalizer may borrow outer A while it is live; outer finalizer cannot capture an inner file that has closed. Evaluated copyable scalar captures may survive their original binder when stored safely. This does not require `Scope.fork`.
- **SW-11 — Captured scalar/token, log annotation/span and repeated invocation isolation:** large u64 token stays exact; each entry retains its own capture and oracle context; helper-return does not invalidate captures; next invocation has no stale handles/entries/log context.
- **SW-12 — Escaped/forged resource use and unclosed pending scope:** refuse use after scope closure, handle output/error/input, cross-scope invalid captures, forged channels/unregistered binder and fallible/Exit-aware cleanup; supported captures inside the owner region still compile without casts.
- **SW-13 — Capacity 0/1/15/16/17 and mixed entry kinds:** at 16 exactly 16 entries can close. 17 is refused before IO when statically provable. Count all file and plain cleanup entries, repeat multiplicity, successful retry attempts and branch maxima; bound is per scope instance, not per function/site.
- **SW-14 — Defensive full-capacity acquisition/registration:** no overwrite/drop-without-awaited-cleanup, panic-driven drain or leaked newly opened file. Reserve/check capacity before open under mask; refuse 17th open and drain existing 16. If install can fail after open, immediately close/await that new resource before draining prior entries. Runtime refusal is structured, separate from Boolean IO failure; exact error channel/precedence remains a parent decision.
- **SW-15 — Close twice / closed registration boundary:** if manual close is exposed, second close performs no release. Official closed registration runs immediately: either implement it or statically exclude closed scopes; a reachable runtime refusal must be explicitly reported as divergence, not parity.
- **SW-16 — Frame/source policy and costs:** typed-failure frame paths/omitted counts agree; None emits no frame storage and repeated drain is empty. Provenance identifies acquisition/registration/release sites. Measure registry/context/future layout and allocation costs independently of real IO/log polling.

## Capacity analysis and cost evidence

Use the proposed **16 entries per scope** only after deciding what an entry means. One file close plus its sequential after-close program should be one owned registration entry; independent `addFinalizer` registrations consume their own entries. Count **runtime occurrences**, not unique graph nodes or syntactic sites: sequence adds counts, mutually exclusive branches take the maximum, finite loops multiply executions, nested scopes have independent bounds, and retry counts successful registrations retained by the owner. A retry that registers successfully then fails later can retain entries across attempts; multiplying by attempt count is required unless an inner attempt scope drains them. Unbounded `forever`/retry/repeat registering into one outer scope must be refused absent a proved bound. Saturate analysis at 17 to avoid arithmetic overflow.

Prefer static refusal plus defensive pre-open capacity reservation; neither deferred overflow detection at close nor silently discarding the 17th finalizer preserves ownership. Official Effect has no corresponding capacity error. If the bound cannot be proved, choose documented refusal rather than pretending the oracle supports it. Parent must resolve whether dynamic overflow is reachable at all and where structured diagnostics flow.

Probe counts 0/1/4/8/16 with logging off and a separate logging-on corpus, under all four native combinations. Record `size_of` the registry, context, actual generated top-level/acquisition/close futures, emitted bytes/helper counts, construction allocations, and incremental registration/drain allocations. Compare context to the matching current-policy baseline; keep registry local to the scope rather than add a global stack. A fixed-capacity registry may pay its full layout at count zero: report that honestly and measure nested depth separately. Structural gate: no unbounded list, boxed dynamic helper futures, handle clones or resource table for this slice. Assert zero incremental allocations only for registry/context/unpolled future construction when the chosen representation warrants it. Warm Tokio and separate cancellation-watch allocation, spawn_blocking, timers, logging/JSON and failure-frame polling costs; existing zero construction evidence does not prove allocation-free execution.

## Missing gates in the existing registration record

1. **SCOPER-005 and its resolved log/token first workload cannot establish PLAN step 2 for registered real resources.** Existing lexical file evidence does not fill delayed outer lifetime, repeated ownership or acquisition→registration atomicity. Admit a bounded file-owned entry contract or label the real registration gate pending.
2. **Capture lifetime/storage is unspecified.** Typed cleanup lists need evaluated scalar captures, scope-safe resource borrows, repeated shared-site environments, and registration-time Context/log behavior after lexical helpers return. Unit/Never alone does not prove any of these.
3. **Capacity wording conflicts.** “Checked refusal” and “fails the close path” do not specify safe behavior after successful open. Static analysis must include loops/retries/multiplicity/mixed finalizers; defensive install must not strand the new resource or skip draining old ones.
4. **Acquisition cancellation gate is absent from the acceptance list.** Include pre-entry, queued open and post-open/pre-install cancellation plus failed acquisition consuming no entry.
5. **Closed-scope runtime refusal diverges from pinned Effect.** Excluding access through lexical scoped builders is a representability boundary; exposing a live operation with different behavior is not semantic equivalence. Record which is intended.
6. **Nested lexical scope vs fork needs clarity**, including child/outer capture validity, independent per-instance capacity and outer resource usability after inner drain.
7. **Exactly-once actual closure and mask restoration need independent observations.** Ordered logs, aggregate counts and swallowed close errors alone cannot prove individual ownership. Add before/after identities, attempt counts and post-close caller/next-invocation observations.
8. **Cost gates need registration/drain and zero/count/capacity/depth matrices**, not only unpolled future construction. No context-field growth is a design preference to verify alongside full scope/future cost, not proof of efficiency.
