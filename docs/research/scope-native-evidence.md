# Native Scope registration evidence and design assessment

Research/design only, checked **2026-10-02**, in the existing `master` workspace. No feature implementation or native prototype is claimed. This record assesses the next milestone 3A slice against [PLAN](../../PLAN.md#current-frontier), [PROGRESS](../../PROGRESS.md), [Scope preparation](resource-scope-registration.md), [scoped files](scoped-files.md), and [async RPC](async-rpc.md). Only this new document is owned by this task; index/progress integration is left for the integrating owner.

## Recommendation

Implement **lexically owned, sequential scopes with generated finalizer enums**, a fixed-capacity array of owned records, runtime length/order, and an exhaustive concrete async close match. Statically known finalizer variants do not imply statically known executions: branching, bounded repetition, retry and recovery can append different instances and captures at runtime. Prove the maximum registrations per scope instance before execution; refuse programs without an adequate proof. Preserve the authored `Never` registration error channel.

Admit scalar captures and one specialized **owned read-only File acquisition/registration** path. Store the File by value in its close record and borrow it only while executing use. Do not store lexical file references, `&mut AsyncContext`, closures, futures, raw handles, or scope references inside records. Nested lexical scopes are supported; explicit scope values, manual close, closed-scope registration, `fork`, parallel finalization, Exit-aware cleanup, and resource Layers are separate capabilities.

This is implementable with Rust std and the already selected Tokio substrate. It is a substantial compiler extension, not a change confined to the runtime scaffold.

## Corrections to the earlier preparation

The earlier record's resolved section proposes runtime overflow/closed-scope refusal and a fixed bound of 16. **Do not implement those as execution errors.** `Effect.addFinalizer` has a `never` domain error channel; manufacturing Boolean failures, synthetic errors or interruption for capacity would change semantics. Failing close after an over-capacity registration can also lose cleanup for an acquired resource.

Use 16 as an initial **compiler admission ceiling**, not an upstream semantic limit. Derive actual storage capacity `N <= 16` per lexical scope instance. Reject an unknown or larger bound in `check`/planning before reference effects, filesystem acquisition or native execution start. Safe indexing may retain bounds checks/internal invariant assertions, but an assertion must not substitute for the capacity proof. No valid admitted execution reaches an overflow branch. Explain reports should expose capacity, its contributors, unknown multipliers, capture representations and refusal sites.

Closed-scope registration is excluded structurally: no public runtime scope value or close operation, no registration targeting a scope being finalized, and no escaping pending registration. Thus the subset need not substitute a runtime refusal for Effect's immediate-execution behavior on closed scopes. Explicit closed-scope behavior remains unimplemented, rather than an admitted divergence.

## Actual implementation and reusable pieces

- `packages/reffect/src/scoped-sequence.ts:8–85`: pending Register/Run steps are currently closed by rewriting registrations into nested `AcquireUseRelease` brackets. `scoped(Computation)` currently returns the computation unchanged. This cannot express registration within Match/repeat/recovery as ordinary effects; it is not a runtime finalizer registry.
- `packages/reffect/src/lower.ts:182–251,330–509`: lowering scopes map scalar binders and active file binders to helper inputs. Effect helper memoization is indexed by node, lexical lowering scope and error witness. Every effect helper inherits **all** active `fileInputs`, even if its body does not use them. Do not reuse that signature wholesale for delayed cleanup.
- `lower.ts:868–918`: FileScope owns one local File, awaits masked spawn_blocking open, executes borrowed use, drops the file explicitly, then awaits afterClose under mask. Reuse IO projection (`false`), acquisition strategy, borrowed size operation and mask/result restoration, but move release lifetime to the enclosing registration scope.
- `lower.ts:957–1043`: Repeat/Retry generate concrete loops; retry handles domain Fail only. CatchAll drops handled frame trails, but does not implement a resource-registry rollback. AcquireUseRelease/Ensuring retain body results through masked cleanup; pending cancellation turns successful completion into interruption and preserves an already failed result. Reuse that outcome policy and verify it for multi-record close.
- `packages/reffect/src/async-runtime.ts`: AsyncContext owns cancellation receiver/masking and optional log/frame state. Keep the registry outside this context; scopes are generated locals, passed to helpers only when required. Preserve independent source/frame/log reachability selection.
- `packages/reffect/src/file-resource.ts`, `file-model.ts`, and `effect-ir.ts:552–578`: symbolic ScopedFile is not an Expr; FileSize requires an active lexical binder. This is useful ownership groundwork, but current lexical validity at registration time does not prove a borrowed handle survives delayed close.
- `effect-ir.ts`: the computation union, substitution, channel checker, async reachability, ordinary reference interpreter, and frame-observing interpreter all require new-node handling. Current reference files already use official scoped/acquireRelease and injectable `ReferenceFiles`; reuse those adapters.
- `packages/reffect/src/flow.ts`: R.flow inlines by scalar binder substitution through `substituteComputation`; there is no runtime call node. New finalizer capture expressions must be substituted too; bound scope/resource identities must stay hygienic. Capacity is proved on the composed graph, with occurrence multiplicity, not the number of unique nodes.
- `packages/reffect/src/compiler.ts` and `provenance.ts`: reachability/capability and provenance traversals are exhaustive. New cleanup bodies must remain reachable for dependencies, type checking, origin/use ranges and support reporting even though execution is delayed.

The scoped-file tests already cover real lease closure and acquisition/use/cleanup cancellation. Existing conformance is reusable infrastructure, not evidence that the new registry compiles or preserves those behaviors.

## Narrow authoring surface and IR

Recommended public shape (proposed, not shipped):

1. `R.Effect.addFinalizer(() => cleanup)` becomes an ordinary Unit/Never computation that requires an enclosing lexical `R.Effect.scoped`. Keep the Exit-independent zero-argument callback restriction and existing spelling. It can then occur in FlatMap, Match, repeat and recovery; its callback constructs IR once at authoring, never a runtime native closure.
2. `R.Effect.scoped(self)` always creates an actual lexical scope node, even for ordinary Computation. Preserve the existing ScopedSequence authoring form by translating its steps to registration/sequencing nodes and wrapping once. Avoid two implementations of finalization. Add scoped requirement checking: function roots must discharge registrations; a requirement is not a domain error.
3. `R.Effect.acquireRelease(acquire, resource => cleanup)` initially accepts existing scalar computations only. It returns the scalar with the original acquisition error witness, requires Scope, masks acquire plus append atomically, and restricts cleanup to Unit/Never and Exit-independent. Do not expose `{ interruptible: true }` yet.
4. For the existing non-Expr file reference, prefer a specialized CPS adapter **`R.File.acquireRelease(path, use, afterClose?)`**: acquire and register an owned file in the enclosing scope, then call the build-time use callback with ScopedFile; the file remains open until scope close. This is deliberately a reffect-specific file adapter signature, not a claim to mirror a stock filesystem API. Document the lifetime difference from `R.File.scoped` prominently. Its scalar result joins use errors with the existing Boolean IO witness. It avoids widening ordinary scalar Expr/flatMap into general resource values. A normal `File.open` resource computation with resource-aware flatMap is a later, larger API choice.

The CPS use binder expires at the adapter's use-body boundary, while native ownership lasts until enclosing scope close. This permits runtime repeated file acquisition with scalar results without exposing runtime handle values, but cannot carry the file into a later sibling computation. That deliberate limitation is sufficient for the first real-resource registration workload.

Suggested immutable nodes:

- `Scoped { scopeBinder, body }`: provides a fresh lexical scope and drains on every admitted body outcome.
- `AddFinalizer { finalizer }`: Unit/Never; nearest open lexical scope is resolved during checking/planning. Free scalar binders become typed capture fields in the verified plan.
- `AcquireRelease { acquire, resourceBinder, release }`: scalar output/error follow acquire; successful acquire produces one release record. The release's resource binder and outer free scalar binders become owned fields.
- `FileAcquireRelease { path, fileBinder, use, afterClose }`: specialized owned File record; use is checked with a lexical borrow, afterClose without the owned file binder. Preserve existing path validation.

Use semantic references for new effects/requirements. Record target scope identity, capacity witness, variant/capture layout and cleanup safety in a verified scope plan, not unchecked serialized integer IDs or author-supplied bound claims. With nearest-scope registration, the author cannot target an ancestor scope from a child.

For this first slice, an implicit Scope requirement can be enforced by the graph checker, as file lexical requirements are today, without changing every `Computation<A,E>` generic. The API documentation must state that this is checked at compile/reference admission, not statically guaranteed by TypeScript. A third environment generic or a composable pending-scope type is more type-safe but much wider than the current ScopedSequence and needs a separate DX decision. Type tests still enforce cleanup channels and non-returnable handles; graph tests enforce discharged Scope requirements and escaped/reused IR.

## Static capacity: count executions, not definitions

Compute a conservative registration bound **per target scope instance**, with arithmetic saturating to `ceiling + 1` and an explicit unknown/unbounded result. A proof may overestimate and refuse a valid larger program; it must never underestimate.

- Registration contributes 1. FileAcquireRelease contributes 1 for possible successful open plus registrations in its use body; failed open contributes no record at runtime. Scalar AcquireRelease also includes registrations performed inside acquire, if admitted, plus its own successful append.
- Sequential composition adds bounds. Match uses the maximum branch bound, not their sum. Map contributes only its source; scalar expression evaluation registers nothing.
- CatchAll uses `bound(source) + bound(handler)` conservatively: source can register, fail, and then handler register in the **same scope**. Recovery does not discard earlier finalizers. Count Ensuring/lexical bracket release bodies that register while the enclosing scope is still open; this is distinct from registry close callbacks, which must not register into the closing scope.
- Repeat and Retry multiply by maximum attempts. `recurs(n)` and `{ times: n }` mean at most **n + 1 executions** in the current lowerer; when both constrain the loop, use `min(recurs, times) + 1`. Retry failure can follow successful registration on every attempt. Do not count only the eventual success, or infer rollback from recovered frames.
- Spaced/Exponential/Forever without a finite times bound are unbounded. If they can register into the containing scope, refuse. Cancellation is not a capacity proof. If their contribution to that scope is zero, they can remain admitted.
- `repeat(scoped(body))` creates and closes a fresh inner instance on each attempt: prove inner capacity once, with zero contribution to outer. `scoped(repeat(register))` accumulates and needs the multiplier. Nested scopes close inner-first, but are not independently escaping child objects.
- Shared computation nodes executed on multiple edges count multiple times. Memoize **summaries**, then add them per occurrence; a visited-node set is only suitable for capability collection. R.flow substitution must be included before final proof verification. Future named calls/recursion need explicit bound summaries or refusal.

First admission can use one numeric upper bound rather than a full success/failure path analysis. Diagnostics should identify whether refusal comes from repeated registration, recovery accumulation, nested contributors, an unbounded schedule or total >16. Do not replace the proof with a syntactic count of addFinalizer sites.

## Native representation and control flow

Generate one finite record enum per checked lexical scope layout, with variants for each cleanup/capture layout and an owned File variant. Initialize `[Option<FinalizerRecord>; N]` safely with `std::array::from_fn(|_| None)`, and maintain a private length. This stores runtime registration sequence; repeated executions of one site occupy separate slots. Plain scalars stay bool/u64/(). No generic runtime service map or new Cargo crate is necessary.

Each append is synchronous after capture copies. Successful acquisition and append occur under one saved mask, with no intervening cancellation check or await. A pending cancellation is observed after registration, before use; close still runs. Failed acquisition registers no release for that acquisition, while preserving records already registered by earlier operations. Native blocking-open task failures remain outside the existing supported defect profile; do not reinterpret task panic as Boolean IO failure.

For file use, move the File into its record, then obtain a temporary shared borrow of that slot's File. **Do not** retain this borrow while passing `&mut` of the same registry into arbitrary use helpers. The simplest bounded solution is compiler-directed split slices: the occupied prefix/file slot is borrowed read-only, while registrations in use operate on a disjoint suffix writer with an absolute base and a separate mutable length. Prove returned suffix occupancy and rejoin after use. Nested file acquisition splits again; reborrows end at each awaited helper boundary. Alternatively refuse registration while a file-use borrow is active in the initial implementation, but that is a material composition limitation and must be explicit. This borrow topology needs a rustc fixture before committing to the integrated implementation.

Ordinary helpers receive a short-lived `&mut ScopeStorage` (or suffix writer) in addition to a separate `&mut AsyncContext` only when their reachable code registers. Each call is awaited immediately; no record captures either reference. Do not put the registry in ctx: that makes file borrows and mutable ctx access overlap unnecessarily. Precise required-file helper inputs also remove unrelated lexical borrows.

At scope exit: retain body result; save mask; set uninterruptible; decrement length and `take()` the last record into a local; release the storage borrow; exhaustively match the owned record and directly await its concrete cleanup helper; continue until empty; restore mask and return the body outcome with the existing pending-cancellation policy. File arms explicitly drop the owned File **before** awaiting afterClose. Pop-before-await plus ownership makes exactly-once consumption straightforward. Records contain no futures, so different match arms need no boxed future unification.

The close helper must be a genuinely scope-free cleanup path: reject registration into the closing scope, escaping scope references, fallible/Exit-aware cleanup and unsupported captures. Keep cleanup helpers specialized to Never (or a verified masked Unit-returning lowering); never fill the enclosing Boolean/u64 error witness with a fake payload. If existing helper machinery returns `AsyncError<Infallible>`, exhaustively eliminate `Fail(never)` and treat masked interruption as an internal invariant violation, never as an invented domain failure. Stronger masked-cleanup lowering removes that impossible branch, but needs separate emission mode/memoization. Neither panic assertions nor Unit/Never alone prove termination; decide and document whether unbounded cleanup repetition is refused in this bounded slice.

## Captures, delayed lifetimes and log context

**Scalar captures:** collect free symbolic scalar parameters/binders of the cleanup graph, copy their values at registration and rebind cleanup helper parameters to record fields. Do not evaluate effectful cleanup early or snapshot filesystem metadata just to replace a file capture. Pure embedded expressions retain their semantics when evaluated later from immutable captured values. Unit may be elided physically; Never has no runtime capture.

**Files:** first profile rejects every free lexical File binder in delayed cleanup. In particular, registration inside `R.File.scoped` into an outer scope cannot capture that bracket's file, even though the current active-binder checker accepts FileSize there. Reject before execution, including reused graph nodes and R.flow-composed capture bodies. The specialized FileAcquireRelease record owns its own File; afterClose cannot inspect that closed handle. Capturing other registered-file slots by index could be safe with a proven release-dependency order, but branches/repetition/recovery complicate it; defer it rather than introduce self-referential records or raw pointers.

**Log context:** pinned addFinalizer/acquireRelease capture registration-time Effect Context. At registration, retain the admitted annotations and span labels/**original Instant start values**; cleanup must see that snapshot even after Annotate/Span wrappers have restored ctx. The request JSON is fixed and owned by this invocation, so it may remain in ctx without a per-record clone, provided mutation after registration stays unavailable. Swap/install the captured annotations/spans for each close arm, run authored cleanup-local wrappers normally, then restore the closer's state before the next record. Do not snapshot cancellation, interruptibility or failure storage from registration time.

For the first implementation, existing Vec snapshots are simpler but add per-registration allocations when logging scopes are nonempty. Prefer generated bounded annotation/span snapshot arrays if allocation-free record construction is a gate: derive maximum annotation keys and span depth from authored nesting, preserve overwrite order and span start values, and omit all snapshot fields when unreachable. This adds emission/context-installation work but no new AsyncContext fields. Measure both empty and nonempty snapshot paths; fixed registry storage alone cannot justify a zero-allocation claim. Logger/filter replacement and other dynamic Context services are not admitted by this snapshot design.

## Alternatives assessed

| Alternative                                                            | Decision                                                                                                                                                                                                    |
| ---------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Existing nested bracket specialization                                 | Preserve as an optimization only when proven equivalent; alone it cannot express accumulated registrations in runtime branch/retry order.                                                                   |
| Generated enum + owned fixed records + concrete match                  | **Chosen**: explicit captures/ownership, bounded runtime sequence, safe Rust, no dynamic dispatch or stored futures. Largest variant determines every slot's size; measure rather than promise compactness. |
| Vec of generated enum records                                          | Semantically plausible without a fixed semantic bound, but entails allocation/growth and does not satisfy this static-capacity profile. Consider later if the 16 ceiling proves workload-hostile.           |
| Boxed FnOnce/trait-object future finalizers                            | Flexible but defeats the requested representation and complicates heterogeneous async lifetime/context borrowing; rejected for this slice.                                                                  |
| RAII-only File Drop / detached cleanup                                 | Drop is useful for the explicit owned-file close arm; alone it cannot await arbitrary afterClose or preserve observed completion/order.                                                                     |
| Stored `&File`, raw pointer, Arc/try_clone                             | Borrow escapes/self-reference or changed ownership/close timing; rejected. A proven dependency-indexed resource registry would be a different, larger profile.                                              |
| Separate typed pools with compact order tags                           | Can reduce largest-variant array waste, but adds capacity proofs per pool and more slot bookkeeping. Revisit after measurements.                                                                            |
| Full Scope service with make/fork/manual close and closed registration | Requires further Exit/Cause/lifetime/service semantics; not needed for the first lexical sequential registration workload.                                                                                  |

## Acceptance before admission

Compare independently authored official Effect RC.118, reference and native debug/release, both Bounded/None frames and representative Full/None artifacts:

1. Runtime branch registration order, repeated same-site captures, reverse awaited close, empty scope, nested inner-before-outer close; skipped registration after failure.
2. Scope around repeat/retry versus scope inside each attempt; n+1 counting; accumulated failed-attempt finalizers and recovery handler registrations; shared-node/multiple-edge and R.flow substitution parity.
3. Exactly 16 admitted and 17 refused before IO; unbounded registration refused; unbounded loop with zero outer contribution admitted; unknown forged proofs cannot bypass staged check/plan/verify/lower/reference entry points. Refusal leaves acquisition/log side effects absent.
4. Successful/domain-failed/interrupted body; pre-entry cancellation; cancellation during acquisition, immediately after acquisition before use, during use and during delayed close. Existing records survive failed acquisition. Pending cancellation does not skip any registered cleanup; already failed body stays failed under the established policy.
5. Real file retained beyond CPS use until scope close, two/repeated successful acquisitions close in reverse order, failed open has no corresponding close, actual handle invalid before afterClose. Include registration during borrowed use to exercise split writer topology; absence of use-after-close/try_clone/raw handles is verified.
6. Outer-scope delayed captures of short-lived lexical files refused; cleanup reference to owned file after drop refused; forged/reused/cross-scope IR refused. Scalar captures from FlatMap/recovery survive correctly.
7. Registration under annotations/spans followed by wrapper exit and differently annotated closer: cleanup sees original captured values/span starts, local cleanup wrappers shadow/restore, successive finalizers and requests remain isolated. No failure-trail capture or mask snapshot contaminates close.
8. Rustc checks the core concrete enum/array/pop-await and split-file-borrow shapes without unsafe, boxed closures/futures or fake errors. Registry ownership/private helper signatures do not permit external capacity corruption. Reachable-only Tokio/files/log dependencies and plain native scalar layout remain intact.
9. Measure `size_of` registry/record and representative **polled and unpolled** future sizes for 0/1/16 registrations, variant count, scalar capture width, nested scopes and files. Separate registry construction, snapshot, file/threadpool, logging and HTTP allocations. Track generated source/compile growth; no universal zero-allocation/future-layout claim.
10. Existing heartbeat, scoped-files, schedule, recovery, flow and async RPC/socket conformance remain passing. Add a real-socket registered-file disconnect case before claiming transport-integrated registry lifetime support.
