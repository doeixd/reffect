## Verified semantics

### Registration and masking are separate contracts

1. **`Scope.addFinalizer` does not introduce a mask or capture context.** It stores an effect. `addFinalizerExit` uses `suspend`, checks state and performs a synchronous state mutation for open scopes. Its closed path executes the supplied effect immediately in the caller's interruptibility/context. The mutation is not an awaited acquisition; do not invent a blanket masked registration phase.
2. **`Effect.addFinalizer` captures context at execution/registration time**, not builder time. It obtains the active Scope and wraps the finalizer in `provideContext(..., capturedContext)`. It does not itself mask the closed-scope immediate execution path.
3. **`Effect.acquireRelease` captures context before acquisition and masks acquisition plus successful registration by default.** It resolves Scope, acquires, then taps successful acquisition to install release. Failure installs nothing. A cancellation request while masked is pending: acquisition can still return a resource, release is registered, restoration delivers interruption and scoped closure releases it before completion. “Aborted acquisition registers nothing” is correct only when acquisition actually exits unsuccessfully; a cancellation request alone is not that exit.
4. **`{ interruptible: true }` restores the caller's previous interruptibility only for acquisition.** It does not force an already masked caller to be interruptible; registration remains in the surrounding mask. A canceled interruptible acquisition that never returns installs no release, so partial-acquisition cleanup must belong to the acquisition adapter itself. Defer this option until a real adapter proves it, or implement exactly this contract.
5. **Close masks draining by default**, and scope state becomes Closed before awaiting any cleanup. Explicit `Effect.interruptible` inside a finalizer can restore interruption. The first subset can refuse explicit interruptibility in cleanup at compile time; it must not claim the full upstream override surface.

### Closure, children and context

- Sequential finalizers execute in reverse **runtime registration order**, not declaration/site order. Failed/skipped acquisitions and untaken branches do not register entries. Finalizers are claimed once before execution.
- First close stores its Exit. **Repeated close returns immediately**, does not rerun finalizers and does not replace the stored Exit. A second close while the first is suspended is not a barrier waiting for the first drain. “Closing waits for completion” applies to the first close's own cleanup effect, not every call on the same object.
- Closed-scope registration immediately executes and awaits the newly supplied finalizer with the original closing Exit. This also applies during another finalizer's suspension, because the scope is already Closed. Registering a finalizer from a finalizer on that same scope runs it inline; there is no second delayed drain.
- `Scope.fork(parent)` registers child close as a parent finalizer at that moment. Closing the child first removes that entry from the parent's open registry; parent closure cannot rerun it. Closing the parent first gives its Exit to still-open children. Forking an already closed parent creates an already closed child holding the same Exit.
- A child-close entry participates in ordinary parent LIFO order. Parent finalizers registered **after child creation** execute before the child's close entry; “all children always close before all parent finalizers” is incorrect. Nested lexical `Effect.scoped` regions are fresh scopes closed by structured unwinding, not automatically `Scope.fork` parent-child objects.
- `Effect.scoped` restores the previous context before closing. High-level finalizer capture makes registration-local services and log annotations/spans available later. Low-level `Scope.addFinalizer` does not supply this capture. Native deferred cleanup must not accidentally read only close-time annotations or borrow storage whose lexical lifetime already ended.
- `Never` describes the **typed error channel**, not impossibility of interruption/defects. Upstream sequential close attempts all finalizers and combines their failing exits; do not stop the drain after an unexpected cleanup failure. The initial admitted cleanup language can exclude defects, domain failures and explicit interruptibility, but that is a representation boundary, not general Effect Cause parity.

## Corrections needed in the existing registration decision

These are recommendations to its owner; that record is not edited here.

- **SCOPER-001 / resolved bound: overflow “fails the close path deterministically”.** A normal runtime capacity failure introduces an observable failure absent from RC.118; treating it as a domain error also violates the Never cleanup/registration channel. Making it a defect preserves the type spelling but still changes semantics. Prove capacity before execution and refuse unbounded/over-budget programs in the compiler, or choose a preserving growable representation. Never turn an admitted program's 17th registration into failure or skip its cleanup.
- **`maxScopeFinalizers = 16` “covers realistic request/connection cleanup”.** No workload/cost evidence supports 16. Bound live registration **executions**, including loops/retries and child entries, rather than distinct reachable IR sites. One site in `forever` registers unboundedly unless each iteration closes a fresh scope. A finite capacity budget may be configurable compiler policy; generate a proven per-scope capacity and explain the proof/refusal.
- **SCOPER-004 / resolved closed registration: runtime refusal.** Direct divergence from immediate execution. Either implement it when explicit scopes or finalizer-side registrations are exposed, or make those programs statically unrepresentable. A lexical surface can postpone manual close/escaping scopes without inventing a runtime closed-registration error.
- **SCOPER-004: registration is masked, failed/aborted acquisition registers nothing.** Distinguish bare registration from masked acquire-and-register. Cancellation requested during default acquisition may lead to successful acquisition and a mandatory release; see semantics above.
- **SCOPER-005 / first workload: only unit callbacks and real resource deferred.** Contradicts `PLAN.md:89`'s real resource gate for the new profile. Existing lexical File proves one bracket, not registration ownership. Admit the same read-only file lease through the new registration lifetime and test two conditional acquisitions, failure after the first, and cancellation during the second acquisition. A new resource family is unnecessary.
- **No new AsyncContext fields as an acceptance mandate.** An implementation constraint is not semantic evidence. Scope can be a generated local argument rather than an execution-context field, but registration-context snapshots still need a proven representation/lifetime. Measure costs before asserting the unchanged-context target is attainable.

## Minimal semantics-preserving statically representable surface

**Recommend a sequential lexical Scope requirement with actual registration nodes and per-program proven storage, plus the existing read-only file as the first real registered resource.** Keep build-time callback construction, ordinary structured IR branching and existing owned cancellation context. Reuse the official reference APIs; generated native code needs a small semantic adapter, not a second JS Scope interpreter.

- Keep v4 names/shapes: `R.Effect.addFinalizer(() => cleanup)` (Exit-independent callback is an intentional narrow instance of `exit => cleanup`), `R.Effect.acquireRelease(acquire, resource => release)` (second Exit parameter omitted in the narrow callback), and `R.Effect.scoped(effect)`. Preserve `andThen`, `flatMap`, Match and pipeability. Initially support default acquisition or `{ interruptible: false }`; refuse true unless its adapter cleanup obligations are validated.
- Registration results must compose as scoped computations, including conditional branches and scalar binders, rather than remain a separate straight-line sequence that cannot flow through ordinary combinators. Track an unhandled Scope requirement in authoring types or a comparably strong checked pending wrapper and reject it at `R.fn`/compile/reference boundaries. `scoped` discharges only its own lexical Scope requirement. Do not rely on callback identity or display names for scope selection.
- Keep output/error witnesses and resource references distinct: scalar acquisition returns its existing symbolic Expr; real File acquisition yields a symbolic borrowed resource reference with known plain native representation, never a serializable scalar/descriptor. The exact resource-computation carrier needs a separate design choice because current `flatMap` binds Expr values, whereas `ScopedFile` is not an Expr. Do not conceal that mismatch with casts.
- Start with Unit/Never, Exit-independent cleanup; preserve the body's supported success/typed-failure/interruption outcome internally. No public general Exit/Cause witness is necessary until callbacks inspect it, but runtime early close would require an explicit supported Exit representation.
- Derive maximum simultaneously retained registrations per lexical scope: sequence sums registrations; alternatives take the safe maximum; finite repetition/retry accounts for execution multiplicity; nested fresh scopes own separate capacities. Refuse same-scope registration in unbounded loops/recursion or any graph without a sound bound. A repeat that closes its own scope each iteration remains admissible. Unique IR site count is not the bound.
- Generate a closed set of typed finalizer entry variants/captured values and a LIFO order representation only where runtime selection needs it. Straight-line cases can still specialize to control flow. Prove moves/borrows and finalizer capture lifetimes; keep scoped handles from escaping through results, errors, shared bodies or deferred outer-scope cleanup. Context capture must retain registration-local logging/services after authoring lexical context unwinds.
- Initially omit user-visible `Scope.make/provide/close/fork` and escaping scope values. That is a narrower API boundary, not changed admitted behavior. If closed registration, explicit child scopes or manual/repeated close are admitted now, mirror `R.Scope.addFinalizer(scope, cleanup)` versus `R.Scope.addFinalizerExit(scope, callback)` and implement the exact state machine above; do not alias low-level and high-level context behavior.

Alternatives: current bracket specialization remains useful but cannot generally defer release to an outer scope across a nested recovery/context boundary. A growable concrete enum vector preserves unbounded registration count but changes allocation costs and needs a workload decision. A fixed-capacity array is reasonable only after a static proof; arbitrary runtime overflow and runtime closed-scope refusals are rejected. General fibers, parallel finalization, resource Layers and rich cleanup Cause composition remain separate gates.

## Meaningful oracle and admission tests

Compare independently authored official RC.118 programs with reference IR and native **debug/release × both failure-frame policies**. Observe value/domain failure/interruption, ordered lifecycle events, actual lease closure, log context and completion barriers. Use Deferred/gates or explicit “entered” signals; timers alone are not sufficient to locate an interruption phase.

1. **Dynamic count/order:** input-dependent branches register zero/one/two distinct resources; finite repeat registers the same site multiple times; body failure skips later registrations. Assert exact reverse runtime order and count, not just the final log message.
2. **Acquisition cancellation:** gate acquisition before it returns. Default mask waits, registers and releases success without entering use after pending interruption; acquisition failure releases no new resource but closes prior resources. Pre-entry cancellation creates nothing. If true is supported, canceled interruptible acquisition returns no resource and its adapter cleans partial work itself.
3. **Use/close cancellation:** interrupt suspended use and await all cleanup; interrupt first suspended close and prove it remains incomplete until cleanup finishes. Failure plus cancellation during cleanup must be compared against the oracle rather than simplified to a new generic error.
4. **Captured context:** register under temporary service/log annotation/span values, leave that lexical provider, then close under different values. High-level finalizers observe registration values; low-level explicit Scope finalizers observe close-time context. Include nested capture/restoration and request isolation after suspension.
5. **Nested lifetimes:** inner lexical scope closes before surrounding work resumes; outer handles remain usable while inner cleanup runs. Resource release occurs at the owning scope boundary even if a typed error is recovered inside that scope. This last case detects an incorrect rewrite to release-at-acquisition-bracket/recovery-boundary.
6. **Closed/repeated/child semantics if admitted:** second close retains first Exit and does not rerun; while first close is gated, second returns immediately and late finalizer runs before the old drain completes. Test finalizer-side registration, child early detachment, parent-first propagation, parent finalizers on both sides of the child entry, and child fork after parent close.
7. **Real ownership:** two read-only files via registration, actual handle unusable after release, no leaked handle on failure/cancellation, borrowed outer-file access while inner scope is active, capture/escape refusals. Reuse `ReferenceFiles` injection and descriptor checks; log/token cleanup alone cannot pass this gate.
8. **Static budget:** exactly proven capacity and a program requiring more than 16 both run successfully if admitted; configured budget rejection occurs before native execution and reference invocation. Refuse unbounded same-scope registration, account for retries, and accept repeated fresh per-iteration scopes. Type checks reject unclosed Scope requirements and fallible/unsupported Exit-aware cleanup at the mistake.
9. **Costs:** measure generated scope and concrete future sizes, retained cleanup captures and zero-capacity path; report context/future construction allocations separately from open/poll/logging allocations. No unsupported zero-allocation claim follows from avoiding boxed futures.

## Unresolved design questions for the parent

1. How will scoped computation requirements compose through current `Computation<A,E>`, Fn construction and resource-returning symbolic bindings without user casts? The present resource carrier cannot simply be inserted into Expr-only flatMap.
2. Does the immediate slice expose explicit scopes/close/fork, or only lexical `Effect.scoped`? If lexical only, which closed-scope/finalizer-reentrancy programs are statically refused, and how will the stated closed-scope frontier gate be tracked honestly?
3. Which loop/retry cases can the checker bound soundly, and what measured compiler-policy budget is appropriate? No evidence currently selects 16 or justifies an unconditional native storage size.
4. Which captured context components are admitted, and can registration-local log spans/services outlive their lexical provider without borrowing dead data? Captured Scope also affects cleanup that attempts further registration.
5. Can the same read-only File adapter become an acquired resource under the new registry while preserving close-error projection, ownership and cancellation behavior? The real-resource requirement should be demonstrated through registration, not discharged by the older FileScope node alone.
6. Is `{ interruptible: true }` deferred or required by the chosen real workload? Default masked acquisition is sufficient for an initial preserving slice; interruptible partial acquisitions need adapter-specific cleanup evidence.
7. What unsupported defects/explicit interruptibility can reach cleanup through provided adapters? Unit/Never is not sufficient proof that native draining can safely stop on the first unexpected failure.
