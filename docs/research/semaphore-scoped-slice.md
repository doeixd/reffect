# Bounded scoped Semaphore preparation

Prepared 2026-10-06 against installed `effect@4.0.0` and [the pinned primary Semaphore source](https://unpkg.com/effect@4.0.0/src/Semaphore.ts), fetched today. Re-read [coordination decisions](coordination-modules.md), the public Deferred records, lexical resource checks, structured task ownership and generated turn adapters. This refresh supersedes rc.118 observations only where stable source or executable evidence differs.

## Chosen scope and decisions

- SEM-001: first introduce private lexical make/withPermit/withPermits builders and official-Effect interpretation. Capacity is positive safe integral configuration, acquisition count exactly one. Constructor allocation becomes a lexical scope when directly flatMapped, following Ref/Deferred ownership. Handles cannot escape function channels, enter arbitrary expressions, or outlive their owner. General manual take/release/resize, non-waiting Option results and multi-permit contention remain deferred.
- SEM-002: mirror upstream names and curried wrapper behavior; symbolic handles require an explicit handle argument in the IR namespace because upstream's instance methods cannot run on symbolic values. Record that adaptation before any public export. Do not expose native admission merely because interpretation succeeds.
- SEM-003: release is scheduled, unlike Deferred's synchronous callback continuation turns. Effect's releaseUnsafe immediately restores free count, then schedules the registration-ordered waiter scan at dispatcher priority zero. The releasing task can execute further synchronous work or reacquire before the scan. Resumed acquisition rechecks free capacity. An awaited Deferred-style broadcast or permanent FIFO reservation changes observable behavior. [Tokio Semaphore](https://docs.rs/tokio/1.53.1/tokio/sync/struct.Semaphore.html) promises FIFO; it is a candidate only for a separately proven restricted profile.
- SEM-004: prove the native scheduled adapter independently before integrating generated lowering or owned execution budgets. Target capacity 1..3, one-permit operations and bounded All2/3, scalar/Never, with inline waiter slots and cancellation removal. A raw adapter may register wakers and defer scanning to a dispatcher phase; generic wake-all is not itself proof of registration-order semantics. Existing Deferred profiles must refuse mixed Semaphore nodes rather than count unknown evaluator steps as free.
- SEM-005: acquisition bookkeeping and release registration are masked atomically. Waiting/body run at restored interruptibility, cancellation unlinks queued waiters, interrupted granted bodies await their finalizers before releasing exactly once. Parent masks must survive nested permit wrappers. Count overflow, invalid capacity and escaped resource uses require structured refusal.

## Validation and next admission gates

Reference fixtures compare logs/results with directly authored official Semaphore programs: overlapping one-permit users, synchronous reacquisition before queued wake, cancellation while queued, cancellation while holding, async finalizer before reuse, zero-start pre-interruption and fresh owners across executions. Use barriers and controlled start/register/cancel observations; elapsed sleeps alone do not prove ordering. Test data-first/data-last typing and invalid-number/handle escape boundaries without casts in supported examples.

A private native adapter needs deterministic transition/dispatcher probes for the same cases before public compiler admission. Then prove operation receipts/owned context, bounded waiter/owner topology, interrupted frames, structural/code/native layout and allocation budgets. Until those gates close, ordinary compiler planning must emit an explicit Semaphore integration refusal. These are staged delivery gates, not user approval requirements. Follow [native research](semaphore-native.md) and [IR preparation](semaphore-ir.md) for implementation evidence.

## Delivered initial evidence

Private `SemaphoreIR` constructs lexical scopes and curried one-permit wrappers; plain/framed interpretation delegates to official Effect. Reference conformance uses a controlled TestClock and three guarded children to verify scheduled reuse after asynchronous cleanup, including the releasing continuation. Parent interruption cancels queued children without entering their bodies and awaits the held permit's cleanup. Separate IR tests verify typed failure/recovered reuse, substitution, fresh owners, invalid arguments and escape checks. These cases do not establish a general interrupted-frame contract or individual IR waiter cancellation.

Scope checking conservatively refuses every Semaphore acquisition in registered cleanup, including a newly created local owner. Immediate Ensuring cleanup and awaited guarded-body finalizers are distinct from delayed registered cleanup. Narrowing that refusal requires its own lifetime proof (SEM-006).

The private raw adapter matches 60 exact official traces in debug/release for barging, independent queued cancellation and cooperative holder cancellation. It uses Arc/Mutex and spawned scans; only the tested traces are proved. The separate inline scan prototype now matches 140 controlled debug/release traces, with zero quiet allocations and a wake-all ordering counterexample ([native evidence](semaphore-native.md#delivered-prototype-and-counterexample)). Generated dispatcher integration, grant-to-cleanup handoff, owned context/budgets and generated layout/frame cost gates remain required before public/native admission.
