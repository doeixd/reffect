# Source-map design research

Checked 2026-10-01 before planning the source-map extension. This records design evidence, not implemented support. The companion [design](../source-maps.md) supplies the contracts and delivery gates.

## Existing boundaries

Reviewed PLAN, PROGRESS, AGENTS, observability, compiler API, conformance, migration and milestone documents alongside `packages/reffect/src/lower.ts`, compiler artifacts and Cargo writing/building. The current compiler consumes immutable authoring/Entity IR, emits new Rust through templates and shared helpers, and reports IR paths. Artifact writing accepts three fixed files; no source-map producer, mapped diagnostic or logical native stack is implemented. Effect RC.118 reference execution and the scalar native stdout protocol must remain intact.

The observability design already separates semantic identity, source origin, execution context and exported records. Source mapping must preserve that separation, definition versus use edges, and transform ancestry. It must not expand the supported TypeScript syntax or execute builder callbacks a second time.

Observed npm registry releases: MagicString `1.4.2`, gen-mapping `0.3.13`, trace-mapping `0.3.31`, remapping `2.3.5`; workspace MagicString remains transitive `0.30.21`, TypeScript `7.0.2`, Node `24.19.0`. These observations do not pin dependencies or establish compatibility. Upstream MagicString master describes experimental range mappings; exclude them from the initial contract. A real adapter must declare/pin tested direct dependencies rather than relying on transitive availability. Documentation work adds none.

## Alternatives and decision

1. Use only captured JS stacks: inexpensive bootstrap, but engine formatting, bundling, helper frames and build-time callbacks make exact locations unreliable. Keep explicitly marked best-effort fallback.
2. Use MagicString for everything: appropriate for surgical JS/TS edits, inappropriate for semantic IR-to-Rust synthesis. Whole-file overwrite does not discover correspondence.
3. Emit only a v3 Rust-to-TS map: interoperable point lookup, but cannot represent many origins, shared invocation edges, range precision or logical frames. Offer an optional projection, never make it authoritative.
4. Compiler-owned provenance/range records plus standard maps at JS boundaries and native symbols at machine boundaries: chosen. Preserve exact byte spans when known, explicit unknowns when not, and versioned artifact/build identities. An emitter records mapping while writing final Rust, without reverse-engineering templates afterward.

Manual immutable source annotations and a structured Rust writer are the first useful slice. An optional AST-aware metadata plugin can follow without admitting arbitrary TS control flow. AST parser/binding resolver and exact public types remain implementation decisions; assess Oxc/Babel or a supported TS API against the pinned toolchain, not regex or undocumented TypeScript 7 internals.

## Acceptance and unresolved choices

Require independent location fixtures with CRLF, astral characters and unmapped gaps; composed multi-stage JS maps; shared helper definitions versus executed call sites; rustc JSON type-error mapping; stale/missing maps; malformed input and bounded resolution; byte-identical deterministic artifacts; production builds without embedded source or automatic network fetching. Confirm callback counts, semantic identities and native stdout remain unchanged. Native address tests require actual matching platform debug artifacts; logical failure sites remain available without them.

Set exact schema/public API and ID algorithms, parser/host integration and Cargo message compatibility during implementation. Clarify metadata granularity/overhead with real emitted workloads. Do not promise perfect inverse mapping of Rust fixes, identical IDs across arbitrary source edits, or async stack reconstruction from native symbols. Detailed sequencing and limits are in the companion design.

## Foundation implementation preparation — 2026-10-01

Rechecked current source, installed Effect RC.118 Schema/Effect/process APIs and the official rustc/Cargo JSON specifications before implementation. No Effect skill is installed in either available skill catalog; pinned source remains the API authority. Existing source-map research remains applicable; automatic stack capture, AST/MagicString transforms, standard-map projection, native symbols and runtime logical frames are separate follow-ups.

Selected first contract: synchronous `Source.file(path, text)` snapshots and explicit UTF-16 half-open `Source.site` ranges; pipeable `Source.at`, `Source.named` and `Source.use` on Expr/Fn/Computation/EffectFn. Annotation copies retain the same semantic node/binder and execute no builder callback. Definition metadata and use metadata stay separate. A graph collector records bounded unique-node/edge provenance, including shared parents, without enumerating all DAG paths. Existing identity normalization/optimization keeps this graph unchanged; lower/emit records its origins rather than inventing rewrite evidence.

Emit through a UTF-8-counting writer with explicit mapped semantic fragments and unmapped scaffolding, retaining shared helper generation. Produce schema-version-1 `reffect.sources.json` and a build manifest with SHA-256 digests using platform Web Crypto through typed Effect adapters. Authored snapshots stay in memory; artifacts omit source contents by default. Resolve generated ranges only against matching file bytes and return the entire explicit authored range, not fabricated character-level correspondence. Name-only/ancestor attribution must report reduced precision.

Extend GeneratedFiles with an optional auxiliary-file dictionary so existing Foldkit consumers remain compatible; validate all relative output paths before writing. Cargo build uses its JSON mode and preserves envelopes/raw diagnostics/stdout/stderr; generated executable modes remain unchanged. Load optional provenance artifacts through scoped filesystem services, validate version/range/reference bounds, and degrade explicitly on absent/malformed/stale maps. Native compiler errors remain Cargo/backend errors with authored context, not typed domain failures or automatic TS fixes.

Acceptance: callback count and generic inference, frozen annotation copies and unchanged node/binder identity, both branches/repeated/shared DAGs, independently specified Unicode/CRLF positions and byte ranges, generated gaps and range boundaries, determinism/privacy, invalid paths/sites/maps and digest mismatch, real rustc type-error spans with raw/related diagnostics, and all existing native/reference/Foldkit checks. Imported Foldkit exact-site annotations and runtime frame protocols are outside this builder-focused slice; their existing compilation/writing must still pass.

Implementation review also checked [Node 24.19 Web Crypto digest](https://nodejs.org/download/release/v24.19.0/docs/api/webcrypto.html#subtledigestalgorithm-data). The adapter uses SHA-256 over UTF-8 bytes and typed Effect failures, without an additional package or installed global provider. Wire occurrences use parent IDs and compact edges; compiler-only snapshots retain full paths. Review added occurrence-specific alias context, separate definition/use attribution, immutable lowered snapshots, canonical map/manifest identity checks and revision-specific source IDs. Native symbol and JS-map adapters remain deferred.
