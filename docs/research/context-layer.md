# Static scalar Context/Layer profile

Checked 2026-10-02 against installed Effect 4.0.0-rc.118 and its upstream [Context source](https://github.com/Effect-TS/effect/blob/effect%404.0.0-rc.118/packages/effect/src/Context.ts), [Layer source](https://github.com/Effect-TS/effect/blob/effect%404.0.0-rc.118/packages/effect/src/Layer.ts). Preparation follows PLAN milestone 3B and the runtime-lowering/metadata constraints: plain native scalars, reachable runtime machinery, observable sharing rather than merely erasing a graph. Upstream sources were fetched before implementation; installed signatures are the execution authority.

## Decisions

- **CTX-001 — accepted: lexical scalar service wiring.** Service tags pair a stable literal ID with an IRType witness. Context contains symbolic Expr values and exists only while building IR; get/add/merge are immutable authoring operations. Acquisitions become existing FlatMap binders, with no native context map or metadata wrapper. Alternative: dynamic service requirements/new IR nodes. Consequence: no implicit Effect service lookup, arbitrary JS service objects or registry selection. Revisit with the first service-method/request-injection workload.
- **CTX-002 — accepted: ID plus witness compatibility.** Effect Context uses string keys; duplicate keys share a slot. Our matching tags use the same ID and exact semantic witness; reusing an ID with an incompatible witness is an authoring error. Context get type-checks admitted tag IDs and values and verifies witness compatibility at runtime. Alternative: object-only tag identity diverges from upstream; global interning retains build metadata. Revisit if separately compiled service identities need a serialized ABI.
- **CTX-003 — accepted: per-provide Layer object memoization.** Each provide constructs a fresh memo table while staging one lexical graph; repeated acquisition occurrences reference the same bound Expr and execute once per runtime invocation. fresh starts an independent memo table on every occurrence, including repeated uses of the same fresh wrapper, matching pinned Layer.fresh. Alternative: global singleton memoization leaks request ownership. Consequence: no runtime sharing across separate invocations/provide calls. Revisit with long-lived resource Layers.
- **CTX-004 — accepted: explicit sequential composition.** Effect Layer.merge builds concurrently. This profile exposes sequence, whose oracle is two sequential buildWithMemoMap calls sharing a memo map/scope, followed by Context.merge (right wins). It does not alias effectful sequential execution to upstream merge. merge is admitted only for literal/pure providers where execution ordering has no observations. Alternative: add general concurrency machinery now. Consequence: effectful merge is refused; sleep/log acquisitions are supported through sequence. Revisit after fork/join semantics.
- **CTX-005 — accepted: non-failing, resource-free acquisition only.** Layer.effect accepts an existing Computation<A, never>; supported scalar outputs are checked against the tag witness. This proves acquisition count/log order/suspension, but never exports Scope-owned handles. Alternative: Layer.scoped before resource registration exists. Consequence: no fallible acquisition, release hooks, acquisition masking, general resource layers or automatic resource capture. Revisit after Scope ownership/refusal gates pass; resource finalizers must enclose the consuming body, not just the acquisition.

## Validation gates

Compare duplicate sharing, fresh occurrences, sequential ordering, override, unused acquisition and separate invocations with official Layer.buildWithMemoMap/Context.merge, then native debug/release. Verify missing/wrong service and wrong acquisition types at TypeScript/authoring boundaries. Generated code must contain ordinary scalar binders and no dynamic service map; disabled source/frame policies compose through the existing compiler.

## Limits

This is a static lexical authoring profile, not general Effect Context requirements or a complete service implementation registry. Callbacks execute at build time and receive symbolic values. The reference for the expanded IR uses official Effect; independent official Layer scenarios verify the expansion's sharing contract. Native acquisition inputs remain ordinary function arguments owned by each invocation. Scope-dependent Layer support is deferred explicitly.

## Implementation and observed evidence

Implemented `R.Context.service/empty` plus immutable lexical Context.add/get/merge and `R.Layer.succeed/effect/sequence/merge/fresh/provide`. Private erased type declarations retain precise Layer service inference without creating runtime fields. Context.merge clones its map once at build time. Reused compatible ID/witness tags address the same slot; incompatible witness collisions fail before lowering.

Focused `vp test packages/reffect/tests/context-layer.test.ts` passes 2 tests (79.54s total, 73.73s test execution): pinned official sharing/freshness/override/unused-acquisition scenarios and native debug/release under both frame policies. A prior parallel run reached the original 120s budget while competing with other fresh Tokio builds; the four-build harness now has a bounded 240s budget. Native assertions were unchanged. Own-file Oxlint passes; strict package TypeScript passes after shared concurrent changes stabilized. The final shared suite also checks the pure-provider profile omits Tokio and any AsyncContext; generated native values remain scalar binders, without a service lookup map or boxed helper futures.

No dynamic Context requirements, fallible/resource Layer acquisition, concurrent effectful merge or cross-invocation Layer cache is admitted by this work. No new native runtime or Cargo dependency was introduced by Context/Layer itself.
