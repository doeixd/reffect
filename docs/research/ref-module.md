## Official behavior and the admitted workload

Official `Ref.make(value)` allocates a fresh reference **when its effect executes**. Re-executing the same effect creates another reference. `get` reads the current value; `set` writes and returns void. `update` applies a synchronous transformation; `modify` atomically computes `[result, newValue]`, writes the latter and returns the former. Pinned implementations execute these operations through `Effect.sync`. The Ref handle is shared: repeated operations on the same reference observe prior writes, and copying the handle does not copy its stored state.

The implemented native subset preserves that behavior for **lexical, sequential, nonescaping Ref cells**, initially storing Bool/u64/Unit. It is a scoped representability restriction, not an alternative State API. It must continue to look like this, with normal symbolic builder callbacks:

```ts
R.Effect.flatMap(R.Ref.make(R.U64.literal(0n)), (counter) =>
  R.Effect.andThen(
    R.Ref.update(counter, (n) => R.U64.add(n, R.U64.literal(1n))),
    R.Ref.get(counter),
  ),
);
```

This spelling is implemented. `R.Ref.make` returns a checked computation whose success witness is an internal Ref-handle type; `counter` is the symbolic handle supplied by ordinary `R.Effect.flatMap`. Reusing `counter` in sequential get/set/update/modify operations denotes one cell. A sleep between operations does not duplicate state. A handler invoked twice owns two cells. No author casts or runtime TypeScript mutable cell are required.

For `modify`, preserve the upstream argument/result order: the builder receives a symbolic current value and returns a readonly TypeScript pair `[resultExpression, newValueExpression]`. That pair constructs one checked node; it is not a native tuple value and need not introduce a runtime Tuple module. Evaluate result and new-value expressions from the same old snapshot, then commit one mutation. Only pure admitted expressions are allowed in this callback; effectful updates belong to future SynchronizedRef support.

## Representation alternatives

| Approach                                                | Observable semantics and cost                                                                                                                                                                                                                                         | Choice                                                                            |
| ------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------- |
| Generated owned local slot, checked lexical identity    | Native `T` state lives in its owner's stack frame or suspended concrete future. Sequential aliases resolve to the same slot; no Ref allocation or synchronization. Requires escape/region analysis and helper borrowing.                                              | Preferred for the admitted subset.                                                |
| Monomorphized state structure passed to helpers         | A generated structure groups known typed slots; `&mut` access remains exclusive. Useful if repeated/nested helpers make individual arguments unwieldy. Structure lifetime must remain allocation-region owned, never a global context.                                | Valid later representation if measured code/future growth justifies it.           |
| `Rc<RefCell<T>>`                                        | Heap allocation, dynamic borrow failures, non-Send state; allows aliasing but adds behavior and target constraints absent from checked sequential ownership.                                                                                                          | Refused as the default. Could be an explicit future single-thread shared profile. |
| `Arc<Mutex<T>>` / atomics                               | Heap/shared ownership and lock/atomic costs; async mutex can suspend and changes synchronous-operation obligations. Mutex poisoning/runtime lock policy and fairness are not Effect semantics automatically. Atomics cover only carefully admitted values/operations. | Reserve for proven cross-task/request aliasing, with a semantic adapter.          |
| Authoring-time JS cell or rewritten pure state argument | Definition-time mutation yields wrong repeated-execution behavior; replacing Ref with an unrelated State API loses sharing and migration fidelity.                                                                                                                    | Reject.                                                                           |

A synchronous Ref operation must not poll, suspend or be interrupted halfway through its mutation. A native helper may hold the exclusive borrow of the owning state **across its own sequential awaits** if Rust lifetime checking proves safety and there is no competing access. Borrowing `&mut` across await is not intrinsically unsafe. What must be rejected is concurrent access, a borrowed reference escaping to another future/registered callback, or an operation that retains a borrowed snapshot beyond its checked region.

## Minimal patch design

Implement one complete scalar path before widening surfaces. The following changes are dependencies, not permission to mutate files owned by another agent.

1. **Authoring module and handle witness:** add `src/ref.ts` exposing a frozen `RefIR` with official-shaped overloads. A private/canonical `RefType<A>` stores the content IRType and uses a distinct non-wire handle classification. Avoid lying that a handle is ordinary u64; the planner must distinguish semantic values from lexical resource references. `RefIR.make(initial: Expr<A>)` creates a `RefMake` computation; get/set/update/modify accept `Expr<RefValue<A>>`. Updates bind a symbolic old-value expression once. Validate witness equality at construction and again during compiler checking.
2. **Computation nodes and identities:** admit `RefMake(initial)`, `RefGet(handle)`, `RefSet(handle,value)` and `RefModify(handle,binder,result,next)`. `update` can construct the same RefModify node with Unit result; set can specialize it or remain one simple node. Add explicit allocation/read/write semantic references so reachability, normalization and diagnostics preserve sequencing. Do not teach the pure expression evaluator to read mutable state.
3. **Allocation region:** first admit `FlatMap(RefMake(initial), binder, body)` as a lexical allocation region. The direct-source restriction is deliberate: general effect-valued handles from Match/retry/Layer cannot be represented merely by adding a Rust type name. A standalone make whose handle escapes is refused. `map(make, ...)` can be implemented through checked flatMap+succeed only if the existing authoring helper does that already; otherwise refuse it in the first patch and document the boundary. Every region output/error witness must be handle-free.
4. **Handle/region checking:** track a separate environment from ordinary scalar binders: `RefHandle binder/index -> content witness + allocation region`. Require Ref operands to resolve to a live region handle. Sequential repeated use is allowed; fabricated handle literals, foreign binders, writes of another witness, storing/returning handles and deferred captures are refused with stable structured diagnostics. Ref allocation inside repeated/array computations initializes fresh state each execution. Scope/finalizer analysis must recognize and reject unsupported capture even when nested under annotations/recovery/helpers.
5. **Official reference:** allocate with official `Ref.make` each time the region is evaluated, bind the actual Ref in the interpreter environment, and call official get/set/update/modify. Keep compiler/evaluator defects outside typed failure recovery. The framed interpreter mirrors the same operations with stable occurrence kinds and bounds, rather than creating a second JS Ref implementation.
6. **Native ownership/lowering:** the region emits a local mutable scalar initialized once after entry/cancellation checks. Resolve each symbolic handle to that slot. Generated synchronous state helpers receive `&mut T`; asynchronous body helpers reborrow the same slot as needed and never start two such futures concurrently. Modification binds a Copy snapshot once, computes result/next locally, writes next and returns result. The first implementation may specialize helpers per region/environment like existing error-channel specialization; memoization keys must include state-region binding identity, not just node identity. Verify generated lifetimes with rustc rather than erasing them through pointers/interior mutability.
7. **Cross-cutting traversal:** update checking, analysis/effect reachability, provenance, plain/framed reference evaluation, helper binding/substitution, native effect enum/emission, frame decoding and structured Scope scans exhaustively. `FOREIGN_PARAMETER` checking alone does not prove a delayed finalizer capture safe. Add public R.Ref/barrel exports only after this complete path works. All native handle admission must be refused at external codec/function boundaries.

To keep the smallest patch reviewable, initially reject **all registered-finalizer Ref captures**, even where a nested Scope could eventually prove safety. Do not reject unrelated file/Scope use: a file can surround the entire Ref region and a finalizer that does not capture the cell can run normally. If the first implementation cannot safely thread local state through existing helper functions without broad structural changes, record that blocker and stop API admission; a TypeScript-only Ref export would misrepresent delivery.

## Acceptance and executable workload

Run official Effect, reference, native debug/release and both failure-frame policies for the same authored programs:

- Make/get; set then get; update then get; modify returns the old computed result and stores the new value; data-first/data-last calls preserve inference and error locations.
- One allocation used through two sequential branches and after sleep observes all previous mutations. Two executions of the identical authored function are isolated. Two independent RPC invocations interleaved during sleep must never read each other's counter.
- A shared `RefMake` **node** executed twice allocates twice, while repeated accesses to one **bound handle** share the cell. Repetition, retry and sequential forEach re-enter allocation regions correctly.
- Typed failure after mutation remains recoverable; recovery within the region sees the mutated state. Recovery outside a failed region cannot access its cell. Interruption during sleep exits cleanly and awaited unrelated cleanup completes exactly once.
- `modify` expressions observe one old snapshot; branch failure/defect is not silently converted to a partially committed mutation. In this bounded pure expression profile, ordinary domain failure cannot occur inside the callback.
- Negative type/compiler tests refuse escaping handles, ordinary literals masquerading as handles, wrong stored witnesses, foreign bindings, public/RPC handle channels, captures by registered finalizers and effectful callbacks. Shared helper bodies compiled under different allocation regions must not accidentally address the same slot.

The first demo is a per-invocation u64 counter: make 0, update +1, sleep, modify returning the previous value while adding 2, get 3, and return a Struct containing previous/current values. Surround that region with read-only file ownership and logging. Validate cleanup/counter/log ordering; run two invocations with distinct initial values and controlled suspension. This provides observable sharing/isolation without inventing a fake cell that only exists in TypeScript authoring.

## Costs and limits to measure

A scalar cell adds its `size_of::<T>()` plus alignment to the active stack or concrete future when live across suspension. Helper borrows may enlarge future captures and lifetime-specialized code; measure rather than promise a one-word global increase. A Bool can occupy one byte locally but padding may dominate future growth. Nested allocations inside finite loops need no per-iteration retained heap if regions close before the next iteration; cells simultaneously live across nested scopes increase bounded storage/code. No arbitrary fixed slot-count limit is needed when the native program itself owns lexical locals.

Measure unpolled future construction, execution without timers/logging, repeated sequential updates and then the real async workload. Record native allocations separately from TypeScript builder/compiler allocation, emitted Rust/code growth, future layout and existing frame/log/runtime costs. Verify SourceArtifacts.None and FailureFrames.None introduce no per-cell metadata or frame allocation; preserve optional inherited instrumentation costs honestly. Composite contents later require snapshot semantics and explicit clone/move choices; shared content references cannot be admitted as scalar Copy by accident.

## Readonly Duration boundary review

The parallel Duration track's normalization uses official `toMillis` and admits only integral 0–60000 ms. A local pinned-source probe checked nanos `1`, `999999`, `59999999999`, `60000000001`: each remains fractional and is refused; `1000000` and `60000000000` are accepted. Within the admitted interval, nanosecond integers are below Number's exact integer bound and a one-nanosecond fractional part remains distinguishable after conversion. Larger nanos can lose precision through the official Number conversion but exceed this interval and are refused. No blocking rounding/policy issue was found; raw-NaN refusal versus upstream constructed-zero behavior and existing Schedule normalization differences remain explicitly documented in the [Duration record](duration-module.md). This review adds no Duration code changes or fresh native timing evidence.

## Implementation and validation evidence

The public `R.Ref` supplies make/get/set/update/modify. Direct make plus ordinary flatMap becomes a checked RefScope, retaining allocation provenance. State is a native local with `&mut` helper reborrows across sequential awaits. Standalone or map-wrapped make, intermediate handle-bearing channels, public/composite escape, stale handles and registered cleanup captures are refused. Lexical compiler-erased Layer providers may share the live cell. Two independent readonly reviews found no further defects.

The rc.118 focused suite passes 2/2 (34.99s total; 33.70s tests), with fresh debug/release, both frame policies, file composition, independent interleaved invocations, cancellation/cleanup and source provenance. Compile-only contracts check inference and rejected state/effect mismatches. After remote synchronization the oracle is Effect 4.0.0; integrated stable results belong to PROGRESS.md.

Release probes report bounded-frame context/counter/cancellation future sizes of 104/536/408 bytes, and None sizes of 96/520/392. Unpolled future construction and 1,000 sequential cell workloads each add zero allocator calls after setup. These are whole-workload layouts and release observations, not isolated Ref deltas or general allocation guarantees. The constant finite-array workload may be optimized; timers/logging/runtime setup have separate costs. Compiler-only witness caching admits three canonical scalar keys and a WeakMap of native representations; TypeScript heap cost is unmeasured.
