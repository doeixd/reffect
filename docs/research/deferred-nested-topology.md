# Private nested Deferred topology

Prepared 2026-10-05 before source edits. Reviewed PLAN/PROGRESS, DADM-001/004, DGEN-001–005, TURN-002/003/006, existing structured-concurrency analysis and generated-profile refusals. Fetched [Effect 4.0.0 internal race implementation](https://unpkg.com/effect@4.0.0/src/internal/effect.ts) and verified the installed version is 4.0.0. Its `raceAll` starts children in iterable order, resumes on the first successful child, and interrupts remaining children through the parent's exit finalizer. Winning observation therefore does not establish completed loser cleanup.

**DNTO-001 — Explicit private opt-in, unchanged ordinary admission.** Add an optional internal nested-topology analysis mode. Default Deferred topology analysis and ordinary task-group analysis retain `NESTED_TASK_GROUP`; public planning and ordinary lowering do not consume this opt-in. Private opt-in removes only the existing nested diagnostic, retaining cleanup, host/service, arity, loop, stream, cycle and callback-startup refusals. The generated profile separately proves every reached computation has Never error; nested topology with fallible outcomes remains outside this experiment.

**DNTO-002 — Bound live contexts, not distinct graph nodes.** A leaf needs one context. A group needs its own context plus the sum of child subtree capacities; sequence and mutually exclusive branches take their maximum. Thus All2(Race2(waiter, timer), producer) needs five contexts, and All3 with one Race2 needs six. Lexical owner occurrences remain a separate expanded count. Expose build-owned per-computation subtree capacities so lowering can reserve contiguous child ranges. Memoizing capacities for shared IR nodes does not memoize task identity: each simultaneously live occurrence receives its own range. Sequential groups may reuse ranges only after complete child/finalizer drain and retirement of active turn requests.

**DNTO-003 — Preserve callback and cleanup startup barriers.** A nested child group may start directly from its parent's initial poll. Group startup after Deferred Await or Complete remains refused, including branches, recovery and finalizers reached after such operations. Masked cleanup cannot create groups even if no Deferred resume preceded it. A nested coordinator's adapter Pending must route a descendant priority without marking its parent as semantically suspended; actual child completion/finalization remains the acknowledgement boundary.

**DNTO-004 — Validate capacity and admission independently.** Focused analysis tests cover five/six-context examples, shared nested group occurrences (disjoint live reservations), sequential reuse, preserved default/ordinary refusal, callback and cleanup barriers, and fallible nested refusal. Generated native/reference tests are separate evidence owned by the integration track; static capacity analysis alone proves neither scheduling nor cancellation ordering. Public Deferred, rich nested outcomes and executable reference-context enforcement remain gated.

Alternatives rejected: globally allowing nested ordinary groups, assigning slots by distinct node identity, summing sequential lifetimes, or counting only leaves while omitting suspended group ancestors. These would either widen an unverified compiler boundary or under/overstate invocation-local storage.

Strict package TypeScript passes. Formatting applied to the three owned files. Generated runtime/reference conformance remains integration-track evidence.
