# Deferred executable context boundary audit

Prepared 2026-10-05 against installed and published **Effect 4.0.0**, before implementation. Read AGENTS, PLAN/PROGRESS, DBUD-001–005, DADM-001–004, the private generated reference shim and the plain/framed official evaluators. Retrieved the published [Scheduler](https://unpkg.com/effect@4.0.0/src/Scheduler.ts) and [internal evaluator](https://unpkg.com/effect@4.0.0/src/internal/effect.ts); both match installed source byte for byte. Further primary references: [Effect runners](https://unpkg.com/effect@4.0.0/src/Effect.ts), [Fiber interface](https://unpkg.com/effect@4.0.0/src/Fiber.ts), [Context defaults](https://unpkg.com/effect@4.0.0/src/Context.ts), [Clock](https://unpkg.com/effect@4.0.0/src/Clock.ts), [Tracer](https://unpkg.com/effect@4.0.0/src/Tracer.ts), and [Logger](https://unpkg.com/effect@4.0.0/src/Logger.ts).

## Source findings

- `Effect.runForkWith(context)(effect)` constructs `FiberImpl`, starts `fiber.evaluate(effect)` immediately, and returns the fiber. Unlike `Effect.provideService`, constructing its context does not add evaluator primitives. It does not inherit the calling fiber's context even when invoked from synchronous code inside another Effect.
- Root fibers start interruptible unless `RunOptions.uninterruptible === true`. `options.scheduler` overrides the supplied context. `onFiberStart` and AbortSignal handling happen **after initial evaluation**, and are skipped if the fiber already finished. A pre-aborted signal therefore does not prevent the synchronous prefix from executing.
- The evaluator resets `currentOpCount` at each evaluation, checks `scheduler.shouldYield` before evaluating each primitive, and invokes `cache.tracerContext` in place of normal primitive evaluation when supplied. `succeedWith` increments the counter too. `MixedScheduler.shouldYield` compares the counter with `cache.maxOpsBeforeYield`; defaults are 2048 and `PreventSchedulerYield = false`.
- `Fiber.Cache` publicly exposes scheduler, maxOps, preventYield, tracer/context, runtimeMetrics and other cached references. `Fiber.getRef` can resolve Clock/loggers. These support observational checks but do not prove no earlier custom hook ran. Runtime metrics can run already in the FiberImpl constructor; a tracer-context hook can run before an Effect-level guard primitive is evaluated.
- `MixedScheduler` accepts a custom dispatcher callback in its constructor, its methods can be overridden, and subclasses are valid. `instanceof MixedScheduler`, constructor/prototype identity, or one observed yield decision cannot establish default scheduler behavior for a caller-provided object.
- `Context.empty()` excludes custom metrics, parent spans, annotations and service overrides. Native tracing remains enabled under the upstream defaults; absent explicit tracer cache resolves to `Tracer.nativeTracer` when creating the named reference span. The default Clock's sleep uses callback/void and synchronous timer cleanup, matching DBUD/DADM receipts. Providing a TestClock/custom Clock changes that receipt and is not production admission evidence.
- `Logger.CurrentLoggers` holds a set of synchronous logger objects. `log` receives the active **Fiber**, so accepting an arbitrary logger accepts context mutation, reentrant evaluation and throwing callbacks. A synchronous TypeScript return type alone does not establish the DBUD logger precondition.
- `Fiber.setContext`, `interruptUnsafe`, observers and mutable underlying Context/default service objects are accessible. `Context.Reference` memoizes its default object on the reference itself. An isolated Context does not sandbox arbitrary JavaScript or defend against monkeypatching Effect/global timer functions.

## Decisions

**DCTX-001 — Prefer an isolated standalone runner.** Keep the existing composable private reference effects as experiments with conditional assumptions. Add a separately named, private execution boundary which constructs its own Context, creates the unchanged existing plain/framed evaluator, and uses `Effect.runForkWith` directly. It must accept the authored EffectFn, not an arbitrary host Effect, so callers cannot insert their own continuation before/around the invocation. Reject unsupported runner options before starting execution. No boolean user assertion substitutes for this boundary. Public Deferred remains gated independently.

A minimal supported production context starts with fresh `Context.empty()`, a runner-owned `new Scheduler.MixedScheduler()` with no constructor callback, explicit `Scheduler.MaxOpsBeforeYield = 2048` and `Scheduler.PreventSchedulerYield = false`. Resolve the default Clock through `Context.get(Context.empty(), Clock.Clock)` if an explicit identity is useful: the default ClockImpl constructor is internal, and manufacturing a superficially equivalent clock adds another semantic adapter. Leave the native tracer/default tracing references intact; do not turn tracing or automatic yields off to satisfy the proof. Context construction uses ordinary synchronous APIs, not Effect-level `provideService` wrappers.

**DCTX-002 — Keep invocation control opaque and logging owned.** Avoid returning the raw Fiber from this isolated boundary: a caller could replace its context after initial suspension. Prefer a Promise result exposing only Exit and immutable captured log observations; use a closed AbortSignal option for cancellation. `Effect.runPromiseExitWith(context)(effect, { signal })` owns the underlying Fiber and registers the completion observer directly. An observer attached after completion is supported by upstream addObserver. Do not accept arbitrary logger objects, contexts, schedulers, clocks, tracers, startup hooks or uninterruptible options in the initial supported runner. A runner-owned logger may append primitive event data to an invocation-owned array without invoking user callbacks and without retaining/exposing the active Fiber. Loggers can use a fresh internal Set and Context.add outside evaluation.

This is an execution contract within a trusted JavaScript process. Global monkeypatching of upstream defaults, scheduler prototypes, global timers or IR internals is not prevented. If a later API accepts any user callback, its effects and possible reentrancy must be admitted explicitly; freezing only the options object is insufficient.

**DCTX-003 — Entry inspection is not the same guarantee.** A guard using `Effect.withFiber` can reject visibly overridden Clock, scheduler budget, tracer context, metrics and logger references, but it cannot detect the number of prior Effect operations, arbitrary surrounding continuations, hooks already executed or future host wrappers. Inspecting `currentOpCount` is timing-sensitive because evaluation/resumption resets it; one initially small value does not constrain later resumption continuations. Guarding before the named wrapper or inside it also adds an evaluator primitive and possible terminal result; the old DBUD entry receipt cannot silently cover this. Replacing the inherited Context for the duration of an Effect still leaves prior operations and outward continuation effects. Thus an embedded checked reference would require a separate proof and contract. It should not be represented as equivalent to the standalone runner.

**DCTX-004 — Audit actual additions, not TypeScript call nesting.** The standalone `runForkWith`, Context.make/add/get, checker invocation, Promise construction and direct observer registration introduce **zero** extra Effect evaluator primitives on the successful path. The existing named Effect.fn reference wrapper remains unchanged. The runner should observe its plain result directly; it needs no extra `Effect.exit` around it because Fiber observers already receive Exit. Framed interpretation already returns its FramedExit as a success value. The DBUD entry 24-operation receipt already overcounts one external Effect.exit observer and the plain/framed alternatives, so removing that external observer is conservative. Adding validation via `Effect.try`, `Effect.suspend`, `Effect.withFiber`, logging wrappers, Schema decoding or arbitrary signal cleanup Effects requires a new receipt. Promise continuations attached after a terminal Exit cannot affect scheduling within the admitted invocation.

**DCTX-005 — Cancellation is explicit.** The chosen first runner uses a closed option containing only a genuine AbortSignal, preserving official interruption/draining behavior, rather than forwarding generic RunOptions. Validate extra context/scheduler/hook/uninterruptible fields and the signal before starting execution. A pre-aborted signal short-circuits before interpretation to an explicit interrupted Exit; specify the pre-start framed result separately without inventing authored frames. Upstream's eager initial evaluation means signal wiring alone cannot promise zero execution after pre-abort; a synchronous check before invoking the runner and a separately defined cancelled result are necessary. There is no await between the precheck and upstream eager evaluation; normal JavaScript execution cannot interleave another task in that span. This does not promise sandboxing of malicious getters or monkeypatched AbortSignal internals. Finalizers must finish before the Exit promise settles. Do not add timeout/deadline timer machinery implicitly; it would need explicit lifecycle and cancellation semantics. Unsupported custom options must fail before observable authored logs or completion effects execute.

## Validation and remaining gates

- Assert supported plain/framed runner results and exact traces against independently authored official workloads; preserve ordinary/public Deferred refusals and the narrow nested profile.
- Run the standalone boundary from within an outer Effect with hostile Clock/tracer/logger/scheduler overrides and substantial preceding operations. Its behavior must remain independent of those overrides; verify overridden hooks receive no invocation callbacks.
- Reject explicit unsupported options before starting any authored work. Include custom MixedScheduler subclasses and constructor dispatchers rather than testing only an unrelated Scheduler implementation.
- Verify no raw fiber/logger callback capability escapes and cancellation waits for awaited cleanup. Test immediate completion, pre-aborted signals, suspended execution and abort-after-completion. Copy/freeze the log array in the completed result.
- Corroborate successful-path receipt equivalence with a separate delegating MixedScheduler probe; a probe is test instrumentation, not an accepted production scheduler. Exercise conservative near-boundary admission/refusal and an independently longer workload that actually yields under the real default scheduler.
- Existing TestClock-based differential tests are useful controlled-semantic experiments, but they do not establish a default-Clock production entry contract. Keep them clearly separated from this boundary's validation.
- Exact interrupted diagnostic-frame equivalence, compound outcomes, callback-created groups and broader task topology remain independent public admission gates. No Rust runtime, scalar representation or per-value metadata change is required by this execution-context boundary.

Research-only record: no feature code or tests changed by this audit. Root integration owns documentation index/progress links and executable validation. The selected implementation direction is an internal standalone Promise runner with separate plain/framed entries, synchronous profile prevalidation, a closed AbortSignal option, isolated defaults and owned log collection; the earlier Effect-valued private entry remains explicitly conditional.
