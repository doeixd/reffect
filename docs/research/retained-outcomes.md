# Cancellation-retained outcome analysis

Recorded 2026-10-04 before implementing the DOWN-001–003 repair. Checked installed Effect **4.0.0** and fetched its [published runtime source](https://unpkg.com/effect@4.0.0/src/internal/effect.ts) online on this date: `FiberImpl.getCont`, typed `catch_`, `combineFinalizerCause`, `OnExitImpl`, and `setInterruptible`. This refines [Deferred ownership](deferred-ownership.md) without admitting Deferred or nested task groups.

**RETAIN-001 — One build-owned analysis.** Extend `analyzeTaskGroups` with `requiresRichErrors`, `hasRetainedFailures`, and identity sets `richComputations`, `richGroups`, and `cancellationGuards`. Keep `hasFallibleGroups`'s declared-channel meaning. The checker, emitted helper flags, runtime reachability and host refusal consume this result. No scalar value, dynamic annotation or context gains metadata.

**RETAIN-002 — Conservative async recovery seeds.** A typed CatchAll or Retry whose source is asynchronous can encounter cancellation after failure selection while masked cleanup awaits. Effect's continuation selection skips recovery when interrupted, preserving that selected failure. Record a cancellation guard even if source and destination E agree. Bool/U64/Unit sources select the existing rich carrier; changed E retains the source's tagged scalar value. Source Never is not sufficient to dismiss propagated retained failures. Propagate seeds and existing fallible groups through every parent edge, including distinct contexts of shared nodes; rich group wrappers are selected from these reachable outcomes, not child E alone.

The analysis intentionally also selects rich support for async sources whose concrete failure path has no awaited cleanup. A local scheduling proof could narrow this later; underapproximation would discard an observable failure. Pure synchronous sources keep existing recovery behavior, since the current source interpreter offers no suspension between selecting failure and recovery.

**RETAIN-003 — Composite boundaries.** Same-E composite recovery outside groups can preserve its ordinary typed error and needs a cancellation guard. Changed-E async composite recovery is refused because RuntimeFailure has no composite payload representation. Existing task-group-related composite channel-change refusal remains. No generalized heap error box or schema encoding is introduced as a workaround.

**RETAIN-004 — Capacity remains three.** Existing admission forbids child task groups and cleanup-created groups. Each leaf contributes at most one failure: cleanup runs masked and has declared Never; nested masked typed recovery therefore handles its error normally. Recovery skipped during ambient cancellation stops the sequential leaf rather than entering another source. Repeat/Retry do not accumulate earlier failures; a successful recovery discards the handled cause, and a canceled retry returns its selected failure. A root may receive a complete group cause, but sequential execution cannot concatenate multiple group causes. Thus All3 is the maximum three-failure collector; Race2 contributes at most two. The existing single interruption Boolean remains separate. This proof depends on the current masked cleanup contract; it does not justify nested groups, failing cleanup, interruption restoration inside cleanup or future custom host effects. Those need separate admission and capacity proofs.

**RETAIN-005 — Required evidence.** Analysis tests cover root and child same/changed scalar errors, Never-declared children, Retry, composite refusals, synchronous legacy recovery and shared-node contexts. Differential native tests must interrupt during held cleanup, assert recovery/retry does not execute, retain original scalar kinds after E changes, and exercise None/Bounded and debug/release. Root All and Race observation policies remain distinct. Rich-carrier RPC programs remain refused until compound wire causes are supported. Existing ordinary artifacts must stay unchanged when no rich outcome is reachable.

The analysis and source audit alone do not establish native correctness. The runtime changes and differential tests are separate release gates.

**RETAIN-006 — Cleanup-only recovery needs no cancellation guard.** Root review found that a guard emitted for an always-masked cleanup can reference the rich carrier even though analysis correctly does not select it. Only unmasked analysis contexts seed cancellationGuards. A node shared with an unmasked context still receives the guard and carrier; its cleanup occurrence observes the existing mask and continues normally. Direct analysis and native cleanup-only compilation regressions must preserve ordinary specialization.

The [composite recovery refinement](retained-composite-recovery.md) narrows RETAIN-003 for ordinary sources that cannot suspend with a selected failure. Merely awaiting a Remote store call or timer before failing does not establish retained composite outcomes. Masked cleanup/acquisition, registered resources, task groups and unverified coordination remain conservative boundaries. Scalar carrier selection is unchanged.
