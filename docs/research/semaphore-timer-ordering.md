# Bounded Semaphore timer ordering

Prepared 2026-10-06 before feature edits. Checked installed Effect **4.0.0**, Node **24.19.0**, Tokio **1.53.1**; reviewed AGENTS.md, PLAN current frontier, latest PROGRESS and [SPUB-007](semaphore-public-admission.md#spub-007-concurrent-timer-admission). This is preparation for a restricted widening, not evidence for arbitrary scheduler or host equivalence.

## Primary evidence

- Published [Effect evaluator/Clock](https://unpkg.com/effect@4.0.0/src/internal/effect.ts), [Scheduler](https://unpkg.com/effect@4.0.0/src/Scheduler.ts), and [Semaphore](https://unpkg.com/effect@4.0.0/src/Semaphore.ts) were fetched and byte-compared equal to installed source. Relevant installed evaluator lines1034–1049,1155–1220,6298–6326; Scheduler lines86–107,203–253; Semaphore lines214–229,264–275,299–310.
- `ClockImpl.sleepMillis(0)` returns `yieldNow`; it does **not** install a zero timeout. Yield queues priority0 dispatcher work and always suspends. A canceled Yield ticket is ignored by its closure. Positive finite Sleep registers `setTimeout`; its callback invokes `resume` and synchronously evaluates the suspended fiber's continuation. Interrupted Async evaluates a masked finalizer that clears the timeout, and `resumed` prevents subsequent stale callback resumption. Infinite Sleep is `never`; durations above2³¹−1 are chunked. The public bounded profile already limits durations to integers0..2³¹−1.
- MixedScheduler on Node uses `setImmediate`; without it, its fallback uses `setTimeout(0)`, then microtask only if scheduling throws. Equal-priority tasks append FIFO. A dispatcher callback drains a snapshot; work enqueued during a scan runs in a later scheduled snapshot. This host distinction matters for timer/scan ordering.
- A permit release mutates capacity synchronously and queues priority0 **live** waiter scan, rather than running it inline. The later scan sees current registration/cancellation state. Each selected waiter synchronously resumes its Effect continuation. Masked asynchronous cleanup retains the permit until the guarded result and its finalizers finish; only then does the permit wrapper release.
- [Node timer API](https://nodejs.org/api/timers.html#settimeoutcallback-delay-args) explicitly makes no callback ordering guarantee. Pinned [Node24.19.0 timer source](https://github.com/nodejs/node/blob/v24.19.0/lib/internal/timers.js) nevertheless provides primary implementation evidence: insertion groups timers by integer duration; a priority queue orders duration lists by head expiry then list creation id; each selected list drains its due members FIFO. `processTimers` uses one `now` snapshot. It runs next ticks/microtasks between timer callbacks, but a `setImmediate` release scan cannot interrupt that timer pass. [Node event-loop explanation](https://nodejs.org/en/learn/asynchronous-work/event-loop-timers-and-nexttick) identifies `setImmediate` with the check phase and describes the Node20+ timer-phase change. Already queued check work versus future timer readiness needs its own turn handling; a blanket rule to always run all currently overdue timers before all scans is not established.
- [Tokio1.53.1 Sleep source](https://github.com/tokio-rs/tokio/blob/tokio-1.53.1/tokio/src/time/sleep.rs) was fetched and byte-compared equal to the installed Cargo source. Sleep has millisecond granularity; dropping cancels it. No cross-Sleep callback FIFO contract is documented. [Timer driver](https://github.com/tokio-rs/tokio/blob/tokio-1.53.1/tokio/src/runtime/time/mod.rs) fires expired entries and batches their wakers; [wheel](https://github.com/tokio-rs/tokio/blob/tokio-1.53.1/tokio/src/runtime/time/wheel/mod.rs) and linked-list implementation are execution substrates, not Effect ordering guarantees. A child waker queue preserves observed Tokio wake order, which does not by itself prove Node order.

## Controlled official observations

Temporary scripts outside the repository used actual `Effect.all` with concurrency unbounded, a fresh ordinary MixedScheduler and actual Semaphore; no custom Clock or scheduler hooks. Node24.19.0 observations:

1. Holder acquires and sleeps20; waiter contends; independent sibling sleeps20 then acquires. Blocking the host immediately after starting for50ms makes both timers overdue. Trace: `holder entered, holder released, timer barger before, barger entered, barger released, waiter entered, waiter released`. Draining the release scan immediately after the holder timer instead produces the wrong waiter-before-barger order.
2. Sleep0 child and synchronous sibling: `zero before, sync sibling, host after run, zero after`. A native Sleep0 that returns Ready on its initial poll contradicts this suspension.
3. At t0 children register A100 and B101; a third sleeps50 then registers C100. A host timeout at70 blocks for150ms. Trace: `C registered, A100, C100, B101`. Individual nominal deadlines are100,101,150, but Node drains the100-duration list before the101-duration list. This disproves a general globally sorted deadline bank, even with only three children.

These probes corroborate source behavior, not an absolute wall-time claim or every host/phase topology.

## Decisions and implementation obligations

- **STIM-001:** retain existing arbitrary positive sequential sleeps when at most one All child can sleep. For a useful bounded widening, consider multiple Sleep-bearing children only when **every possible Sleep literal across those children, ordinary bodies and masked finalizers, is the same strictly positive integer**. Branches count conservatively. Then all competing generated timers occupy one Node duration list, whose ordering is registration FIFO; absolute-deadline sorting with registration ties agrees if registrations share a consistent monotonic clock. Mixed-duration concurrency remains refused. This does not establish behavior for custom Clock, browser fallback schedulers, automatic yields, mutable host hooks or general Futures.
- **STIM-002:** generated Sleep needs explicit registration identity and unregister-on-completion/cancellation; cancellation invalidates only the interruptible timer, while masked finalizer timers remain active. Renewed sleeps receive new tickets. Parent cancellation must preserve existing settlement/cleanup ownership and terminal sibling cancellation before releasing permits. Registration must precede Pending and not be inferred from generic Future readiness.
- **STIM-003:** a timer turn freezes its due set/time before polling any callback, resumes selected children in registration order through synchronous tails, and only after that frozen timer wave allows release-created scans to run. New positive registrations cannot join the frozen wave. Preserve live scan selection, one selected callback at a time and existing cancellation checks; do not release all permits before executing timer continuations. Distinguish an already scheduled scan turn from a timer turn; source evidence does not justify selecting a timer merely because time advanced while a scan was pending.
- **STIM-004:** a safe `Arc`/Mutex child-waker queue can route independent wakes without raw borrowed RawWaker lifetime hazards, but adds allocation/shared state and preserves Tokio ordering rather than proving Effect order. A generated-only inline deadline/ticket bank can exploit audited Sleep/acquisition Pending sources and retain inline scalar/owner/future storage; its costs and layout must be measured. It must own one substrate wake for the earliest relevant timer and impose the checked ordering itself, rather than poll all Tokio Sleeps in tuple order. Prefer this restricted bank only after the phase cases below pass. Do not introduce a general Effect scheduler.
- **STIM-005:** Sleep0 is scheduler work, not positive timer work. Concurrent zero/positive or zero/scan admission needs a separately proven queued-yield/dispatcher snapshot adapter that guarantees initial Pending. Merely assigning zero an immediate deadline or repeatedly self-waking is insufficient. If it cannot be proved in this change, explicitly refuse zero in the affected coordinated profile and record the compatibility restriction; do not silently change its reference meaning.

## Acceptance and uncertainties

Required official/generated debug+release cases: reversed static versus registration order; same-duration equal deadlines; all timers overdue; a staggered third registration; sequential renewals; timer-wave barging ahead of a queued waiter; a scan already pending before a later deadline; scan-created timers and releases; parent/sibling cancellation between callbacks; stale canceled registration; masked holder and sibling finalizer timers; source branches and literal-uniformity refusals; framed and unframed exits; actual returned-future layout and full invocation allocation measurements. Timer/scan-order mutations should fail targeted traces. Keep native builds sequential.

Open: native clock precision versus Node's integer libuv registration clock can split an apparently simultaneous due batch; a wall-time-only bank cannot infer the exact host callback phase when the parent is polled late. Uniform duration removes cross-duration-list ordering but does not erase those phase/clock obligations. Already pending release scans and asynchronous cleanup cancellation are the critical remaining cases. Accept a narrower profile or retain SPUB-007 where evidence is insufficient; any accepted difference must be recorded as a divergence rather than called parity.

## Chosen implementation boundary (STIM-006)

Implement a generated-only inline timer bank and one pinned Tokio wake timer per All. Child sleeps register monotonic deadline and unique ticket; they suspend until the driver grants that ticket, rather than polling independent Tokio Sleeps in static order. Each resumed parent poll freezes the eligible registered tickets before executing callbacks. Positive timer callbacks run FIFO by registration, then release scans drain to completion through existing live selection. Registrations created by those callbacks wait for a subsequent wave. First group polling performs eager startup and returns Pending before delivering any registered timer. No lock crosses child polling. Timer leases unregister on completion/interruption/drop; masked finalizers register fresh uncanceled timers.

The closed profile cannot carry a semantically pending release scan across a suspended group poll: the live-scan driver drains all scheduled scans before returning Pending. Releases before the group's startup have no earlier suspended borrowers because there is only one unnested group and a nonescaping lexical owner. Selected callbacks run through synchronous completion or an explicitly marked wait before the scan proceeds. Add an invariant assertion/test at the Pending boundary rather than relying on host wake identity. This is a bounded adapter argument, not equivalence for arbitrary host work or a general scheduler.

Keep arbitrary positive sleeps in a single timer-bearing child. With multiple timer-bearing children, every Sleep in their bodies/finalizers/source branches must have one identical positive literal. Refuse zero inside All children for now: their yield jobs share the dispatcher's snapshot queue with scans and require a separate adapter. Sequential root sleep(0) can use a guaranteed initially Pending Tokio yield with biased cancellation, since no other source borrower is live outside the group. Its reference operation receipt remains bounded by the existing conservative Sleep atom.

Clock precision and execution speed can vary real-time wave boundaries between hosts; this profile preserves FIFO registration and callback-before-release-scan ordering for each observed due wave, and does not promise equal elapsed times or all timing-dependent event interleavings across hosts. Test fully-overdue waves deterministically, plus separate waves, scan-created timers, renewed leases, cleanup and root-zero cancellation. Widening mixed durations or queued child yields stays refused.

## Review corrections

Node timer registration calls `GetLibuvNowImpl` → `Environment::GetNowUint64`, which calls `uv_update_time` on each insertion ([env.cc](https://github.com/nodejs/node/blob/v24.19.0/src/env.cc#L1591), [timers.cc](https://github.com/nodejs/node/blob/v24.19.0/src/timers.cc#L43)). Its clock is integer-millisecond, not one necessarily shared startup timestamp. Native clock precision may still change real-time wave cutoffs; registration FIFO remains the verified invariant.

Independent review found that a final cancellation settlement after scan draining could synchronously release a holder while a later waiter remained registered and start another child's masked timer cleanup, leaving a pending scan at suspension. The ordered driver now performs the final settlement before draining, with no further settlement between drain completion and the Pending invariant. Parent watch readiness stays registered throughout; a signal after this point wakes the next poll rather than releasing a permit behind the invariant.

## Delivery

The uniform-positive profile is selected by public Compile and owned SemaphoreExecution. Native debug/release conformance runs with both frame policies and source artifacts disabled; profile/emission tests also exercise full artifacts. Fully overdue barging, reverse renewed registrations, scan-created timers, normal and final-phase cancellation with awaited masked cleanup, root-zero interruption, stale ticket grants and drop removal pass. Timing-controlled tests hold the native returned root future between polls and block the official event loop after eager startup; this proves due-wave ordering without treating an arbitrary elapsed sleep as a scheduling barrier. A test-only watch sender at the second parent check reproduces the valid late cancellation phase; production runtime exposes no new execution hooks.

Mutation evidence: dispatching scans between timer callbacks changes waiter/barger log order; moving the final settlement after draining panics at the no-pending-scan invariant. Both are rejected by conformance and reverted. Inline bank size is bounded below1KiB and a lease belowfour pointer words in native code-generation probes. Returned root futures retain the existing2560-pointer-word bound. Quiet generated scalar/All2 calls retain0/2 allocations after parent initialization; the two All allocations are child watch channels. Full registration/wake/interruption allocation and compiler peak-memory accounting are still separate measurements.

Next gates: mixed-duration timer-list semantics, queued zero/yield jobs inside All, broader hosts/context integration and unused-state specialization. Native nanosecond versus Node integer-millisecond timing can change which timers become due in a poll; the adapter preserves registration FIFO and wave-before-scan guarantees without promising equal real-time wave cutoffs.
