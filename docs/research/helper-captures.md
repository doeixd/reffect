# Private generated helper captures

Prepared 2026-10-04 before implementation. Reviewed AGENTS, PLAN/PROGRESS, DGEN/DHELP/DGC, metadata-cost and the lowerer's binding scopes, helper memoization, argument emission and existing delayed-finalizer capture walk. Checked the current [Rust Reference async functions](https://doc.rust-lang.org/reference/items/functions.html#async-functions) and [closure capture precision](https://doc.rust-lang.org/reference/types/closure.html#capture-precision) online. Async functions capture every parameter, including unused parameters, into their returned future; relying on optimization to remove unused signature arguments is therefore weaker than omitting them. Rust 1.98.1 / Tokio 1.53.1 are the measured project profile; future layouts remain compiler/target observations.

**HCAP-001 — Select signature captures without changing binding scopes.** Reuse the exhaustive IR expression/computation walk that selects external delayed-finalizer parameters. For private generated Deferred functions, compute actual external scalar and lexical owner references across the whole helper subtree, including nested helpers and immediate finalizers. Filter helper signature inputs while retaining the complete Scope bindings/input and existing node/scope/error memo identities for lowering. Newly introduced binders are absent from the caller Scope, so they never become external captures. Pure expression helpers use the same scalar selection. Ordinary helpers retain their existing signatures and output.

**HCAP-002 — Owners remain separate borrowed references.** Track owner binder identity independently from scalar parameters; retain only owners referenced by await/complete/isDone anywhere below the helper. An inner owner scope creates its own owner locally, while its body can still reference outer owners. No owner registry, metadata field, erased pointer, allocation or copied payload wrapper is introduced. Preserve context/turn arguments uniformly: eliminating those requires a separate transitive runtime-obligation proof, beyond lexical capture minimization.

**HCAP-003 — Evidence and bounded scope.** Test unused owners and scalar binders, transitive uses, immediate finalizer captures, shared nodes in distinct scopes and pure branch helper captures. Preserve emitted source ranges and ordinary output. Existing generated debug/release, None/Bounded trace/cancellation/quiet-allocation tests remain authoritative. A separate cost-growth fixture measures depth growth; no fixed portable Rust ABI size is claimed. Pruning signatures can reduce redundant future captures but cannot erase the intrinsic state-machine storage needed by a deeply nested semantic composition.

Alternatives: prune Scope itself (rejected because it changes binder lookup and nested parameter positions); infer uses from emitted strings (rejected because names are not semantic identity); globally change ordinary helper captures (deferred to avoid unrelated artifact/provenance changes). Dynamic resources, nested groups and rich Deferred channels remain outside private admission. The exhaustive walker must remain updated as IR tags evolve; matches enforce that at TypeScript compile time.

**HCAP-004 — Bound the compiler-side walk honestly.** Signature selection currently walks each helper's reachable IR independently, with per-walk node sets. Deep chains therefore have quadratic worst-case compiler traversal rather than linear traversal. The private entry's existing 2048-operation expanded reference budget bounds admitted workloads, and no new runtime work results. Do not claim linear compile costs. If measured compilation cost becomes material, replace repeated walks with memoized semantic free-reference summaries (scalar binder/index and owner binder), then resolve/filter through each complete Scope; memoization must preserve lexical binder identity and shared-node behavior. That optimization remains deferred rather than adding a second IR traversal system without evidence.

Focused initial validation passes 10/10 across helper-capture and private-profile suites; strict package TypeScript passes. The test record includes transitive pure-branch scalar reads, omitted unused outer owner/scalar bindings, shared owner nodes in distinct scopes, and immediate finalizer owner/scalar captures. Full native semantic and growth measurements are recorded by the integration owner.
