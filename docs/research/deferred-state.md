# Inline cooperative Deferred state

Preparation recorded 2026-10-04 before implementation. Reviewed PLAN/PROGRESS, AGENTS, DN-001–007, TURN-001–012 and the existing turn-bank fixture. Checked [Effect 4.0.0 Deferred source](https://unpkg.com/effect@4.0.0/src/Deferred.ts) online: await registers a removable resume callback; `doneUnsafe` retains completion, detaches callbacks before executing their registration-ordered cohort, and rejects subsequent completion. TURN-011 replaces DN-003's proposed stored Wakers with checked task IDs for one cooperative invocation.

## Decisions and boundary

- **DS-001 — Inline one-shot owner.** `DeferredState<A,E,N>` stores Copy `Result<A,E>` and N linked registration slots under std Mutex. This private experiment is unreferenced by compiler/public authoring. No Arc, stored Waker, heap registry, generation counter or scalar wrapper is introduced.
- **DS-002 — Detached indices cannot alias reused registrations.** Await first checks retained completion under the registration lock. Winning completion atomically installs the result and detaches the linked ordered cohort. Existing registrations remain unreleased until their selected turn. Drop removes its own slot, including a detached slot. Once completion is retained, no new pending registration is possible, so detached indices cannot alias a replacement. Repeated pre-completion cancellation may reuse physical slots; the linked list preserves registration order. A fresh lexical owner is a fresh borrowed object; Rust prevents dropping/replacing it while futures retain borrows.
- **DS-003 — Wake delivery belongs to the turn bank.** Winning completion selects each surviving detached registration in order, then requests/awaits the existing continuation-turn acknowledgement. Locks are released before requests/waking. Await Pending marks a genuine suspension; completion adapter Pending does not. Late awaits and losing completions finish immediately even while the winning cohort is being processed.
- **DS-004 — Explicit lifecycle gates.** The coordinator must poll selected canceled tasks through cleanup and acknowledge their semantic suspension/completion. Completion must remain interruption-masked until its whole cohort drains, including requests already selected. Arbitrarily dropping an armed completion future abandons a bank request; this private state adapter does not repair that unsupported host action. Public admission, operation-budget proof, nested ownership routing, typed retained failure carriers and generated masking remain gates.
- **DS-005 — Capacity faults are invariant faults.** Zero capacity, duplicate parked task identity, exhausted slots, incorrect slot identity and poisoned locks assert/panic. Generated checked topology must establish capacity and identity before this emitter is selected. General shared/multiexecutor Deferred and non-Copy outcomes remain excluded.

## Validation requirements

Compile emitted Rust in debug/release. Exercise both result variants; completion before polling; first/losing completion; late awaits during active cohort; registration order distinct from physical slots; pending and detached cancellation; cancellation of an armed target acknowledged by its task wrapper; repeated registration-slot reclamation; independent owners; and construction/registration/completion with a noop Waker under a counting allocator. Report owner/wait/completion layouts and isolated allocation counts separately from Tokio/coordinator/frame costs. These tests establish state and turn composition, not compiler/public Deferred conformance.

## Implemented experiment and results

The private `deferred-state-runtime.ts` emitter now implements the proposed owner and borrowed wait/completion futures. `deferred-state-runtime.test.ts` compiles emitted safe Rust with warnings denied in debug and optimized modes, verifies equal results, and verifies Rust rejects dropping an owner while a future retains its borrow (E0505). Direct polling tests cover the state cases above and nested bank requests; reading an await result alone does not acknowledge its whole continuation turn.

Measured on Rust 1.98.1, Linux x86_64 in both modes: `DeferredState<u64,bool,4>` is **184 bytes**, its wait future **40 bytes**, completion future **128 bytes**, and registration entry **32 bytes**. The shared six-task turn bank remains separate (168 bytes in the existing turn-bank record). A completion stores its detached fixed cohort on the future; the owner does not duplicate that cohort. One hundred complete lifecycles containing construction, pending registration/cancellation, winning completion and acknowledgement, losing completion, late await and Drop produced **zero allocations**, hence zero allocated peak/retained bytes on the isolated measured path. The noop Waker and manually driven bank exclude executor/watch/task/finalizer/frame costs. No None/Bounded claim follows from this private emitter because it carries no frame policy and is not selected by compiled code.

All runtime code uses safe Rust. Unsafe code is restricted to the test counting allocator's required std System forwarding. The state fixture is intentionally independent from the real Tokio/official-Effect turn fixture; root integration of the new owner into that fixture supplies complementary executor/ordering evidence. Neither fixture removes the public gates recorded in DS-004.
