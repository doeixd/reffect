# Private Queue continuation bridge

Prepared 2026-10-06 before implementation. This experiment connects ordinary pinned Rust futures to the [bounded Queue protocol](queue-bounded-foundation.md); it precedes checked IR lowering and public admission.

## Sources and compatibility

Reviewed installed and freshly downloaded [Effect4.0.0 Queue source](https://unpkg.com/effect@4.0.0/src/Queue.ts), especially takeUnsafe, releaseCapacity, releaseTakers and scheduleReleaseTaker. Pending producers resume synchronously inside capacity release, before take returns. Takers receive retry notifications and scan the live registration set; offers schedule a later dispatcher pass. The [Rust Future contract](https://doc.rust-lang.org/std/future/trait.Future.html) and [pinning contract](https://doc.rust-lang.org/std/pin/index.html) require exclusive pinned access during poll and forbid polling a completed future. Existing ScanTask/Latch drivers dispatch after a poll completes and cannot directly reproduce producer-before-consumer ordering.

The pinned upstream reentrant-shutdown defect remains the QBF version gate. Its fix is already merged upstream; do not report it again. This experiment does not upgrade Effect or admit the differing topology.

## Decisions

- **QCB-001 — Operations execute outside child poll.** A private Queue operation future posts a request to a fixed inline task bank and returns Pending. The serialized driver first releases its exclusive pinned child borrow, then processes the operation. Queue callbacks synchronously route and run the selected peer continuation. Only after the operation and all its callbacks return does the initiating child receive its result and continue. Protocol Pending is a routing boundary, not an observable semantic suspension or permission to yield to the host.
- **QCB-002 — Safe scoped routing.** Caller-pinned, heterogeneous child futures remain borrowed; short RefCell borrows protect polling and explicit active-task guards detect accidental same-task reentry. No raw-pointer aliasing, unsafe pin projection, heap boxing, task spawn or Arc-owned Queue is needed for the experiment. Queue mutation locks and future borrows must both be released before any callback. A completed child is never polled again. Request state/generations and Queue tickets must reject stale or mismatched receipts. Bound synchronous drain steps and callback depth separately; do not claim that a finite registration bank alone bounds native stack growth.
- **QCB-003 — Retry is not reservation.** Store the outstanding take until its ticket is selected. A retry processes take again before resuming authored continuation, potentially registering a new ticket. Immediate offer must run its own continuation through the next real wait/completion before scheduled taker dispatch. Dispatch runs at those explicit semantic boundaries and uses the existing live scan; a posted request alone is never such a boundary. A future posting another request during callback continuation is handled synchronously, not detached into a later cohort.
- **QCB-004 — Cancellation is explicit at this stage.** Driver-routed cancellation removes an outstanding registration and executes any resulting terminal callbacks before returning. Cancellation marks a child inactive and suppresses its authored continuation; it does not remove mandatory owner callbacks after Done. An official public-API probe with terminal-taker continuation interrupting a pending producer during shutdown confirms that the owner still delivers the callback but the interrupted producer does not execute its offer-false continuation. This distinguishes fiber cancellation from the QBF owner cancellation contract. General Drop, arbitrary select, host interruption, asynchronous finalizers and task-group settlement are not implemented by this experiment. Do not conceal those gaps with a waker-only adapter or a Drop that silently defers cancellation past authored continuations.
- **QCB-005 — Private proof before integration.** Start with small fixed-capacity scalar producer/consumer futures and a fixed task bank. Differential traces must show repeated backpressure, producer-before-consumer continuation, scheduled-taker priority/barging and terminal completion. Retry re-registration and same-pass new-taker integration need separate evidence before checked admission. Check a deliberate delayed-producer mutation. Measure quiet execution allocations and actual bank/borrowed-driver/future layouts separately from the existing Queue owner. Bounds in the prototype are assertions, not checked whole-program operation receipts or default-scheduler admission evidence.

## Alternatives and remaining gates

Direct polling a peer inside the initiating future poll requires routing through an outstanding exclusive future borrow, complicates safe heterogeneous ownership and may reenter an active task. Plain wakers defer the producer continuation until after the consumer and fail the source contract. Explicit generated task state machines are viable, but introduce a second emission path before the generic future bridge has been tested. A request boundary retains ordinary Rust async helpers while leaving synchronous Queue callbacks under the semantic driver.

Acceptance of this experiment is limited to controlled differential workloads in debug/release. Checked lexical IR lowering, reachable runtime emission, default-context operation receipts, provenance/failure frames, cancellation/Drop ownership, settlement, actual generated root costs and owned/public execution remain separate gates. General timers, foreign futures, multiple owners, richer errors and the upstream defect topology remain unadmitted.

## Implementation boundaries

The initial bank has two slots. QueueDriver borrows two heterogeneous pinned Future outputs of Unit and runs with an inert waker under explicit serialized pump/dispatch control; foreign Pending is refused. It is not a host executor or a Send/multithread runtime. Request generations and owner tickets prevent stale receipts reaching replacement requests. Private cumulative steps100000 and callback depth256 are experiment assertions, not compiler-derived profile receipts. Controlled tasks can only truly suspend on Queue registrations. Same-pass creation of a third ordinary taker remains a separate integration test; the owner protocol suite supplies its existing live-scan proof. Barging before dispatch proves absence of reservations, not retry re-registration: an immediate retry consumes available data without an intervening automatic yield in this controlled subset. A forced retry can test replacement-ticket safety locally, but naturally scheduled retry re-registration remains an admission gate.

## Delivered experiment — 2026-10-07

Source: queue-continuation-runtime.ts; fixture: queue-continuation-runtime.test.ts. Six debug/release traces match pinned official Effect: repeated producer backpressure, barging, Closing admission/refusal, shutdown false/interruption, canceled offer and canceled take. Removing synchronous peer pumping makes the producer-before-consumer assertion fail. Foreign Pending is refused in both profiles. Completed-task pump/cancel, stale callback and a separately injected empty retry/replacement-ticket edge are covered. The injection is local safety evidence, not an official scheduling trace.

Current Linux fixture measurements after QOWN: Queue owner120 bytes, request bank144, borrowed driver72, producer future168 and consumer future152. QOWN lifecycle guards add8 bytes to the initial136-byte request bank. Construction and full repeated-backpressure execution over1000 quiet invocations allocate zero times. Logs use a fixed inline array during measurement. These costs include the fixture's actual child futures but exclude host execution context, cleanup/frames, checked generated root and compiler heap. Debug/release fixture output agrees.

[QOWN](queue-driver-ownership.md) now supplies quiescent scoped driver registration retirement and closed-bank refusal. This does not implement individual request Drop or Effect finalizer settlement; borrowed child futures remain caller-owned. Source selection, exported Queue APIs and public Compile refusals are unchanged. Next implement a checked native profile and generic lowering integration only after cancellation ownership and bounded default-context receipts are designed.
