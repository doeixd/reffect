# Bounded Effect v4 Result

Checked 2026-10-02 against installed Effect **4.0.0-rc.118** and its [published primary Result source](https://unpkg.com/effect@4.0.0-rc.118/src/Result.ts). Constructors are `succeed`/`fail`, variants are `Success`/`Failure`, and payload fields are `success`/`failure`. `map` and `flatMap` visit only success; `mapError` visits only failure; `match` uses `onSuccess`/`onFailure`. Official `flatMap` admits an error union.

The existing [record representation](records-unions.md) and [recovery profile](error-recovery.md) supply checked tagged branches and typed error capture. This module adds builders over those representations rather than a runtime evaluator or new lowering nodes.

## Decisions recorded before implementation

- **RESULT-001 — plain tagged data.** `R.Result(A,E)` is an interned tagged-union witness with Success `{ success:A }` and Failure `{ failure:E }`. Native enum payloads are inline subject to their existing type representation; there is no Result-specific box, metadata field or heap registry. Reference values expose the documented tags/payloads but omit upstream prototype, `_op`, iterator and TypeId branding. Compare using official Result operations as the oracle, rather than passing plain reference objects to upstream branding predicates. A specialized Rust `Result<A,E>` layout is deferred because existing unions already provide verified structural decoding and matching. Revisit for measured size/code growth or interoperability consumers requiring branding.
- **RESULT-002 — explicit absent-channel witnesses.** `succeed(value,errorWitness)` and `fail(error,successWitness)` retain native representability of both alternatives. This differs from upstream's inferred Never channel, avoiding implicit unchecked widening. Witness factories and ordinary combinators are data-first/data-last where upstream is dual. Revisit when a general representation-safe widening primitive exists.
- **RESULT-003 — checked branch combinators.** `match`, `map`, `mapError`, `flatMap`, `isSuccess`, `isFailure`, `getOrElse` and `mapBoth` expand into existing exhaustive tagged-expression branches; match also permits homogeneous effectful branches via the existing checked computation match. Both alternatives are constructed symbolically during authoring, but only the selected branch evaluates at execution. Match/getOrElse require the same output witness; flatMap requires the same error witness, refusing upstream's implicit heterogeneous error union. Explicit mapError or tagged-union errors remain available. Revisit alongside generalized explicit union injection.
- **RESULT-004 — typed Effect capture.** `Effect.result` can compose existing map and typed recovery, making ordinary errors Result data while compiler defects and interruption bypass recovery. No Cause capture is added. Existing cleanup runs before capture as prescribed by catchAll. Reference/native async and cancellation remain governed by the recovery adapter; wider Cause/Exit modules need their own evidence.

## Validation and costs

Compare constructors/branch transformations with official pinned Result for both variants, chained maps, payload ownership and failures. Compile a meaningful chained transformation to native Rust; check no new Cargo dependency and inspect generated enums. Validate inference without author casts and reject incompatible branch/error witnesses. Authoring creates immutable expression and witness objects; existing structural interning retains witnesses for the process lifetime. Native scalar payloads do not carry this information. Cloneable owned payloads retain existing ownership/clone behavior; no zero-allocation claim is made for String/array payloads. Generated-code growth and union layout are inherited, not independently benchmarked here.

## Implementation evidence

`src/result.ts` implements the declared witness and operations without adding IR nodes, Rust scaffolds or dependencies. `match` also accepts two effectful branches using existing checked MatchTags computations; their channels follow the established equal-witness-or-Never join rule. Mixing pure and effectful branches is refused. `effectResult` supplies the capture primitive used by the separate `matchEffect` implementation.

Focused suite passed **3/3** in **2.88s**: pinned official Result differential transformations, reference structural results, exactly-once symbolic callback construction, reversed union tag order, malformed-shape/error-witness refusal, and fresh native debug/release scalar projections. Native success-only and failure-only capture exercise Never on either Result alternative. The existing CLI runner accepts scalar outputs; these checks fold native Result values to scalars and do not establish a composite CLI/RPC codec. Fresh Rust std artifacts contain no Tokio or Result-specific dependency. Focused lint and package strict TypeScript pass. Parent integrated validation remains separate.

A fixture initially attempted to invoke a composite-output function through the scalar CLI; its generated dispatch correctly omitted that entry. The fixture was corrected to use typed scalar projections rather than widening the CLI protocol. The scoped temp directory is only a parent; CargoApi.write creates a child directory.

Remaining upstream APIs (including generators, validation accumulation, arbitrary error unions and runtime Result branding) are not admitted by this slice. Direct official Result predicate interoperability would require a branded interpreter representation decision and is not silently claimed.
