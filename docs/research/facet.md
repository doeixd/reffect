# Facet evaluation for reffect

Checked 2026-10-01 against reffect `0cc5ca0` and Facet upstream commit `65bae5c31a7ce401bc44630fb96250ea884cfd3e` (release `0.50.0-rc.7`, 2026-08-20). Reviewed source before selecting a role or changing the roadmap. This is an optional-adapter evaluation, not an implemented dependency or codec compatibility claim.

## What it supplies

[Facet](https://github.com/facet-rs/facet/blob/65bae5c31a7ce401bc44630fb96250ea884cfd3e/README.md) is a Rust reflection ecosystem. Types expose structural metadata: layout, fields/variants, attributes/documentation and type-specific operations. Reflection consumers inspect/build values, format/diff them and supply serialization integrations. The README lists related projects, but their existence does not establish compatibility with Effect/Foldkit protocols. The README also warns that website prose is being repaired; this evaluation uses pinned source and registry manifests.

The central [Facet trait](https://github.com/facet-rs/facet/blob/65bae5c31a7ce401bc44630fb96250ea884cfd3e/facet-core/src/lib.rs) has `const SHAPE: &'static Shape`. [Struct derive output](https://github.com/facet-rs/facet/blob/65bae5c31a7ce401bc44630fb96250ea884cfd3e/facet-macros-impl/src/process_struct.rs) generates associated shape data and trait/inherent implementations, not a metadata field on each value. [Scalar implementations](https://github.com/facet-rs/facet/blob/65bae5c31a7ce401bc44630fb96250ea884cfd3e/facet-core/src/impls/core/scalar.rs) include ordinary `u64`. This is consistent with our design of shared static type descriptors and plain runtime values.

[Peek::new](https://github.com/facet-rs/facet/blob/65bae5c31a7ce401bc44630fb96250ea884cfd3e/facet-reflect/src/peek/value.rs) constructs a borrowed reflection view with a value pointer, shape reference and lifetime marker; that constructor does not allocate a box for the underlying value. The view is separate from the value. This does not make all reflection allocation-free: [Partial construction](https://github.com/facet-rs/facet/blob/65bae5c31a7ce401bc44630fb96250ea884cfd3e/facet-reflect/src/partial/partial_api/alloc.rs) allocates storage, and [Partial state](https://github.com/facet-rs/facet/blob/65bae5c31a7ce401bc44630fb96250ea884cfd3e/facet-reflect/src/partial/mod.rs) uses Arc-backed plans and Vec-backed frame/state structures. General traversal, shape-driven operations, output buffers and plan/cache ownership have costs; no Facet-versus-generated/Serde performance benchmark was run here.

## Fit with the compiler and metadata design

| Potential role                                                                | Assessment                                                                                                                                         |
| ----------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| Plain numeric values/static native type descriptions                          | Useful design precedent; no reason to add Facet to the current arithmetic profile just to obtain metadata we already know at compilation           |
| Structured diagnostic/log/config inspection, pretty printing and diff tooling | Useful optional consumer when generated records and their approved field projections exist                                                         |
| JSON/other codecs for generated records/unions                                | Candidate runtime adapter to compare with direct generated codecs and Serde at the Schema/RPC milestone                                            |
| Dynamic Rust extension types whose structure is needed at runtime             | Plausible later use, with declared Facet-compatible types, trusted derives and measured reflection boundaries                                      |
| TS IRType/operation/law/support metadata                                      | Not a replacement: Facet describes Rust layout/structure, while our compiler also needs semantic witnesses, target selection, effects and evidence |
| Source maps, executed use sites, logical frames or scoped annotations         | Not supplied by per-type SHAPE; retain our definition/use provenance and request/task context                                                      |
| Effect RPC/SchemaBinary/OTLP or Foldkit protocol implementation               | Not established by Facet JSON/schema/RPC ecosystem support; each protocol requires its own conformance                                             |
| Typed Rust string generation                                                  | Not the main tool: extend the verified Rust IR/source writer; reflection does not print our compiler's semantic control flow                       |

One `u64` shape describes all u64 values; it cannot identify which addition or call occurrence ran. Keep runtime type reflection separate from source `SiteId` and dynamic execution annotations. Facet also cannot reduce existing TypeScript wrapper/map heap usage: it is a Rust library, while that work happens in the TS compiler.

Reffect's semantic Schema/IR remains the source of truth. Lower supported TS schemas to verified Rust/native and wire representations; optionally derive Facet on generated structs for a chosen consumer. Do not reflect Rust back into a new TS contract and assume it is the original Effect Schema. Encoded-versus-decoded types, missing/optional/null fields, refinements, defaults, transforms, union tags, bigint bounds/encoding, unknown-field behavior and domain-error schemas require explicit adapters. Generic structural reflection cannot infer arbitrary Effect transformations or codec laws.

The [Shape definition](https://github.com/facet-rs/facet/blob/65bae5c31a7ce401bc44630fb96250ea884cfd3e/facet-core/src/types/shape.rs) explicitly says DeclId is opaque and unstable across compilations/refactors/reformatting. Do not use reflected type/declaration identifiers or shape addresses as stable source IDs, artifact identities or wire-schema fingerprints. Keep compiler-owned canonical identities.

## Versions, dependencies and trust boundaries

Observed [facet](https://crates.io/api/v1/crates/facet), [facet-core](https://crates.io/api/v1/crates/facet-core) and [facet-reflect](https://crates.io/api/v1/crates/facet-reflect) latest releases are `0.50.0-rc.7` with declared Rust `1.92`; latest stable for these is `0.46.5` with declared Rust `1.90`. [facet-json](https://crates.io/api/v1/crates/facet-json) latest is `0.50.0-rc.7`; latest stable is `0.46.1`. Pinned main source here is the RC release; do not infer stable API behavior from it. Workspace toolchain is `1.96.0`, whereas reffect's observed rustc is `1.98.1`, so these declared minima alone do not block experimentation. No dependency set/build was tested and reffect has not adopted this MSRV.

[Facade features](https://github.com/facet-rs/facet/blob/65bae5c31a7ce401bc44630fb96250ea884cfd3e/facet/Cargo.toml) default to std/helpful-derive/doc; reflection is optional. Documentation can be stripped with the upstream `facet_no_doc` cfg. Select exact features and audit the complete reachable dependency set, reflected field names/docs, compile time and retained binary tables rather than enable every implementation. [facet-reflect](https://github.com/facet-rs/facet/blob/65bae5c31a7ce401bc44630fb96250ea884cfd3e/facet-reflect/Cargo.toml) enables std/alloc by default and depends on hashbrown and a prerelease smallvec. Facet core/derive and allocation-backed reflective construction are different dependencies/costs. License is MIT OR Apache-2.0.

The Facet trait is unsafe to implement: wrong layout/invariant metadata can make safe reflection consumers unsound. Prefer the tested derive/official implementations for generated types. Do not synthesize pointer/layout-bearing Shapes directly from untrusted source-map JSON or TS annotations. Reflected values still need input validation and log redaction; serializing every reflected field can expose secrets even when the type description itself is static. Queue/export ownership rules remain unchanged.

## Decision and evaluation gate

Retain Facet as an optional candidate for native record inspection and codecs, with no dependency added now. It validates the static-descriptor approach but does not justify runtime reflection on every expression/value. Prefer direct generated access/codec operations when the compiler knows the schema; use reflection when a real generic consumer benefits from it.

At the supported structured-Schema/JSON RPC slice, compare equivalent generated codecs, Serde and a pinned Facet/format pair against official Effect fixtures. Measure cold compile time, release binary size, allocation/peak retained plan state, success/failure encode/decode latency and dependency/MSRV/features. Cover missing/null/unknown fields, transforms/refinements, tags, u64 overflow/precision and exact error paths. Verify no extra per-value fields, docs stripping/redaction, borrowed/owned lifetimes and bounded caches. Keep stock client wire contracts unchanged; separate JSON results from later SchemaBinary evidence.

**Next work remains the artifact-off compiler slice**, as specified in [metadata policies](../metadata-cost.md#opt-out-controls-and-defaults): honest typed artifact absence, skipped collection/range/hash/JSON work, unchanged Rust output/domain results, source-diagnostic fallback and a reproducible allocation/retention comparison. Then Unit, bounded logical failure frames and scoped logging, extracting typed Rust helpers as these constructs need them. A Facet experiment belongs with a concrete record/codec consumer and does not delay this sequence.
