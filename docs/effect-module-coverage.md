# Effect v4 module coverage and implementation order

This inventory supports the parallel module work without changing the core roadmap owned by the other implementation instance. A public Effect export is an inventory item, not a commitment to compile its entire API. Coverage means an authored `R` program has a checked representation, official reference execution and native lowering; importing upstream Effect in the compiler does not establish native support.

## Evidence and version boundary

Checked 2026-10-02 against the installed `effect@4.0.0-rc.118` package, `packages/reffect/src/authoring.ts`, the package barrel, checked computation IR, records, schedules, RPC codecs and current research records. Online primary sources checked before this inventory:

- [Pinned package exports](https://unpkg.com/effect@4.0.0-rc.118/package.json) and [stable package exports](https://unpkg.com/effect@4.0.0/package.json).
- [Ref](https://unpkg.com/effect@4.0.0-rc.118/src/Ref.ts), [Deferred](https://unpkg.com/effect@4.0.0-rc.118/src/Deferred.ts), [Queue](https://unpkg.com/effect@4.0.0-rc.118/src/Queue.ts) and [Semaphore](https://unpkg.com/effect@4.0.0-rc.118/src/Semaphore.ts).
- [Existing bounded decisions](effect-modules.md), [runtime lowering](runtime-lowering.md), [resource Layers](research/resource-layer.md), [metadata costs](metadata-cost.md) and [current Remote design](research/native-remote.md).

The installed root barrel exports **138 module namespaces**. Its group entry points are `effect/rpc`, `effect/http`, `effect/sql`, etc. Both pinned and stable online manifests confirm those paths. Historical `effect/unstable/*` spellings in [the API scope reference](effect-v4-api-scope.md) are stale for this checkout.

Effect v4 names also matter: the pinned recovery primitive is `Effect.catch`, while the baseline R API retains `catchAll`; aligned helper naming belongs to the assigned Effect helper track. Names and matching type signatures still need a native semantic gate.

Initial research and focused evidence used rc.118. Remote synchronization on 2026-10-03 brought the coordinated Effect/platform migration to 4.0.0 stable. Integrated validation now uses stable; historical source links remain pinned to the research version. This inventory changes no dependencies and does not imply general rc/stable semantic equivalence.

## Coverage vocabulary

- **Bounded:** an implemented native subset; omitted functions remain unsupported.
- **Partial:** related representation or infrastructure exists, but the upstream module is not generally exposed or compiled.
- **In progress:** assigned parallel work, awaiting integration and conformance evidence.
- **Missing:** no checked native authoring support located.
- **Build-time / host:** suitable for normal TypeScript compiler, schema-contract, test or tooling use; not evidence of native lowering.
- **Deferred:** intentionally behind a semantic gate or outside the current native profile. Revisit for a concrete reachable workload.

## Priority waves and hard acceptance gates

These are implementation dependencies for module breadth, not a replacement for PLAN.md. Work owned by the core instance remains coordinated there.

| Wave                                     | Modules / executable workload                                                                                                                                                                                                                              | Gate before calling the slice delivered                                                                                                                                                                                                                                                                                                     |
| ---------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 0 — typed composition                    | Option/Result, definition-time Duration, selected pure Array/Record and Effect helpers; branch over an optional RPC field and recover a typed validation failure without author casts.                                                                     | Official/reference/native agree on Some/None and Success/Failure tags, empty collections, evaluation order and error channel; unsupported shapes fail clearly; generated values stay plain. Bounded foundation implementations, focused conformance and integrated stable validation pass; exact suite evidence is recorded in PROGRESS.md. |
| 1 — local state and explicit environment | Ref.make/get/set/update/modify for lexical nonescaping state; injectable Clock and Random; finite typed collection helpers. Workload: sequential request counter with deterministic time/random input, sleep and cleanup.                                  | Invocation isolation, atomic non-suspending updates, alias/escape refusal, deterministic official/native event traces; cost measurements for state/future layout; no Arc/Mutex for exclusive locals. Clock epoch/monotonic domains and random algorithm/distribution are explicit.                                                          |
| 2 — bounded coordination                 | Minimal structured child tasks, typed Exit subset, Deferred, Semaphore, then Latch/partitioning where demanded. Workload: two child computations share a one-shot result; one waiter cancels without cancelling the Deferred; permit scope finalizes once. | Parent/child ownership, cancellation/join/error propagation and context inheritance proved; first completion wins and later completion returns false; cancellation removes waiters; permit release is masked and leak-free; no fairness claim without oracle evidence.                                                                      |
| 3 — bounded communication                | Queue bounded first, then dropping/sliding/unbounded and PubSub subscriptions. Workload: scoped producer/consumer queue whose consumer cancels while producer is blocked, followed by queue shutdown.                                                      | Offer/take order, full/empty suspension, completion/failure/shutdown, interrupted waiter removal and strategy results match v4; memory is bounded for bounded queues; PubSub delivers to all admitted subscribers with correct scope/backpressure.                                                                                          |
| 4 — streaming                            | Stream.fromIterable/map/filter/take/runCollect, then Sink fold/drain and checked Channel adapters. Workload: bounded queue feeds a streamed RPC response and disconnect triggers finalization.                                                             | Pull/chunk semantics, laziness, failure ordering, downstream demand and disconnect cleanup agree; memory does not grow with consumed item count; no post-cancellation emissions; fusion only with valid effect-order evidence.                                                                                                              |
| 5 — shared lifecycle                     | SynchronizedRef/SubscriptionRef, Cache/ScopedCache, Pool, Request/RequestResolver, richer resource containers. Workload: two overlapping requests share one cached acquisition and invalidate safely.                                                      | Race/expiry/invalidation and sharing tested, cancelled followers do not corrupt shared ownership, resource close awaited exactly once, stampede/memoization/batching behavior matches selected profile.                                                                                                                                     |
| Later / demand driven                    | Rich Schedule, DateTime/Cron, transactional modules, general Channel/Sink, distributed/durable and AI profiles.                                                                                                                                            | Separate records establish portable semantics, capability reachability and cost before widening APIs. No blanket obligation to implement every Effect export.                                                                                                                                                                               |

**Next dependency gate: explicit child handles and admitted Exit/Cause ownership**, before suspending coordination and communication modules. The [first structured kernel](research/structured-concurrency.md) and its [evidence](research/structured-concurrency-conformance.md) deliver static infallible All/Race with independent cancellation and awaited cleanup; they do not expose Fiber handles or coordination borrowing. Lexical Ref and the millis/next/nextBoolean Clock/Random profile are delivered. The [coordination record](research/coordination-modules.md) defines cancellation-safe task ownership before Deferred/Latch/Semaphore, and [streaming research](research/channel-stream-modules.md) permits a separately bounded finite pull slice. Coordinate this gate with the core owner's workload; finite pure helpers remain demand-driven.

The Ref acceptance workload now passes: checked make/get/set/update/modify, reused execution with fresh cells, interleaved invocations, sequential sleep, file cleanup and lexical Layer sharing. Handles cannot escape their checked lifetime. Shared Ref admission remains behind the structured-concurrency gate.

## Provisional decisions and revisit triggers

| ID           | Decision, alternatives and consequences                                                                                                                                                                                                                                                                           | Revisit trigger                                                                                                                                        |
| ------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| COVERAGE-001 | Track bounded semantic capabilities and precise entry points, rather than promise complete namespace compatibility. Build-time type/schema tools need no redundant Rust module. This reduces accidental native dependencies and preserves honest unsupported diagnostics.                                         | A real migration report needs function-level compatibility; derive it from registered operations rather than hand-maintaining an “all supported” list. |
| COVERAGE-002 | Lexical Ref should specialize to exclusive local native state. A blanket Arc/Mutex wrapper would allocate and impose synchronization on single-owner workloads. Shared handles may require Arc/atomics/locks later, selected by ownership/capability evidence.                                                    | First supported alias across child tasks, service instances or request boundaries; choose sharing representation before allowing escape.               |
| COVERAGE-003 | Admit Clock/Random through explicit effect nodes and injectable environments; duration parsing alone remains definition-time. System wall/monotonic clocks and seeded randomness are distinct contracts. Do not optimize away or reorder draws/time reads as pure expressions.                                    | Production nondeterministic backend, jitter, cache expiry or rate limiting; define oracle substitution and precision first.                            |
| COVERAGE-004 | Stateful primitives require typed resource/handle IR and structured task ownership before useful suspended operations. Deferred is reusable broadcast completion, not a one-consumer oneshot; Queue has a typed end/failure channel; PubSub has subscription scope. Reuse substrate machinery only with adapters. | Coordination implementation begins; pin completion, cancellation, wakeup and fairness contracts in its research record.                                |
| COVERAGE-005 | Keep provenance external and value representations plain. Share/heap-allocate state only when actual aliasing requires it; reserve fixed bounded local storage where proven. Every primitive records context/future size, allocations, queue capacity/waiter growth and reachable Cargo features.                 | Any Arc, boxed future, callback registry or unbounded buffer is introduced; require workload-specific justification and disabled-policy measurement.   |
| COVERAGE-006 | Keep oracle migration separate from module implementation, coordinated with the core instance. rc.118 remains the testing source until stable is installed and checked. Stable's matching export paths alone do not prove equal scheduler/schema/protocol semantics.                                              | Before the stable Foldkit Remote differential harness or a module requiring stable-only APIs.                                                          |

Open questions include atomic Ref operations for non-Copy composite values; cancellation-safe move/borrow access to handle contents; precise Queue `Done`/typed failure representation; Deferred full Cause completion; task-local service/context inheritance; fairness guarantees actually promised by the pinned source; deterministic Clock suspension/advancement; and random reproducibility/distribution. Answer these at their wave gates, not by introducing general runtime machinery into the pure helper batch.
